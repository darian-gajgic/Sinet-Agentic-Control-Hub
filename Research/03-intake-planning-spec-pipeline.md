## 2. Current state of the art (mid-2026)

### 2.1 Plan modes: how the field does intake for experts (SQ1-product, SQ9, part SQ6)

Every major coding harness now ships a distinct planning mode, and they have **converged on one shape: read-only exploration during planning, writes blocked, a plan artifact, then an explicit approval gate** [S1–S11, verified 3× incl. adversarial hunt for counter-examples — none found]:

- **Claude Code** plan mode: docs say "Reads only … Edits stay blocked either way until you approve the plan"; Claude reads files and runs read-only shell exploration; approval is one 5-option dialog (approve into auto/acceptEdits/manual, keep planning, refine); the plan persists as a file on disk; official best practices push an explicit interview pattern (AskUserQuestion → SPEC.md → fresh session to execute) and the rationale: "Separate research and planning from implementation to avoid solving the wrong problem" [S1, S2].
- **Cursor** Plan Mode: asks adaptive clarifying questions before drafting; researches the codebase; produces a persistent Markdown plan with file paths and code references; one Build click executes (locally or in cloud); editing during plan mode was patched as a bug (changelog 2.4); MCP tools are disabled during planning [S3, S4, S5].
- **OpenAI Codex**: `/plan` "keeps the agent read-only while it drafts a plan" (feature docs; merged as read-only iterative planning in PR #4769, 2025-10); separate `:read-only`/`:workspace` permission profiles; Codex *cloud* has no pre-execution plan gate — review lands on the diff [S6, S7].
- **opencode**: two primary agents, Build (all tools) vs Plan — a "restricted agent designed for planning and analysis" with edit/write/bash denied per the current permissions docs (prose elsewhere says `ask`; docs self-contradict — spike-verify the shipped default) [S8, S9].
- **VS Code Copilot Plan agent**: "explores your codebase by using read-only tools … doesn't edit files or run implementation steps while you're planning"; plan saved to a session file containing plan summary, implementation **and verification steps** [S10, S11].
- **Devin**: plans with "implementation questions" at session start — but the default is a **30-second soft gate that auto-proceeds**; a hard Confirm gate is opt-in [S12]. **Kiro**: the richest gated pipeline (see §2.2). **Antigravity**: plans as first-class artifacts with doc-style comments absorbed *without stopping execution* (non-blocking by default) [S13]. **Copilot Workspace** — the 2024 poster child of plan-first UX — was sunset (reported 2025-05-30; secondary sources + dead DNS + archived manual repo; no fetchable primary notice) and folded into the Copilot coding agent, which has **no** pre-execution plan gate [S14, S15].

Three lessons beyond the convergence itself:

1. **Write-lockout is partly prompt-level in shipping products, and it fails**: a recurring Claude Code bug class documents edits executing during plan mode (#43147 → canonical open #47331; #33037 analysis shows the "plan mode still active" reminder injected only in the Edit tool's *result* — reactive, not preventive), and opencode has parallel bypasses where **subagents escape plan mode** (#6527, #26514) [S16, S17]. For Sinet, "writes off during planning" must be a **sandbox property (S5 C1/C2 read-only), inherited by any helper**, never a prompt instruction.
2. **Approval cost in the field**: one keypress (Claude Code), one click (Cursor, Kiro per phase), zero-with-timeout (Devin — an anti-pattern under D7), zero-upfront-review-the-diff-later (Codex cloud, Copilot coding agent). No vendor publishes plan-generation cost or latency numbers; the only quantified guidance is qualitative "plan mode adds overhead — skip it when the diff is one sentence" [S2].
3. **Nobody ships a plan mode designed for non-technical users.** Every surveyed plan artifact embeds file paths, diffs, or code citations. The nearest consumer analogues are deep-research products (OpenAI's clarifier: "ChatGPT uses an intermediate model (like gpt-4.1) to help clarify your intent … before the research process begins"; Gemini's editable research plan: "create a research plan for you to either revise or approve") and Manus's live `todo.md` [S18, S19, S20]. Spec 1.1's "no prompting skill required" therefore has **no off-the-shelf donor** — it is assembled from patterns, not adopted.

**SQ9 verdict:** N6's tools-off-planning stance is **superseded**: the 2026 field plans with reads on and writes off, because plans grounded in the actual repo/context are better plans ("solving the wrong problem" rationale) — but Sinet must enforce the write-lockout architecturally, which the field demonstrably does not. Research-during-planning is likewise normal (Cursor/Claude Code explore before planning; deep-research products make the research plan itself the gated artifact). The one thing that stays off during planning: any outward-facing or mutating tool — which for Sinet is D7 by construction.

### 2.2 The spec-driven-development wave: artifact formats and traceability (SQ2)

The SDD field matured into three active, healthy open projects plus one big-vendor product [S21–S28]:

- **GitHub Spec Kit** (MIT, 122k stars, v0.12.17 released 2026-07-16): `/speckit.constitution|specify|clarify|plan|tasks|analyze|implement|checklist|converge`. Its spec.md: prioritized user stories (P1–P3, each "independently testable") with **Given/When/Then acceptance scenarios**, functional requirements numbered **FR-###** in MUST-prose, success criteria **SC-###** ("technology-agnostic and measurable"), and inline **`[NEEDS CLARIFICATION: …]`** markers for unresolved decisions. `/speckit.clarify` runs coverage-based questioning; `/speckit.analyze` builds a requirements inventory on **stable keys** and detects "requirements with zero associated tasks" (coverage-gap table; a zero-coverage baseline requirement is auto-CRITICAL and blocks the implement recommendation) [S21, S22, S23].
- **AWS Kiro** (GA 2025-11-17; now AWS's flagship — Amazon Q Developer got an end-of-support announcement in its favor): requirements.md = user stories + **numbered EARS acceptance criteria** ("WHEN [condition] THE SYSTEM SHALL [behavior]"); explicit human approval gates between Requirements → Design → Tasks (a "Quick Plan" variant skips gates for low-stakes work — stakes-gating in the wild); tasks.md entries carry **`_Requirements: 1.1, 1.5, 3.1`** back-links. Its May-2026 "requirements analysis" is the field's only shipping **neuro-symbolic** spec check: EARS criteria auto-formalized ("each EARS clause maps cleanly to an implication") and proven for completeness/consistency by an automated-reasoning engine [S24, S25, S26].
- **OpenSpec** (MIT, 61k stars, v1.6.0): delta-based and brownfield-first — every change declares `## ADDED / MODIFIED / REMOVED Requirements` ("The system SHALL …" + `#### Scenario:` GWT blocks), and archiving merges deltas into living specs. **A silently disappearing criterion becomes structurally impossible — it must appear as a REMOVED delta in a diff** [S27].
- **Tessl** (framework still closed beta; repositioned) and **BMAD v6** (active, heavy multi-agent ceremony) round out the field [S28].

**Practitioner verdicts are split in an instructive way** [S29–S32]: Böckeler (Thoughtworks): spec-first is "definitely valuable in many situations" but tools are verbose ("I'd rather review code than all these markdown files"), agents "ultimately not follow all the instructions," and Kiro turned a small bugfix into 4 user stories / 16 acceptance criteria. Eberhardt (Scott Logic CTO) measured the negative extreme: a ~1,000-LOC feature produced 2,577 lines of markdown, 33.5 min agent time vs 8 min baseline, 3.5 h review vs 24 min — "around ten times faster" without SDD. A three-tool comparison scored OpenSpec best (4.0/5, "frictionless iteration through delta specs") and found Spec Kit's "implementation diverged from specification intent." The consensus that emerges: **lightweight specs for small/medium tasks; the full multi-doc pipeline pays only for complex, ambiguous, or compliance-sensitive work.** This is spec 1.8's stakes-gating independently rediscovered by the field — and it independently confirms the Nexus 3.5×-spec-stage lesson from the outside.

**Acceptance-criterion phrasing** (no controlled format-vs-format A/B exists — flagged as a gap): the mechanism arguments are (a) EARS is machine-formalizable (Kiro's automated-reasoning rationale) and was designed at Rolls-Royce for plain-natural-language readability; (b) GWT makes trigger/action/outcome explicit and is BDD's business-readable, examples-first idiom — the epic-organized-Gherkin study (arXiv 2607.01980) found LLM-generated GWT organized by epic beat requirement-aligned organization on expert-judged correctness (4.61 vs 4.14) and completeness (4.31 vs 3.50); (c) ambiguity measurably hurts: Orchid (1,304 tasks, 4 ambiguity types) — "ambiguity consistently degrades the performance of all evaluated LLMs," which "lack the capability to identify or resolve such ambiguity autonomously" [S33, S34]. Converged anti-ambiguity idioms: atomic one-behavior criteria, exact values, binary pass/fail ("if two people could disagree whether it was met, it is not specific enough"), ban on vague adjectives (Spec Kit's /analyze flags "fast/scalable/secure" without measurable criteria as HIGH severity), RFC-2119 SHALL/MUST, measurable technology-agnostic success criteria, examples over prose [S23, S35, S36].

**Traceability mechanics** split cleanly: **deterministic** = stable requirement keys + ID cross-references (Spec Kit FR/SC keys, Kiro `_Requirements:` annotations, OpenSpec deltas); **LLM-judged** = semantic coverage ("does task T actually satisfy FR-3?"), duplication, ambiguity detection; **symbolic** = Kiro's formal pass alone. Academic RTM automation (RAG + CoT trace-link recovery, 99%/85.5% validation/recovery in an automotive study) corroborates that the semantic layer works but the *audit* layer should be key-based [S37].

### 2.3 Elicitation evidence: models under-ask; scaffolds carry the coverage (SQ1-evidence, SQ3)

The 2025–26 measurement record is unusually consistent [S38–S45, all numbers re-verified against the papers]:

- **Models silently assume.** Clarification rates on ambiguous queries: max 4.9%, most models <2%, "80–95% of responses are judged as *only answered*" — and retrieved context suppresses asking further (Sonnet 2.3%→0.3%) [S38 — 2024-era models; scoping per adversarial pass: GPT-5-era products ask more by default (OpenAI's prompting guide documents levers to *reduce* GPT-5's clarifying questions; "question mode" user reports), so the raw rate is a moving target — but see next bullet for why this does not rescue model initiative]. QuestBench (DeepMind): models pick the single right clarifying question only 40–50% of the time on Logic-Q/Planning-Q "even when they can solve the fully specified version" [S39]. **ClarifyCodeBench (2026-07, includes GPT-5 and Claude Sonnet 4.5): best Turn-discounted Key Question Rate 0.30, GPT-5 0.21, Sonnet 4.5 0.12; ambiguity costs 7.8–19.8 pass@1 points; "thinking" mode does not improve clarification; with 3 ambiguities present, the rate of asking all three key questions is almost zero for every model** [S40]. So even where 2026 models ask *more*, they do not reliably ask the *right* questions — asking behavior is a harness property, never a model default. This is spec 1.2's evidence base.
- **Scaffolds close the gap.** Taxonomy-guided follow-up questions beat human-authored ones in a controlled comparison ("outperform human-authored questions when guided by common mistakes types") [S41]; LLMREI's staged prompt beat zero-shot interviewing (33 live interviews; similar mistake counts to human interviewers; up to 73.7% of requirements captured) [S42]; detect-then-ask lifted GPT-4 pass@1 68.02→75.75 (4-benchmark average, ClarifyGPT, OLDER 2024) [S43]; an uncertainty-scaffolded multi-agent setup hit 69.40% on underspecified SWE-bench Verified, closing most of the fully-specified gap [S44]; AskBench-style rubric-guided training/scaffolding shows consistent improvements [S45]. **Design reading: the question taxonomy carries the coverage; the model only phrases the questions.** ClarifyCodeBench's empirically graded 10-type must-ask taxonomy for code tasks (models natively handle Units/Precision; fail Collection Semantics, Comparison Rules, Ordering) is a ready-made seed for the software-family interview scaffold [S40].
- **The ceiling is real.** ReqElicitGym: the best frontier model reaches only **0.32 implicit-requirement coverage** in interactive elicitation; models probe rather than clarify (GPT-5.2: 414 probing vs 23 clarification turns); CoT improves efficiency, not coverage; **style/subjective requirements elicit near zero** (<0.01) — precisely the dimension a zero-IT household member most needs help articulating [S46]. No interview, scaffolded or not, guarantees a complete spec — which is why the pipeline needs the confirm loop, the preview, and bounded revision *behind* the interview, and why degraded-mode honesty (2.1) extends to intake itself.
- **Restate-and-confirm canon**: teach-back is the evidence-based confirmation pattern (effective in 19/20 studies in a systematic review, including low-literacy populations — OLDER, medical domain, transfer is inference) [S47]; production AI has converged on describe → clarify → editable plan → approve (OpenAI DR clarifier, Gemini plan edit, Manus, Kiro) [S18, S19, S20, S24]. No 2025–26 study quantifies restate-confirm convergence speed for non-experts (gap).

### 2.4 Rubber-stamping is measured — and exactly one mitigation has an RCT (SQ3)

- **The failure mode is quantified in production**: Anthropic telemetry — "Claude Code users approve 93% of permission prompts"; full auto-approve grows from ~20% of sessions (new users) to **over 40% by 750 sessions**; and (on the most complex task tier — scoping added per adversarial verification) Claude Code asks for clarification more than twice as often as humans interrupt it [S48, S49]. Approval-queue decay to "near-perfect approval rate and almost no real oversight" is a recurring practitioner report [S50]. The habituation canon (80,000-user field experiment: users "blindly accept terms the more their presentation resembles a EULA"; automation-bias literature: explanations do not reduce — may increase — overreliance) is OLDER but undisputed [S51, S52].
- **The one RCT-evidenced mitigation fits Sinet's card exactly**: an n=214 randomized experiment on plan approval (MPI-SWS + Microsoft Research, 2026-01; domain: execution plans in AI-assisted writing) found the **Assumptions cognitive forcing function — surfacing the plan's implicit assumptions — "most effectively reduced overreliance without increasing cognitive load"** (erroneous-plan acceptance 22% vs 42% for the what-if variant); **stacking multiple forcing functions was "ineffective or even detrimental"; and users' *perceived* helpfulness pointed at the wrong variant** — do not tune approval UX by preference [S53]. Caveats that matter for the household: forcing-function benefits skew toward high-need-for-cognition users, and effective ones are disliked [S52] — friction must be stakes-proportional (1.8 already mandates this).
- Design lore **without** direct evidence (flagged): "what I will NOT do" sections, delta-only re-confirmation, per-assumption toggles, delta highlighting between rounds. Usable, but treat as unevaluated until the 11.2 practice measures them.

### 2.5 Plan self-critique and premortem: what actually holds in 2026 (SQ4)

The 2023–24 pessimism ("LLMs cannot self-correct reasoning") is now **conditionally** overturned for planning [S55–S59]:

- Intrinsic self-critique loops (≤10 iterations, validator used only for scoring) lifted Gemini 1.5 Pro from 49.8%→89.3% (Blocksworld) and 60.7%→93.2% (Logistics) — but only with **carefully engineered state-tracking/precondition-check verifier prompts**, the top line includes self-consistency, the checkpoints are 2024-era (transfer to 2026 native-reasoning models untested), and **Gemma-2 27B gained little — "larger and more capable models are better able to self-improve"** [S55].
- **Fresh-context review beats same-session self-review** (F1 28.6 vs 24.6, p=0.008, d=0.52), repeating review in-session does not help — "the benefit comes from context separation itself" — and absolute catch rates stay low (~29% F1): critique is a filter, not a guarantee [S56]. A 2026-06 analysis confirms self-correction is task-sensitive, correct→incorrect flips remain real, and favors separate critics with rubric/checklist guidance [S57].
- **Sycophancy caps who may critique**: false-authority follow rates (MCQ setting) — GPT-5 4%, Claude Sonnet 4.5 ≤11%, but GPT-4 80% and Qwen2.5-1.5B **94%** [S58]. A small local model asked to critique a plan will predominantly rubber-stamp it. Critique/premortem is a **frontier-class duty**.
- **Role assignment is the disagreement switch**: explicit devil's-advocate role induces disagreement 99.2% vs 48.3% baseline; soft "feel free to dissent" is indistinguishable from baseline — though the disagreement→quality link is unproven [S59]. Premortem specifically ("it is six months from now; this plan failed; explain how") has human-decision canon and consistent practitioner reports but **no dedicated 2025–26 academic study** (verified absence) [S59].
- **The escape hatch does not exist off the shelf.** Mechanisms exist at model level (OpenAI Model Spec: the assistant "may politely push back…"), pipeline level (Kiro's phase gates), and policy level (escalate on high-risk regardless of confidence) — but **no surveyed product wires "the critique concludes the objective itself is wrong" to a mandatory human decision**. P45's antidote at intake time is Sinet-built: a distinct terminal outcome of the critique step [S60, S24, S61].

### 2.6 Stakes/size classification and ceremony-model routing (SQ5, SQ8)

- **Classification-for-routing is production-proven and small-model-sized**: GPT-5's live router routes on "conversation type, complexity, tool needs, and explicit intent" [S62]; OpenRouter's Auto Router (Not Diamond) routes on prompt complexity/task type [S63]; **Arch-Router demonstrates SOTA preference-aligned routing with a 1.5B model** [S64]. Cascade economics formalize the asymmetry Sinet wants: cheap-first with escalate-on-doubt makes *underestimates* cheap (the cheap attempt is inspected before anything expensive trusts it); calibrated cascades escalate 15–35% of queries (practitioner tier) [S65, S66]. No published accuracy figure exists for *stakes/risk* classification with small models specifically — Sinet must eval its own classifier (→ T11's eval practice).
- **Deterministic floors are the stated best practice, not an invention**: OWASP's AI Agent Security Cheat Sheet hardcodes a rule-based `ACTION_RISK_MAPPING` (transfer_funds=CRITICAL, send_email=HIGH), requires step-up approval for critical actions, and mandates **"fail closed when risk classification … fails"**; the CSA draft NIST-RMF agentic profile assigns autonomy tiers deterministically; OpenAI's agent guide puts irreversible/payment actions under human oversight *regardless of confidence* [S67, S68, S61]. For Sinet this is doubly safe: **D7 already gates every outward effect as a proposal no matter what any classifier says** — the stakes classifier only sizes *ceremony*, never safety. That is what makes 1.8's zero-interaction path leak-proof: the floor is a rule (outward effects, new spend, credentials, shared assets, named regulated domains → full treatment), not a model judgment, and misclassification costs ceremony-sizing, not damage. Anthropic's auto mode is the production template for the same layering: static allowlist → project-scoped auto-allow → cheap two-stage classifier (single-token filter, then CoT) → **deny-and-continue** rather than block [S48]; an independent stress-test of that classifier exists and probes quality without disputing the design [S69].
- **Utility-model duty floors (bridge to T15)** — what the evidence licenses running on the local free tier (12 GB 5070 Ti: Qwen3-8B/14B Q4–Q5 class, ~61 tok/s reported for 14B-class, Gemma 3 12B QAT; 24 GB 3090: 27–32B at 4-bit, 18–20 GB) [S70, S71]:
  - **Local-safe duties**: task-family/stakes/data-bearing *classification* and routing (Arch-Router precedent), restatement drafting and summarization, structured output and function calling (open-weights within 3–4 points of frontier on BFCL; IFEval ~84.7 for Qwen3-30B-A3B class — vendor-reported), scaffold-driven interview phrasing (the taxonomy carries coverage), deterministic-adjacent rubric *checking* [S64, S72, S73].
  - **Frontier-only duties**: plan critique, premortem, novel-risk spotting, and the P45 "independent of the spec, is this actually good?" axis — because critique capability scales with model size and small models capitulate (94%) [S55, S58].
  - 1.10's "recommend the same default to everyone" is satisfiable as a shipped duty→model-class map; ceremony consumption itemization (3.6) is cheap to honor since most ceremony duties ride the free local tier, with only planning + critique passes drawing on paid allowances.

### 2.7 Approval surfaces and policy-forced grounding (SQ6, SQ7)

- **HITL infrastructure is mature; the explanation layer is not.** LangGraph interrupts + Agent Inbox (cards with accept/edit/respond/ignore, mobile web, persistent checkpointer), OpenAI Agents SDK (`needs_approval`, serialized RunState for indefinite waits, sticky always-approve = built-in don't-ask-twice), Claude Agent SDK (`canUseTool` with approve-with-changes, `defer`, a PermissionRequest hook explicitly for push/Slack notification, and **AskUserQuestion: 1–4 questions × 2–4 labeled options — a ready-made non-technical question card**), gh-aw safe-outputs with staged previews [S74–S78]. Report 01's inbox mechanics already cover Sinet's transport. The convergent card anatomy: numbered plain-language steps + explicit assumptions + scope boundary + one enumerated decision. **No production example found of 13.5's "what this does / what could go wrong / what we recommend and why" framing, and no plain-language standard applied to AI approvals — genuine white space Sinet builds itself** [S74–S78, angle-wide negative finding].
- **HumanLayer — the approval-as-API poster child — is dead** (repo: "the code here is pretty much all deprecated"; pivot to CodeLayer, 2025-09) [S79]. OpenAI's visual Agent Builder (with its human-approval node) is being deprecated (notified 2026-06-03, off after 2026-11-30) [S80]. Design against SDK/protocol primitives, not vendor approval products.
- **Forced grounding (P47) must be composed; only one API lane can even force it** [S81–S84, all primary-doc verified]: OpenAI Responses API — "Use `tool_choice: 'required'` or a specific web search tool choice when search must run" (with community reports of occasional flakiness → verify anyway). Gemini — built-in `google_search` is model-decided ("The model analyzes the prompt and determines if a Google Search can improve the answer"); `mode: ANY` forces only developer-declared functions; no forced-grounding mechanism exists (Gemini 3 added *combining* search with functions, not forcing). Anthropic — "Claude determines when to search"; only prompt steering and a `max_uses` **cap** (a ceiling, no floor); but usage reports `server_tool_use.web_search_requests` — **the harness-side verification lever: check the counter, and retry/escalate if a research-flagged task ran zero searches**. Production precedents for policy-over-initiative: Perplexity retrieves before generation architecturally; ChatGPT routes search through a dedicated lightweight classifier (network-trace evidence, BLOG tier: temporal terms, "near me", explicit lookup); deep-research products make the research phase structurally mandatory [S85, S86, S18, S19].
- **Detecting data-bearing tasks is a cheap-classifier duty, but Sinet's detector is a to-build**: classical TF-IDF classifiers route retrieval decisions at 93.2% accuracy / 0.928 macro-F1 with 28.1% simulated token savings, lexical features beating embeddings — **scope correction from adversarial pass: that benchmark routes among retrieval *strategies*, not retrieve-vs-not**, so it evidences the duty class is small/cheap, not a ready-made detector [S87]. Uncertainty-estimation methods often beat trained adaptive-retrieval pipelines on efficiency with comparable QA [S88]. FreshQA's typology (never/slow/fast-changing + false-premise — OLDER) plus ChatGPT's observed trigger classes validate a **rule layer** (prices, products, laws, APIs/versions, schedules, named entities with churn) in front of any classifier [S89, S86].

## 3. Candidate approaches

**A. Full staged SDD pipeline** (Spec Kit/Kiro shape; N6's five stages as separate sessions). Richest artifacts, best traceability, gates everywhere. **Fails the operator context twice**: cost structure — every stage re-establishes context (the measured Nexus ~15×-class trap; externally confirmed by Eberhardt's 10× and Böckeler's verbosity findings), and review burden — 2,577 lines of markdown is not approvable by a household member (13.5). The field itself now recommends this shape only for complex/compliance work.

**B. Single-session plan mode** (the field default: Claude Code/Cursor shape). One session explores, asks a few questions, emits a plan; one click approves. Structurally cheap; matches the engines Sinet adopts. **Fails the intake contract**: no numbered acceptance-criteria artifact (1.3), no criterion→plan coverage check (1.4), no independent critique or spec-doubt route (1.5/P45), plan artifacts are developer-shaped (13.5), and question-asking is left to model initiative, which the 2026 evidence still shows under-delivering the *right* questions (§2.3).

**C. Hybrid: one planning session + a deterministic spine + one fresh-context critique** (recommended). A single read-only planning session (scaffold-injected interview → spec+plan artifact pair) wrapped by platform-code gates (coverage check, stakes floors, research injection, size-delta check) and **one** artifact-only critique pass with a mandatory escape-hatch verdict. Cost: ~2 heavyweight model passes + local classifiers; context flows between stages as compact artifacts, never as transcript replay — the 15× structure is killed by construction, not by tuning. Satisfies 1.1–1.10 while staying approvable in seconds.

Trade-off summary against the operator context (solo maintainer, household users, flat-rate economics):

| | A: staged SDD | B: plan mode | C: hybrid |
|---|---|---|---|
| Ceremony cost structure | ~15×-class risk (measured) | minimal | ≤2 passes + local classifiers |
| Numbered AC contract (1.3, T06 input) | yes | no (Kiro excepted) | yes |
| Criterion traceability (1.4) | yes (LLM-heavy) | no | yes (key-based, deterministic first) |
| Spec-doubt escape (1.5, P45) | no product wires it | no | built-in verdict |
| Non-technical approval (13.5) | fails (volume) | fails (code-shaped) | two-layer card |
| Stakes-gating (1.8) | all-or-nothing | user-chosen | rule-floored tiers |
| Maintenance (bus factor 1) | many prompts/stages | trivial | few, testable, mostly deterministic parts |

## 4. Recommendation for Sinet

**Adopt the hybrid pipeline (C): "one interview-to-plan session, a deterministic spine, one fresh-context critique, one two-layer approval card."** Concretely, five stages — of which only two touch a paid model:

**Stage 0 — Triage (local models + rules; free tier).** On every request: task-family detection (software/research/content/data/chore — 2.3), stakes+size guess (2.5), data-bearing detection (P47 rule layer first: prices, products, laws, APIs/versions, schedules, churn-prone entities; cheap classifier second), registry match (S1.6: the registry entry — conventions, commands, danger zones — is injected so the interview never asks what the platform already knows, and danger zones feed the stakes floor). **Deterministic floors override everything upward**: any outward effect, new spend, credential touch, shared-asset write, or named regulated domain forces the full treatment regardless of classifier output and regardless of the user's convenience setting (1.8); classifier failure fails closed (OWASP pattern). The zero-interaction path (trivial tier: read-only, no data-bearing flag, within budget caps) skips to a single notification-card; it cannot leak high-stakes work because the floor is a rule, and D7 backstops even a floor miss — outward effects are gated proposals no matter what intake decided. Wrongness stays cheap in both directions: underestimates are upgraded by Stage-2's plan-vs-guess delta before expensive work; overestimates get caught by the preview and cost ceilings (2.5).

**Stage 1 — Planning session (the requester's designated planning model; frontier-class by default per the post-mortem's inversion #2 — the utility model handles phrasing-level duties within §2.6 floors).** One session, in a **C1/C2 read-only sandbox enforced at sandbox level and inherited by any helper** (the field's prompt-level lockouts demonstrably fail — §2.1). It reads the registry slice and relevant repo/document context, runs the **per-family interview scaffold injected by policy** (software seed: ClarifyCodeBench's 10-type taxonomy; research and content families get their own must-know taxonomies — drafted with the strongest model, entering via the 8.3 knowledge gate so they are versioned and falsifiable), asks its questions as **option-card batches** (AskUserQuestion-shaped: 1–4 questions × 2–4 labeled options + "let me type"; batch budget per stakes tier; ask-don't-assume 1.7 for consequential ambiguity, assumption-listing for the rest), and — for data-bearing flags — receives research *results* from isolated C3 fetch steps (the planner itself never gets egress; research is a separate confined step whose output arrives as data, consistent with 4.7). It emits **one artifact pair**, checkpointed per D7:
- **SPEC**: plain-language goal restatement; **numbered acceptance criteria AC-1..n** — atomic, binary-decidable, measurable, vague-adjective-free; each criterion in plain language, with an optional structured sub-line (EARS phrasing for behavioral software criteria, GWT example scenarios where examples communicate better) so T06's verification gets machine-tractable form without making the requester read notation; technology-agnostic outcome criteria (SC-style) so a non-expert can recognize their goal; an explicit **assumptions list**; an explicit **out-of-scope / "will NOT do" list**; unresolved points as NEEDS-CLARIFICATION markers — **an artifact with open markers cannot reach approval**: each is either asked, or converted to a listed assumption.
- **PLAN**: steps with per-step "Done when" (S3/SAW stage-contract pattern), an **AC coverage map (every AC-# → step IDs)**, mandatory research nodes for every data-bearing flag (P47 — present *by policy* before any model saw the plan), risk notes, and a size/cost estimate explicitly compared to Stage-0's guess (2.5 surfaced, not silent).

**Stage 2 — Deterministic spine (platform code; no model).** (a) **Coverage check**: keyed AC↔step cross-reference; any uncovered AC → one bounded auto-fix round with the planner, then a decision card — never a silent drop (1.4; P46: this route gets an e2e test that forces it). A local-model semantic spot-check ("does step S plausibly deliver AC-3?") runs as a secondary, advisory pass. (b) **Floor re-check against the plan's contents**: if the plan itself introduces outward effects/spend the request didn't mention, tier up. (c) **Size-delta rule**: plan ≫ guess → upgrade ceremony now, before expensive work; plan ≪ guess → note it on the card. (d) **Research-node presence check** for every data-bearing flag; on execution, lanes that cannot force search get post-hoc verification (search-count ≥ 1 via usage counters, e.g. `server_tool_use.web_search_requests` on the Anthropic lane) with retry-then-escalate.

**Stage 3 — Critique pass (fresh context, frontier-class, stakes-gated).** Skipped for the trivial tier; mandatory from standard tier up. A **separate session that reads only the artifact pair** (never the interview transcript — context separation is the demonstrated active ingredient, and it keeps this pass at artifact-sized token cost), with an explicit devil's-advocate role (the only reliable disagreement inducer), a rubric per family, a premortem frame ("this shipped and failed — why?"), and **four terminal verdicts**: **PASS** · **REVISE** (numbered blocker findings → planner fixes once; re-critique checks only the findings — bounded, criteria frozen) · **SPEC-DOUBT** — the P45 antidote: "the specification itself is a bad idea, and here is why, in plain language" → mandatory decision card to the requester (proceed anyway / adjust spec / rethink), never absorbed, wired and e2e-tested (P46) · **TIER-UP** (plan reveals stakes the classifier missed). Calibration honesty: fresh-context critique catches ~29% F1 of injected plan errors in the one controlled study — worth one pass, worth zero loops.

**Stage 4 — Approval card (requester; D10; any device; answering resumes per 4.3).** A **two-layer artifact**: Layer 1 is one phone screen — what I understood (restatement), what you'll get, what I'll do (numbered plain steps), **what I will NOT do**, **the assumptions list as the card's centerpiece** (the Assumptions forcing function — the one RCT-evidenced overreliance mitigation; do not stack additional forcing gimmicks — stacking measured as detrimental), what could go wrong + expected cost/time (13.5's what/wrong/recommendation contract — white space Sinet builds), and **one enumerated decision**: Approve / Fix something (structured: tap the criterion or assumption that's wrong) / Re-interview. Layer 2 (expandable): full numbered ACs, plan with coverage map, critique verdict, research findings. High-stakes cards embed at least one real choice (an interpretation option or assumption confirmation) so reading is structurally required; trivial-tier cards are one tap or zero interaction (1.8). Approved criteria are **frozen and numbered** — T06's re-review judges against them (5.4's no-drifting-goalposts), and any later change is an OpenSpec-style ADDED/MODIFIED/REMOVED delta with a delta-only re-approval card (4.3 freshness re-validation writes deltas, never silent rewrites).

**Artifact format**: Sinet-owned markdown + YAML frontmatter (ids, owner, stakes tier, model/version provenance, status), stable AC keys, git-committable (D9), checkpointed at every stage boundary (D7). Borrowed discipline, not borrowed tooling: FR/SC-style stable keys and clarification markers (Spec Kit), EARS phrasing option and approve-per-phase spirit (Kiro), delta-visible revisions (OpenSpec), per-step Done-when (SAW/N5 stage contracts).

**Ceremony economics, stated as an architectural property**: paid-model work = one planning session (reads context once) + one artifact-only critique (+ bounded single revisions); everything else is local or deterministic. No stage ever re-sends another stage's transcript. Receipts itemize ceremony vs execution per 3.6 from day one, so the 11.2 benchmark can price intake honestly against direct use.

**What would change this decision:**
1. **Dogfood evidence that option-card interviews annoy or lose users** (abandonment before approval) → shrink question budgets, lean harder on assumption-listing + preview. Measure in v0 (single-user) before v1 (household).
2. **A real AC-format A/B** (EARS vs GWT vs plain checklist on agent execution/verification quality) appearing → adopt the winner as the structured sub-line format. None exists today.
3. **Local models closing the critique gap** — the self-critique scaling result rests on 2024-era checkpoints; if T15's evals show a 24 GB-class 2026 reasoning model critiquing without capitulation, the critique duty could leave the paid tier. Re-test at T15, don't assume.
4. **Anthropic/Google shipping forced server-side search** → simplify P47 enforcement from verify-and-retry to force-and-check on those lanes.
5. **The 11.2 benchmark showing intake overhead unpaid on Eco-tier tasks** → widen the zero-interaction band; the pipeline's stages are independently removable by tier, which is the point of the deterministic spine.

## 5. What NOT to use and why

- **A full multi-doc SDD pipeline as the default for every task** (Spec Kit/Kiro/BMAD shape): measured 10× overhead and review volume that kills non-technical approval; the field's own consensus reserves it for complex/compliance work. Sinet takes the artifact discipline, stakes-gated — never the ceremony-by-default.
- **N6 as-is** (five separate stages, tools-off planning): its cost structure is the measured ~15×-class trap, and tools-off is superseded by read-only exploration (§2.1). See harvest verdict.
- **Prompt-level write-lockout during planning**: a documented, recurring escape-bug class in both Claude Code and opencode (including subagent escapes). Sandbox-enforced or nothing.
- **Timed auto-proceed "soft gates"** (Devin's 30-second default): structurally a D7/D10 violation for Sinet and hostile to slow or non-technical reviewers. Gates wait.
- **HumanLayer** (deprecated), **OpenAI Agent Builder** (wind-down announced 2026-06-03), **Copilot Workspace patterns** (product gone): do not design against dead approval products; build on SDK/protocol primitives (interrupts, permission callbacks, AskUserQuestion) instead.
- **Same-context "reflect and improve" self-critique loops**: repetition without context separation measurably adds nothing; fresh-context separation is the active ingredient.
- **Small/local models on critique, premortem, or the P45 axis**: 94% false-authority capitulation in the small class; critique capability scales with size. They may check rubrics; they may not judge plans.
- **Model-initiative research on data-bearing tasks** (P47): even mid-2026 frontier products route search by dedicated classifier or architecture, not model choice; two of Sinet's three API lanes cannot even force server-side search — injection must be plan-level policy with post-hoc verification.
- **Yes/no restatement confirmation as the only high-stakes gate**: 93%-approve/EULA-habituation evidence; use the assumptions-centerpiece card with an embedded real choice.
- **Tuning approval UX by user preference**: the RCT's participants preferred the variant that performed worse; tune by measured overreliance/outcomes via 11.2.
- **LLM-judged-only criterion coverage**: drop-detection must be deterministic on stable keys first (LLM semantics advisory only) — otherwise 1.4's guarantee rests on exactly the judgment that fails silently.

**New platform problems found (for the Known-problems list):**
7. **P-T05-1 — Plan-stage confinement must bind helpers.** The field's plan-mode escapes include *subagents* bypassing plan restrictions (opencode #6527/#26514). Sinet's planning sandbox (read-only) must be inherited by any helper the planner spawns, at sandbox level. Owner: T09 (confinement) + spec.
8. **P-T05-2 — Delta re-approval friction.** Freshness re-validation (4.3) and sibling-collision re-planning (S1.11) produce spec deltas needing re-approval; delta-only cards are design lore with zero direct evidence and plausible rubber-stamp risk. Needs in-house measurement via 11.2 practice. Owner: spec + T11.
9. **P-T05-3 — Clarification as an injection surface.** ASPI-class results show clarification-seeking widens the prompt-injection surface; when tasks arrive via channels (10.3) carrying untrusted quoted content, interview questions generated from that content can be steered. Channel-ingested intake needs C3-class treatment of quoted material before it reaches the interviewer. Owner: T09/S5 + spec.
10. **P-T05-4 — No published stakes-classification accuracy.** Task-complexity routing has products and benchmarks; *stakes/risk* classification with small models has no independent accuracy figure anywhere. Sinet's floor-plus-classifier design tolerates this (wrongness is cheap by construction), but the classifier still needs a pre-registered eval before v1 household use. Owner: T11.

Alignment note: this report's transport assumptions (AskUserQuestion-shaped cards on the Claude lane, permission-ask flow on the opencode lane, inbox mechanics) are exactly report 01 §4's adapter surface — nothing here adds engine requirements beyond it.
