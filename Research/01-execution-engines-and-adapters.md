Three corrections to the spec's operating-reality bullet follow:

1. **As of today, the Agent SDK is NOT credits-billed.** SDK, `claude -p`, and third-party apps all still ride the flat-rate subscription.
2. **The implied remedy in the recorded claim was wrong.** The announced change covered `claude -p` (Claude Code headless) *identically* — only *interactive* Claude Code would have stayed flat-rate. "Avoid the SDK, wrap the CLI" never escapes this risk. The correct risk class is: **"all non-interactive subscription use, on any engine, can be re-priced on ~30 days' notice."** Anthropic has demonstrated both the will (April cutoff) and the mechanism (credit pool).
3. **The durable engine-relevant distinction is policy, not billing.** Anthropic's consumer terms prohibit automated access except via API key "or where we otherwise explicitly permit it"; the login-policy article scopes subscriptions to "ordinary use of native Anthropic applications… including Claude Code"; the Agent SDK docs carry (verified verbatim in the live-page archive of 2026-07-09): *"Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK."* Meanwhile an official Anthropic statement (quoted in an April 2026 HN thread) says: *"Nothing is changing about how you can use the Agent SDK and MAX subscriptions! We want to encourage local development and experimentation with the Agent SDK and claude -p"* — businesses are steered to API keys. **Net: first-party Claude Code surfaces (interactive, `-p`, IDE, web) are unambiguously sanctioned on subscription — `claude setup-token` exists precisely for "CI pipelines, scripts" and issues a 1-year inference-scoped token; personal/local Agent-SDK-on-subscription is publicly encouraged but formally a discretionary gray zone; third-party *products offering claude.ai login to their users* are prohibited.** Sinet (self-hosted, each household member authenticating their own account through Anthropic's own tooling) sits closest to the encouraged personal-use category, but this is a judgment, not a guarantee — see Open questions.

Also confirmed: accounts may not be shared (per-person accounts required — aligns with D2); opt-in "usage credits" billed at standard API rates already exist as the official overflow path (aligns with 3.10's explicit-metered-exception model).

### 2.2 The engine field

- **opencode (anomalyco/opencode, ex sst/opencode; MIT; ~187k stars; v1.18.3 on 2026-07-16, near-daily releases; company-backed by Anomaly).** The only surveyed engine *purpose-built* to sit under an external control plane: `opencode serve` exposes an HTTP API with an OpenAPI 3.1 spec at `/doc`, SSE event streams (`/event`, `/global/event`), session CRUD, `prompt_async`, abort — and, decisively, **`POST /session/:id/permissions/:permissionID`**, a first-class REST endpoint for answering permission requests from outside (ecosystem proof: remote-approval dashboards and Telegram approvers built on it). Official TS SDK generated from the spec. **Per-message model selection is native:** `session.prompt` takes `model: {providerID, modelID}` (the keystone feature Nexus needed core-mod #6 for). Agents are config-defined (`primary`/`subagent`), with per-agent model, tools, permissions, and step caps. **Sub-agent depth is safe by default:** without an explicit global `task` permission rule, the Task tool is disabled for child sessions — max 1 level of nesting; an explicit global `"task": "allow"` silently re-enables unbounded recursion (documented footgun; depth-cap feature requests open). Plugins hook `permission.asked/replied`, `tool.execute.before/after`, `session.compacted`, etc. MCP local+remote. Automatic compaction (V2 makes thresholds configurable). Local models: Ollama, LM Studio, llama.cpp `llama-server`, any OpenAI-compatible `/v1` endpoint — documented recipes. Per-message token fields (input/output/cache-read/cache-write/reasoning) plus session-cumulative tokens and computed cost, typed in the OpenAPI schema. Credentials: `auth.json` per data-dir; per-user isolation achievable process-wise via `OPENCODE_CONFIG_DIR` + `XDG_DATA_HOME` (proven pattern: the opencode-multi profile tool — "no modifications to OpenCode itself"). **Caveats:** (1) **Anthropic subscriptions are excluded** — official docs state Anthropic prohibits Pro/Max use through opencode; Anthropic is API-key-only there. (2) **OpenCode 2.0 (beta) declares the V1 server API an intentional breaking change** ("Integrations that call the V1 server API must migrate to the V2 API"; V1 plugins won't work) — adopting opencode today means pinning 1.x and budgeting a V2 migration. (3) Wart list: `agent`-param model fallback bug (#7099), a June 1.15.13 regression that briefly broke headless message POST (#31412), 1.x compaction threshold hardcoded (#11314), some state files ignore XDG redirection (#18633). (4) opencode Zen (their paid model gateway) is optional and metered — irrelevant to Sinet except as something to leave disabled.
- **OpenHands + Software Agent SDK V1 (OpenHands org, ex All-Hands-AI; MIT — app repo has an `enterprise/` directory under a separate license; SDK v1.36.1 on 2026-07-15, multiple releases/week; VC-backed).** The strongest Python-native substrate: ground-up V1 rewrite around an SDK with an **event-sourced state model with deterministic replay** (arXiv 2511.03690), an **agent-server** (REST + WebSocket, interactive OpenAPI docs, webhooks, `X-Session-API-Key` auth, encrypted secrets), per-conversation `LLM` objects (any LiteLLM-convention provider + base_url, `SecretStr` keys — the cleanest per-run credential story of the field), confirmation policies (`AlwaysConfirm`/`NeverConfirm`/`ConfirmRisky`) with a **persistent `WAITING_FOR_CONFIRMATION` state** that survives process restarts (approval can arrive hours later — exactly Sinet's 4.3 semantics), immediate-write persistence (`persistence_dir`, crash-recoverable), LLM-summarizing condenser, MCP, sub-agents via composable `DelegateTool`/`TaskToolSet` (topology is programmer-defined — trivially constrainable to D6). Local models documented (Ollama/LM Studio/vLLM/SGLang). Weaknesses vs opencode for Sinet: smaller flat-rate-provider ecosystem wiring (no Z.AI devpack listing), younger server surface, heavier default deployment (its sandboxing/workspace layers assume more infrastructure).
- **Goose (Apache-2.0; Linux Foundation "Agentic AI Foundation" since 2025-12; v1.43.0 2026-07-14).** Healthy governance, weekly releases — but **architecturally mid-flight**: maintainers are replacing the bespoke `goosed` REST+SSE daemon (103 endpoints, used by its desktop/mobile clients) with an ACP-based `goose serve`, after which `goosed` and `goose-cli` are slated for **removal**. Sub-agents marked experimental. Adopting now means building on an interface that its own maintainers have scheduled for demolition.
- **Crush (Charmbracelet; FSL-1.1-MIT — fair-source, 2-year non-compete window per release then MIT; v0.85.0 2026-07-16).** License alone would *not* block Sinet (personal "internal use" is expressly permitted), but the engine is the wrong shape: no sub-agents, `crush serve` exists but has **no published API reference**, no documented external permission-answering protocol, `crush run` sessions aren't saved by default. Patterns remain instructive (see harvest verdicts).
- **aider (Apache-2.0).** Effectively in maintenance mode: one release in ~11 months (v0.86.2, 2026-02-12), the community "future direction" issue unanswered, no server mode, the Python scripting API explicitly "not officially supported," no MCP. Not adoptable as a substrate.
- **First-party CLIs as engines:** **Codex CLI (Apache-2.0)** ships a real machine interface — `codex app-server` (JSON-RPC 2.0 over stdio; `thread/start|resume|fork`, `turn/start|interrupt`, streamed `item/*` deltas, server-initiated approval requests, token usage on `turn/completed`; WebSocket listen mode exists but is "experimental and unsupported") plus `codex exec --json` headless with resume. **Gemini CLI** remains a well-documented OSS artifact (headless JSON/stream-JSON, documented exit codes, checkpointing, `--acp`) that consumers can no longer fund with a subscription. **Qwen Code (Apache-2.0)** is a capable Gemini-CLI descendant (`qwen serve` ACP-over-HTTP+SSE daemon, TS/Python/Java SDKs, JSONL sessions) whose free tier died and whose paid plan bans non-interactive use. **Copilot CLI** is GA with a programmatic mode but no JSON output format and credit-metered billing.
- **Others scanned:** pi (MIT, RPC-over-stdio, impressive but bus-factor-1 by design), Cline (Apache-2.0, SDK-shaped, no standalone server), Codebuff (routes through its own backend), Amp/Factory droid (closed), Roo Code (shut down 2026-05), Kilo CLI ("rebuilt on OpenCode" — collapses into opencode), nanocoder/mini-swe-agent (wrong shape).

### 2.3 What real control planes do (and what it costs)

The churn evidence is one-directional and multiply-sourced:

- **Deep CLI integrations are the churn sink.** Omnara v1 (PTY wrapper + `~/.claude/projects` JSONL parsing) is deprecated with an explicit capitulation notice — "became unfeasible to maintain with Claude Code's constant updates" — and was rebuilt on the Agent SDK. coder/agentapi (terminal-emulation REST over 11 CLIs) self-describes as a stopgap to be deprecated "in favor of the official SDKs" and broke on a single Claude point release (2.1.83). Vibe Kanban survives by pinning exact executor versions (`@anthropic-ai/claude-code@2.1.119`) and bumping pins near-weekly; its corporate sponsor sunset the product. CCManager carries per-CLI terminal "state detection strategies" that break on cosmetic TUI changes ("esc to interrupt" text removed). GitButler's strict stream-json enum parser died on the *introduction* of a new `rate_limit_event` type. Claude Squad is the healthy counter-example precisely because it is *shallow* — tmux passthrough, no protocol parsing.
- **First-party surfaces are the comparatively durable posture — but not absolutely durable** (adversarial finding, PARTIAL-REFUTE folded in): the Claude Agent SDK is pre-1.0 and shipped multiple breaking changes in one 2026 release (0.3.142); Codex app-server docs tell integrators to pin versions and regenerate schemas; opencode V2 intentionally breaks the V1 server API. **The correct engineering conclusion for Sinet is not "first-party surfaces are safe" but: every substrate is a versioned dependency — pin exact versions, upgrade deliberately, parse streams tolerantly (unknown event types must pass through, never crash), and keep a per-substrate conformance/canary test suite.** This concretizes S2.8 into a testable platform feature.
- **Nobody has true mid-run pause.** Every surveyed system fakes pause as *interrupt (or checkpoint) + resume-from-state*: Claude Squad commits and removes the worktree; Happy restarts the session in remote mode; Coder Tasks saves/restores conversation history. The primitives that exist are interrupt verbs (Codex `turn/interrupt`, Agent SDK `interrupt()`, ACP `session/cancel`, opencode `abort`), never suspension. D3's "pause" maps to "interrupt at a safe boundary, park, resume later" — which is also what 3.2/4.3 want anyway.
- **Checkpoint is substrate-native and hazardous at the edges.** Claude Code's recoverable unit is the per-message JSONL transcript (`~/.claude/projects/<encoded-cwd>/<session-id>.jsonl`), resumable/forkable by session id — with documented failure modes Sinet must design around: session storage keyed by CWD path (worktree rename breaks `--resume` → a control plane entered a "perpetual failure loop"), transcript corruption modes (orphan tool_result after compaction; empty text block; parallel tool_results truncation), **interrupt-during-tool-call permanently corrupting the transcript**, `-p` sessions missing from the newer sessions-index (resume-by-id still works), and **`cleanupPeriodDays` deleting session files after 30 days by default**. Codex persists JSONL "rollouts" with `thread/fork` and turn-level rollback; Gemini CLI checkpoints file snapshots + conversation per tool call; opencode stores sessions under its data dir with fork and undo/redo backed by internal git snapshots. **No protocol exposes "checkpoint" as a verb; the control plane must own it** (which D7 already assumed).
- **Usage fidelity varies by lane:** Claude headless result envelope carries `total_cost_usd` (emitted even on subscription auth — an API-equivalent figure, exactly D5's reporting currency) plus `usage` and per-model `modelUsage`; a `rate_limit_event` stream type surfaces limit state in-band (D4/3.2 gold). Codex reports tokens (no dollars). opencode reports per-message tokens + computed cost. Gemini JSON mode returns a stats block. ACP's session-level `usage_update` is now **stable** (RFD completed 2026-06-05: tokens-in-context, context size, optional cost) but per-turn usage is still schema-unstable and emission is inconsistent across agents (Claude/Codex adapters emit; Gemini uses `_meta`). agentapi and A2A carry nothing.
- **Per-run credential isolation is a solved pattern:** `CLAUDE_CONFIG_DIR` per account (multi-source; commercial products built on it), `CODEX_HOME` per profile, opencode via `OPENCODE_CONFIG_DIR`+`XDG_DATA_HOME`. Gemini CLI has no documented equivalent (moot for Sinet). This is D2's mechanism: one engine process per user, environment-scoped credential stores, credentials living in the engine process outside task sandboxes.

### 2.4 Adapter-standard candidates

- **ACP (Agent Client Protocol; Zed+JetBrains joint governance; v1 stable, weekly releases; 36 agents listed including native `opencode acp`, `gemini --acp`, `goose acp`, `copilot --acp`, Qwen, Kimi, Cline, OpenHands; clients: Zed, JetBrains, Neovim, Emacs, marimo, MS Intelligent Terminal).** Covers: session/new, capability-gated `session/load` (full replay) plus `session/resume` (stabilized 2026-04-22, reconnect without replay), prompt + 11 stable update kinds (including `usage_update` and plan/mode/tool-call updates), `session/request_permission` (allow/reject, once/always), `session/cancel`, terminal management. **Missing vs Sinet's contract: no pause (expected), no checkpoint/fork verbs (session-fork RFD unfinished), per-turn usage unstable, quota/limit surfacing agent-specific.** Note: the official Claude ACP adapter (`claude-agent-acp`) wraps the **Agent SDK** with subscription+Console auth — so ACP's Anthropic path inherits the same policy bucket as any SDK wrapper, it does not launder it. A headless ACP client for orchestrators exists (openclaw/acpx: crash-detection, session reload, per-repo scoping).
- **Codex app-server** — the model of what a first-party programmatic surface should look like (threads/turns/approvals/usage/fork), single-vendor only.
- **Claude Agent SDK** — "Claude Code as a library" (sessions, `resume`/`forkSession`, `canUseTool` approval callback, `interrupt()`, cost+usage on results, hooks); pre-1.0 churn; versioned in lockstep with the CLI.
- **coder/agentapi** — de-facto REST over TUIs; self-declared transitional; no usage/resume; not a foundation to build on.
- **A2A** — inter-agent delegation semantics (terminal tasks cannot restart; no usage), wrong layer for an execution adapter; ignore.

**12.7/12.8 awareness note:** every serious candidate surface is already network-transparent (opencode serve binds a host/port with basic auth; OpenHands agent-server is REST/WS; Codex app-server has an experimental WebSocket listen mode; ACP is transport-agnostic). If Sinet ever grows beyond one host, the adapter contract survives unchanged — satellite runners would speak the same protocols remotely. No design work needed now; nothing in this report's recommendation forecloses it.

## 3. Candidate approaches

**A. Single engine: opencode for everything.** Fails the constraint set outright: Anthropic subscriptions cannot ride opencode (prohibited, enforced, plugin removed), and household Claude plans are the core paid capacity. Rejected as sole approach.

**B. Single substrate: wrap Claude Code for everything** (Anthropic natively; Z.AI/Kimi/MiniMax via their Anthropic-compatible endpoints — all three officially support Claude Code as a client; local models via a local Anthropic-compatible proxy). Genuinely viable on paper, and notable as the *minimal* v0. Costs: every non-Anthropic provider rides an env-var-redirected `claude` binary (`ANTHROPIC_BASE_URL`), so one vendor's CLI release cadence (~daily, 321 releases/yr) becomes the single point of drift for **all** lanes; no OpenAPI control surface (process-per-run only); local-model wiring is awkward (needs an Anthropic-protocol shim in front of llama.cpp/vLLM); concentrates the exact billing-regime risk (§2.1) on 100% of capacity. Kept as a fallback shape, not chosen.

**C. Dual substrate behind one adapter — opencode serve (API lane) + wrapped `claude` CLI (Anthropic lane).** This is D3 as written, instantiated with the two strongest 2026 artifacts. The API lane (opencode) carries: Z.AI GLM (officially whitelisted), Kimi/MiniMax if ever subscribed (both list opencode), local models (native OpenAI-compatible providers), and explicitly-enabled metered keys. The wrap lane (`claude -p` stream-json) carries each member's Anthropic plan through Anthropic's own sanctioned tool. Two substrates ≈ two conformance suites — the solo-maintainer cost the churn evidence says is sustainable *precisely when* one is a structured server API and the other is a single first-party CLI wrapped shallowly (JSON streams only, no TUI scraping, no undocumented surfaces).

**D. Anthropic lane via Agent SDK instead of (or behind the same interface as) the CLI wrap.** Pros: typed events, in-process `canUseTool` approval callback, `interrupt()`, fewer process-management edge cases; every wrapper that survived 2026 migrated to it (Omnara, Happy). Cons: pre-1.0 breaking-change cadence; it is the *more* "third-party product"-shaped surface in policy terms; it is versioned in lockstep with the CLI anyway (0.3.212 ↔ 2.1.212 same day), so it dodges no drift. Resolution: **this is an implementation detail inside the Anthropic adapter, not an architecture fork** — both drive the same session substrate (same JSONL transcripts, same auth, same billing bucket); Sinet should build the adapter against its own contract and pick CLI-wrap vs SDK in the G1 spike, with the loser kept as a documented fallback. Start-assumption: CLI-wrap first (it is the surface Anthropic's own docs bless for scripts, and process isolation per user is trivial with `CLAUDE_CONFIG_DIR`).

**E. ACP as the one uniform adapter for all lanes.** Not yet: no checkpoint/fork verbs, per-turn usage unstable, quota surfacing non-standard — exactly the three things Sinet's contract needs beyond lifecycle. But ACP's verb set is a strict subset of Sinet's contract, so: design Sinet's adapter verbs to be ACP-compatible (same lifecycle shape, permission-request pattern, update-notification pattern), revisit adoption when fork/usage RFDs land. Watching brief, not dependency.

**F. OpenHands agent-server as the engine of record.** The strongest alternative to opencode: event-sourced replayable state (better checkpoint alignment with D7 than any competitor), persistent confirmation states, encrypted per-conversation credentials. Costs vs opencode: no flat-rate coding-plan ecosystem standing (not on Z.AI/MiniMax whitelists — those lanes would need generic OpenAI-compatible wiring and ToS reading), younger external-control surface, heavier deployment, and the Anthropic lane *still* needs the Claude Code wrap. Named fallback if opencode's V2 transition goes badly.

**G. Multi-engine executor matrix (Vibe-Kanban shape: opencode + Codex + Gemini + Copilot + …).** The production evidence (pin-bump treadmill, executor breakage, dead/pivoted precedents) prices deep multi-engine support beyond one maintainer. Rejected. A Codex lane is added *only* if a household member actually holds a ChatGPT plan, as a second first-party wrap (app-server), and only then.

## 4. Recommendation for Sinet

**Adopt two substrates, unmodified, behind Sinet's own adapter contract (approach C, with D held open inside the Anthropic adapter):**

1. **Engine of record: opencode v1.x, pinned** (exact version, deliberate upgrades only), one `opencode serve` instance **per user** launched by the control plane with per-user `OPENCODE_CONFIG_DIR` + `XDG_DATA_HOME` (D2: separate auth.json per person; spike-test the #18633 XDG stragglers before sign-off). Carries: Z.AI GLM plans, any other third-party-open flat-rate plan, all local models (llama.cpp `llama-server` / vLLM on the 5070 Ti/3090 pools as OpenAI-compatible providers), and explicitly-flagged metered keys. Control integration: OpenAPI-generated client, SSE event subscription, `prompt_async` + abort, per-message `model: {providerID, modelID}` routing, external permission answering via `POST /session/:id/permissions/:permissionID`, plugin hooks only if config-level (no engine patches, ever). Sub-agents: leave the default one-level guard in place; **never set a global `task` permission rule** (documented unbounded-recursion footgun); depth-2 delegation, when a task earns it, is orchestrated by the control plane as sibling sessions it spawns and logs itself (D6's "every spawn logged" falls out for free).
2. **Anthropic lane: wrap the `claude` CLI, pinned, per user** — `claude -p --output-format stream-json --input-format stream-json --verbose --include-partial-messages`, per-user `CLAUDE_CONFIG_DIR`, auth via each member's own `claude setup-token` (1-year, inference-scoped, the documented scripts path). Permission gating: `--permission-prompt-tool` (MCP approval tool owned by the control plane) plus `PreToolUse` hooks with the `defer` decision (a headless-only external-approval primitive, purpose-built for exactly Sinet's inbox). Resume: `--resume <session-id>` (+ `--fork-session` for retry-without-poisoning); model per invocation via `--model`. Usage: parse the result envelope (`total_cost_usd`, `usage`, `modelUsage`) — note `total_cost_usd` on subscription auth is precisely D5's API-equivalent reporting figure. Limits: treat `rate_limit_event` and result-level limit errors as 3.2 park events. Never `--dangerously-skip-permissions`; sandboxing via settings (bubblewrap) consistent with S5; raise `cleanupPeriodDays` well above the freshness horizon **and** treat Sinet's own store as the durable record (below).

**The adapter contract, verb by verb (D3 minimum contract → substrate mapping):**

| Contract verb | opencode serve | wrapped `claude -p` | Bridge/note |
|---|---|---|---|
| start | `POST /session` + `prompt_async` (model, agent params) | spawn process (`--session-id` UUID chosen by control plane) | Both accept per-run model + per-run credential env (D2) |
| stream progress | SSE `/event` (typed message parts) | stdout JSONL (typed events incl. partials) | **Tolerant parsing mandatory** — unknown event types logged and skipped, never fatal (GitButler lesson) |
| checkpoint | session state in engine store; per-message granularity | JSONL transcript per message; resumable by id | **Engine stores are the resume medium, not the checkpoint.** Sinet's control plane persists its own event log + last-known session_id + artifact snapshot after every paid call (D7). Engine-side hazards (CWD-keyed lookup, 30-day cleanup, corruption modes) then only ever cost a resume optimization, never paid work |
| pause | `POST /session/:id/abort`, park, re-prompt later | interrupt process at message boundary, park, `--resume` later | True pause exists nowhere in the field; D3 "pause" = interrupt-at-safe-point + park. Avoid interrupting mid-tool-call on the Claude lane (documented transcript corruption); prefer boundary interrupts, fall back to `--fork-session` from last good message |
| resume | new prompt on existing session id | `--resume <id>` / `--fork-session` | Always through the 4.3 freshness check first |
| cancel | abort + session abandoned | process-group TERM→KILL | Orphan-harvest ladder (N1) classifies survivors on restart; worktree/lock cleanup owned by control plane |
| report usage | per-message tokens + computed cost from API | envelope `usage`/`modelUsage`/`total_cost_usd` | Sinet meters independently (D4) and prices via its own table (D5); engine figures are cross-checks and receipt inputs |

**Hardening rules derived from the evidence (these go in the spec):** (1) both substrates are pinned versioned dependencies with a per-substrate **conformance/canary suite** run before any upgrade and on a schedule (S2.8 concretized — drift is *when*, not *if*: 321 releases/yr on one lane, an announced V1→V2 API break on the other); (2) stream parsers are forward-tolerant; (3) the adapter is the **only** component that touches engine specifics — everything above it sees Sinet's contract; (4) provider billing-regime changes (the §2.1 arc) are handled as *data* (per-model flat/metered flags, 3.10 kill-switch), not as architecture.

**Why this and not the alternatives:** it is the only shape that satisfies subscription coverage on every lane (first-party wrap where required, API where permitted), keeps the maintenance surface at two pinned substrates with the churn-resistant postures the 2026 evidence favors (structured server API + shallow first-party wrap), gives D2/D6/D7 concrete, config-only mechanisms on both lanes, and keeps every future door open (SDK swap inside the Anthropic adapter, ACP convergence, OpenHands fallback, Codex lane addition) without re-architecting.

**What would change the decision:**

- **Credits change un-pauses** (Anthropic promised advance notice): the Anthropic *headless* lane becomes metered-by-policy. Sinet's response is a policy decision (pre-register it now): either treat it as the explicit metered exception within each member's announced credit ($100–200/mo on Max) or demote Anthropic to interactive-only and shift headless weight to the Z.AI-class lane. No architecture change — which is the point of the dual substrate.
- **opencode V2 lands badly** (API regressions, delayed stabilization, licensing/Zen drift): hold on pinned v1; if v1 rots, the named fallback is **OpenHands agent-server**, whose contract mapping is equivalent-or-better (event-sourced replay) at the cost of provider-wiring work.
- **Anthropic formally clarifies personal-use SDK/third-party rules**: a written personal-use safe harbor would unlock the SDK path as the primary Anthropic adapter (better typed control) or even opencode-native Anthropic; a hostile clarification (first-party-interactive-only) forces the metered-exception decision early.
- **ACP ships checkpoint/fork + stable per-turn usage + quota surfacing**: converge the adapter's transport onto ACP and shrink Sinet-specific glue.

## 5. What NOT to use and why

- **Goose (now):** its external-control surface (`goosed` REST) is scheduled for removal in favor of a not-yet-stable ACP server; adopting mid-migration buys guaranteed rework. Re-evaluate post-consolidation.
- **Crush as engine:** no sub-agents, no published server API reference, no external permission protocol; FSL-1.1-MIT permits Sinet's personal use but the capability gaps decide it. Patterns only (K1/K2).
- **aider:** dormant (1 release in 11 months), no server mode, unsupported scripting API. Its architect/editor split is a routing idea, not a substrate.
- **coder/agentapi and all PTY/TUI-scraping approaches:** self-declared stopgap; breaks on cosmetic point releases; carries no usage/resume. The entire category (screen-scraping first-party TUIs) is evidenced unmaintainable for one person.
- **ACP as the sole adapter today:** missing checkpoint/fork verbs, per-turn usage unstable, quota surfacing non-standard — the exact deltas Sinet needs; and its Claude adapter rides the Agent SDK policy bucket anyway. Track, align verbs, don't depend.
- **Deep multi-engine executor matrices** (Vibe-Kanban shape): weekly pin-bump treadmill, executor-specific breakage, and the three most prominent exemplars died or pivoted within a year. One maintainer cannot fund it.
- **Gemini/Google lane:** consumer programmatic access is dead (2026-06-18); wrapping Gemini CLI means metered API keys or org licenses, and Google names third-party OAuth use a violation. Antigravity CLI has no documented JSON surface and unpublished quotas. Nothing to build on for a household.
- **Alibaba Model Studio Coding Plan:** contractually bans automated/non-interactive use — structurally incompatible with Sinet regardless of technical fit.
- **GitHub Copilot as a flat-rate lane:** since 2026-06-01 it is token-credit-metered (allowance then metered), and its CLI has no JSON output; usable someday as an explicitly-metered exception, pointless as a flat-rate substrate.
- **Account pooling / shared subscriptions in any form:** prohibited by Anthropic's consumer terms (and Z.AI's, and others') — and D2 already forbids it. Per-person accounts only.
- **Agent SDK as the sole engine today:** pre-1.0 breaking-change cadence plus the "third-party products need approval" clause make it the gray-zone-shaped option; keep it as the alternate implementation inside the Anthropic adapter, not the foundation.
- **Codebuff (backend-coupled), pi (bus factor 1 by its own design), Cline (no server surface), Amp/Droid (closed), Roo Code (shut down), Kilo CLI (is opencode), nanocoder/mini-swe-agent (wrong shape).**
- **Forking/patching any engine** — reaffirmed empirically: the field's velocity (daily releases, scheduled API breaks) makes Nexus-style pinned-fork maintenance strictly worse in 2026 than it was in early 2026.

**New platform problems discovered (for the spec's Known-problems list):**

- **P-T01-1 — Engine transcripts are not durable checkpoints.** Claude Code deletes session data after `cleanupPeriodDays` (default 30); `-p` sessions are missing from its session index; session lookup is CWD-keyed (worktree rename breaks resume); transcripts have documented corruption modes, including interrupt-during-tool-call. → D7's checkpoint store must be Sinet-owned and authoritative; engine sessions are a resume optimization only; config raises retention; resume failures degrade to fork-from-last-good, never to lost work. *(Feeds T07.)*

- **P-T01-4 — Cancel and checkpoint interact destructively on JSONL substrates.** Interrupting mid-tool-call can corrupt the engine-side transcript permanently. → The adapter's cancel protocol must prefer message-boundary interrupts and treat fork-from-checkpoint as the standard recovery, with transcript-repair as last resort. *(Feeds T07's cancel/retry semantics.)*
