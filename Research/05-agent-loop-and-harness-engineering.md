## 2. Current state of the art (mid-2026)

### 2.1 Harness engineering is now a named discipline — and the field agrees on a two-tier boundary

"Harness" became a first-class term in 2025–26. Anthropic has two dedicated engineering posts: *Effective harnesses for long-running agents* (2025-11-26) and *Harness design for long-running application development* (2026-03-24). Their framing: "The core challenge of long-running agents is that they must work in discrete sessions, and each new session begins with no memory of what came before" — the harness owns session looping, durable artifacts bridging sessions (progress files, a feature ledger with `passes:false` flags, git commits as recoverable state), explicit context resets with handoff artifacts (compaction alone was insufficient), and doer/judge separation. Two design rules with direct Sinet consequences: "every component in a harness encodes an assumption about what the model can't do on its own," and harnesses should shrink as models improve (their own V2 removed sprint decomposition) [S1, S2, P]. The community definition converged the same way: awesome-harness-engineering ("the discipline of designing the scaffolding — context delivery, tool interfaces, planning artifacts, verification loops, memory systems, and sandboxes — that surrounds an AI agent," 12 layers) [S20, P]; Osmani's "If you're not the model, you're the harness" [S21, S]; and — most useful for Sinet — Böckeler on martinfowler.com formalizes **inner vs outer harness**: the agent product's internal harness vs the user's control layer built on top of it, with controls split into *guides* (feedforward) and *sensors* (feedback), each either computational (deterministic, fast) or inferential (LLM, slow) [S22, P]. Sinet is an outer harness by construction; opencode and Claude Code are inner harnesses.

**What the two settled engines own (get free, steer via config/hooks/API):**

- **Claude Code lane.** Hook surface far larger than commonly cited — the load-bearing events for a wrapper: `PreToolUse` (returns `permissionDecision: allow|deny|ask|defer` + `updatedInput`), `PostToolUse` (can rewrite tool output), `PostToolBatch` (can stop the loop between batches), `Stop` (can block turn-end), `StopFailure` (fires on API-error turn end with categories `rate_limit|overloaded|authentication_failed|billing_error|server_error` — observe-only), `PermissionRequest`/`PermissionDenied`, `SessionStart/End`, `PreCompact` (can veto)/`PostCompact`, `SubagentStart/Stop`, `ConfigChange` (blockable — a config-tamper tripwire), `Notification` [S3, P]. Permission evaluation is a documented 6-step pipeline: **hooks → deny rules → ask rules → permission mode → allow rules → `canUseTool`** — with the critical subtlety that "auto-approved tools never reach `canUseTool`" (SDK warns `CLAUDE_SDK_CAN_USE_TOOL_SHADOWED`); "for checks that must run on every tool call, use a `PreToolUse` hook: hooks run before every other step" [S4, P]. **Sinet's gate must therefore live in PreToolUse hooks, never solely in a callback.** Ceilings: `--max-turns` and `--max-budget-usd` (both print-mode; §2.6). Compaction: on/off only (`autoCompactEnabled`), threshold not configurable; `PreCompact` veto + `SessionStart(source: compact)` re-injection are the control points [S5, P]. OS sandboxing is deep and native (Seatbelt/bubblewrap, network default-deny, credential masking) [S6, P]. Vendor posture on prompting: Anthropic's own data — "Claude Code users approve 93% of permission prompts" → approval fatigue; their answer is rules + classifier (auto mode) + sandbox, i.e. **the vendor itself treats blanket per-action human prompts as a failed pattern** — which is exactly the spec's 4.2 shape (gate only non-idempotent outward effects) [S7, P].
- **opencode lane.** Plugin hooks: `tool.execute.before/after` (block by throwing), `shell.env`, `experimental.session.compacting`; bus events over SSE `/event`: `permission.asked/replied`, `session.created/updated/compacted/error/idle/status`, `message.part.updated`, `file.edited`, `todo.updated`, etc. [S8, P]. Server seams: OpenAPI 3.1 at `/doc`, `prompt_async`, `POST /session/:id/abort`, and the external answer endpoint `POST /session/:id/permissions/:permissionID` `{response, remember?}` [S9, P]. Permission grammar allow/ask/deny with bash sub-patterns, per-agent overrides — including **`doom_loop`**, an engine-native loop tripwire (§2.5). Per-agent step cap is **`steps`** (`maxSteps` deprecated); compaction has real knobs (`auto`, `buffer`, `keep.tokens`) but v2's `prune` is currently inert [S10, S11, P]. No OS-level sandbox found in opencode docs (absence across all fetched pages, not exhaustively proven) — if OS containment is wanted on this lane, Sinet supplies it externally (S5 ladder; `@anthropic-ai/sandbox-runtime` ships standalone) [S6, P].

**What no engine provides — the outer-harness re-own list (unanimous across Anthropic's practice, the discipline's layer lists, and doc absence):** durable per-paid-call checkpointing (Claude Code *deletes* session data after `cleanupPeriodDays`, default 30); an async approvals inbox with expiry and audit; cross-run/cross-day/cross-user ceilings and spend ledgers; watchdogs and unattended supervision (engine events are signals only); durable receipts exported before engine cleanup; multi-user identity; independent verification runs; freshness re-validation (nobody has it — §2.4). Anthropic re-owns exactly this tier when building harnesses above its own engine [S1, S2, P]. **D7's layering is the field's consensus architecture, and both engines expose precisely the seams the outer tier needs.**

### 2.2 Checkpoint semantics: what a checkpoint *is*, per system — and what resuming really costs

**The checkpoint inventory (all primary):**

| System | Checkpoint unit | Contents | Fidelity holes |
|---|---|---|---|
| Claude Code | JSONL transcript line per message; file checkpoints **per user prompt** (ring of 100) | conversation; edit-tool file snapshots (`/rewind` restores code, conversation, or both) | format "internal… can break on any release"; **bash-driven file changes not tracked**; CWD-keyed lookup; 30-day sweep [S12, S13] |
| opencode | **worktree snapshot per model step** ("immediately before the model call and after a cleanly completed step") in an internal git object DB; `session.revert/unrevert` API | tracked+untracked files (>2 MiB untracked excluded); message parts | requires a git repo; shell side effects (DBs, services) not reversed; undo/redo had shipped data-loss bugs (#10589, #27664) [S14, S15] |
| Gemini CLI (reference design) | per approved fs-modifying tool call | **the trio: shadow-git snapshot + full conversation + the pending tool call**, atomically restorable | off by default; the closest published match to D7's gated-proposal semantics [S16] |
| OpenHands V1 | append-only event log + `base_state.json`; resume = replay-to-last-event | every agent interaction as a typed event | workspace state outside the checkpoint [S17] |
| LangGraph | channel-values snapshot per super-step + **pending writes** (successful sibling nodes not re-run) | graph state by `thread_id`+`checkpoint_id` | node granularity (a node with 3 LLM calls = one checkpoint); pickle-ish serializer; schema-evolution breaks old threads [S18, S19] |
| Durable-execution runtimes | **the paid call as a journaled step**: Temporal (activity results in event history), Inngest (memoized `step.ai`), Restate (journal), DBOS (step outputs in Postgres, written in the step's transaction) | request+response persisted; replay never re-calls the LLM | Temporal: 51,200-event/50 MB history cap, SQLite dev-only; Inngest: cloud coupling; DBOS: requires Postgres; Restate: single binary + RocksDB (~2 GiB default) [S23–S26] |

**Granularity readout for D7:** checkpoint-at-paid-call exists today only in durable-execution journals and opencode's snapshotter. The CLIs' recovery checkpoints are coarser (per user prompt / per approved tool call), but both engines emit a **durable-enough stream record per paid call** (Claude stream-json result envelopes with `usage`/`total_cost_usd`/`modelUsage`; opencode per-message token+cost events) — so a wrapper achieves D7 granularity by *persisting its own event log from the stream*, exactly the split-store pattern live in Vibe Kanban ("code state is managed by Git, workflow state by SQLite") [S27, P/S].

**Recovery-fidelity taxonomy (uniform across the field):** (i) conversation — recovered everywhere; (ii) workspace — recovered only where snapshotted; (iii) **in-flight tool effects — covered by nobody** ("checkpoints tell the runtime where it was… not whether an email was sent"); (iv) accounting — persisted only where the harness journals it. The recovered/re-done line is always "last durable step recovered; in-flight step re-done." War stories confirm snapshot/undo is the chronically buggy layer (opencode undo/redo family; Claude fork-resume loading 0 messages, #25085; sessions vanishing from UI while JSONL remains, #59736; Vibe Kanban's CWD-key breakage; a LangGraph production postmortem: schema evolution silently breaking old threads, 40 GB checkpoint tables in six weeks) [S15, S28, S29, S]. **Consequence: the platform's store must version its schema, own retention, and never trust engine-side undo to have actually restored files** — P-T01-1 reinforced.

**Resume economics — reload, not replay.** Both engine families re-send the full conversation as input tokens on every turn; prompt caching is the only mitigation. Verified specifics: exact-prefix server cache; **subscription auth auto-requests the 1-hour TTL** (API keys default 5 min; TTL silently drops to 5 min when drawing on usage credits; **subagents always get 5 min even on subscription**); a resume past TTL re-pays the whole context; "resuming a session after an upgrade reprocesses the entire conversation history with no cache hits… the first turn back into a long session can be the most expensive request you send" [S30, P]. The precedent that this degrades *silently*: issue #34629 — `--print --resume` stopped caching conversation turns entirely (~$0.02–0.05 → flat ~$0.35/message, ~20x) — **fixed in v2.1.90**, but with siblings closed *not-planned* (#44045 partial cache miss per resume turn; **#39732 prompt caching disabled for SDK `query()`/V2 sessions**; #46829 a TTL 1h→5m regression) [S31, P]. Two consequences: (1) **per-call `cache_read`/`cache_creation` monitoring with a stuck-flat alarm is a platform feature, not paranoia**; (2) #39732 is a live data point for report 01's open question 3 (CLI-wrap vs SDK inside the Anthropic adapter) — the CLI wrap currently has the healthier caching story. The token-multiplication trap is corroborated at the source: Anthropic measured agents ≈ 4x and multi-agent ≈ **15x** chat token use [S32, P]; the mitigations are structural — artifact/summary handoffs instead of transcripts, truncation over rewrite, "hold a reference and a cursor, not the history."

### 2.3 Pause/park/resume across hours: the universal shape and the two substrates

**Every serious system parks the same way: a durable record + zero compute while parked + an external event that re-drives execution.** LangGraph `interrupt()` persists state via the checkpointer and "waits indefinitely" with no process running; resume via `Command(resume=…)` — with the documented footgun that **the interrupted node re-executes from its start on resume** (side effects before `interrupt()` must be idempotent), and same-thread concurrent invocation is undocumented and breaks in issues [S19, S33, P]. Temporal parks in `wait_condition`/timers ("a single Worker can await millions of Timers"; timers survive service downtime and fire late, as minimums — on a sleeping laptop, *everything* fires on wake) [S34, P]. Inngest `step.waitForEvent` and Restate awakeables are the same shape [S35, S36, P]. **None of them re-validates anything on resume — they replay blindly by design** (that gap is §2.4).

**opencode lane.** While `opencode serve` is up: `permission.asked` parks the turn at zero token cost indefinitely; the ask is answerable from anywhere via `POST /session/:id/permissions/:permissionID`; pull-based enumeration exists (`permission.list`, `question.list` REST endpoints — the TUI's historical attach-blindness to them is fixed, #13657). But **pending asks live in an in-memory `Map` (source-verified: `packages/opencode/src/permission/index.ts`) — a serve restart loses the ask**; the session itself persists on disk, and the supported park-across-restart is re-prompting the same session id (a paid turn). Issue #15172 (unanswered question unrecoverable after restart) is open, maintainer-reopened [S37, S38, P]. A serve+attach hang when any permission is set to "ask" (#16367) is the wart to conformance-test on this exact path [S38, P]. Ecosystem proof the live-park pattern works: remote-approval dashboards and Telegram approvers built on the answer endpoint [S39, P].

**Claude lane.** Two primitives, different park durations:

- **`--permission-prompt-tool` / `canUseTool` = held-process parking.** The turn blocks in RAM at zero token cost while an MCP callback asks a human. This is how the surviving remote-approval wrappers work (Happy: CLI keeps Claude running, E2E-encrypted relay to mobile; Omnara: push notification → tap approve → "agent instantly receives your input") [S40, P]. Fine for minutes; fragile for hours on a host that sleeps.
- **PreToolUse `defer` = exit-and-resume parking — the platform-grade primitive.** Added v2.1.89 and now *fully officially documented* (the docs gap closed 2026-04-28): the headless process **exits** with `stop_reason: "tool_deferred"`, the pending tool call preserved in the transcript; `claude -p --resume <session-id>` **re-fires PreToolUse on the same tool call**, and the hook can now allow (optionally with `updatedInput` carrying the human's answer) or keep deferring (polling is sanctioned — "no timeout or retry limit"). Precedence `deny > defer > ask > allow`. Constraints, all verified: honored **only in `-p` mode** (interactive logs a warning); **only when the turn contains a single tool call** — parallel tool calls make defer fall back to the normal permission flow with a warning; a missing tool on resume yields `stop_reason: "tool_deferred_unavailable"` + `is_error`; resume restores the prior permission mode (never `plan`/`bypassPermissions`). **And the trap: a deferred session is still subject to the `cleanupPeriodDays` sweep (default 30 days) — a parked tool call silently evaporates past retention** [S41, P; 3-vote SUPPORT].

**Prior-art parking mechanics validated for the harvest verdicts:** Archon parks as a **database run row + `node_completed` events + artifact files** — approval nodes pause the DAG; resume loads the events, skips completed nodes, re-runs only failed/unrun ones; conversational context is *not* frozen — handoff is artifacts (§6, A3). Crush parks by **blocking a goroutine on a pub-sub broker** — any attached client answers, first resolver wins atomically, nothing persisted, no expiry (§6, K1).

### 2.4 Freshness re-validation on stale resume: nobody does it — Sinet's 4.3 is novel

**The narrowed, verification-hardened claim: no shipped agent system in mid-2026 re-validates a parked run's remaining plan against changed reality (repo HEAD moved, sources changed, prices shifted) before continuing.** Probed adversarially across Devin (event-driven wake, workspace snapshot restore, no plan recheck), Cursor background agents (manual rebase explicitly recommended), GitHub Copilot coding agent, Google Jules, Factory, LangGraph (community guidance is explicit: it "does not automatically re-validate the proposal against the new world state — you must build that check"), Temporal/Inngest recipes, and 2026 academic replanning work (covers goal changes/tool failures, not parked-plan environment drift) [S42–S45, P/S]. Direct evidence the failure mode is real and unsolved at the frontier: OpenAI Codex issue #31982 — "Codex resumes from a stale conversational checkpoint after hard shutdown while VCS state is newer" [S46, P].

**The near-miss palette (cite these pre-emptively; each is adjacent, none is the feature):**

- **GitHub "dismiss stale pull request approvals"** — the cleanest drift-invalidates-approval model: "records the state of the diff at the point when a pull request is approved… if the diff changes from this state… the approving review is dismissed as stale," including when the **merge base** moves. Fingerprint-at-approval, dismiss-on-drift — for human PRs, not agent plans [S47, P].
- **OpenAI Codex cloud maintenance scripts** — a user-supplied freshness hook on resume, environment-level only: container state cached ≤12 h; on reuse "Codex runs the maintenance script… useful when the setup script ran on an older commit" [S48, P].
- **AG-UI protocol interrupts** carry optional `expiresAt` (ISO-8601); "stale resumes produce RunError" — time-based staleness at protocol level, no drift check [S49, P].
- **Copilot's 2026 conflict features** — "@copilot merge in main and resolve conflicts" (2026-03-26) and 3-click "Fix with Copilot" (2026-04-13): user-triggered fresh sessions, not a parked plan re-validating itself [S50, P].
- **Mechanical base-sync** (Renovate/Graphite auto-rebase, auto-rebase Actions): rule-based git-layer sync, no plan semantics [S51, P/S].
- **Approval-side TTLs** (gotoHuman expiry with auto-reject/approve; practitioner TTL guidance): time-based only; **no agent-approval inbox anywhere flags an approval stale because the world changed** [S52, P/S].

**Every ingredient of Sinet's 4.3 exists; the composition does not.** The mechanism this evidence supports (novel, Sinet-built): at park time, record a **freshness fingerprint** — repo HEAD SHA, content hashes/ETags of cited sources, spec/plan version, price-table version. On resume, if age > threshold (spec default 24 h) **or** the fingerprint drifted **or** a sibling task advanced the project (S1.11), run one cheap re-plan validation pass — a local/utility model over `git diff --stat <parked-sha>..HEAD` + the changed-source list + the *remaining* plan steps — emitting continue / adjust-with-note / delta re-approval card (the report 03 delta-card shape; its rubber-stamp risk is already tracked as P-T05-2). Cost bound: one cheap call, satisfying "at low cost… before spending anything significant."

### 2.5 Runaway, loop, and stall detection: what ships, what works, what's snake oil

**Shipped loop detectors (all exact-match, all with false-positive scars):**

- **Gemini CLI `LoopDetectionService`** — the most instrumented: (1) 5 consecutive identical tool calls (SHA-256 of `name:args`); (2) content "chanting" — an identical 50-char chunk recurring ≥10 times; (3) an LLM cycle-check activating after turn 30, every 5–15 turns, firing only at 0.9 confidence with a double-check. Constants verified in source at HEAD. A sustained false-positive complaint stream (sessions failing wholesale; poll/retry workflows tripped; per-tool exceptions refused — a session-scoped disable dialog now exists); the community's repeatedly requested fix is **output-aware comparison** (identical command + different output ≠ loop) [S53, P].
- **OpenHands stuck detector** — default-on; four exact-match classes over the last 20 events: identical action→observation ×4, action→error ×3, agent monologue ×3, alternating ping-pong ×6 (thresholds now configurable). Kills agents that legitimately poll long builds (#5355, #10350) [S54, P].
- **opencode `doom_loop`** — engine-native tripwire, source-verified: `DOOM_LOOP_THRESHOLD = 3` — the same tool call 3× with byte-identical JSON input raises a *permission ask* (default `ask`), i.e. detector + human gate rather than kill; born as a targeted loop-breaker for doom-prone models, later made configurable; documented blind spot: cross-message repetitions missed (#25254) [S55, P].
- **Claude Code: deliberately none.** The feature request modeled on Gemini's service (anthropics/claude-code#4277 — mind the repo, a same-numbered Gemini issue is unrelated) is closed *not-planned*; the vendor's answer is ceilings (`--max-turns`, `--max-budget-usd`) [S56, P].

**Literature and the snake-oil line.** 2026 trajectory work (TIDE; MIRAGE-Bench) confirms loops are a top agent failure mode — agents "repeatedly attempt the same erroneous actions rather than adapting." But **semantic/embedding loop detection ships in zero production tools** (papers only; no measured FP/FN rates) — treat as snake oil for now. The proven-cheap tier is exact-match repetition counting, which demonstrably over-fires on legitimate polling/waiting and misses paraphrased loops; the LLM-judge check has exactly one production deployment (Gemini, heavily thresholded, still complained about). The unshipped-but-everywhere-requested heuristic — **no-progress-on-artifacts** (did any file/commit/checkpoint delta change in N turns?) — is trivially computable by a wrapper that already owns per-call checkpoints [S53, S57, P/S].

**Silence/stall detection.** The canonical liveness pattern is Temporal's activity heartbeat + heartbeat timeout (progress payload survives to the retry) [S58, P]. The vendor SDK stack has a real hole: **no inter-chunk stream timeout exists in the Anthropic or OpenAI SDKs** — total-request timeouts never fire once data has started flowing; anthropic-sdk-typescript #867 documents a stream that "didn't close, didn't error, didn't timeout — it simply stopped sending data" (proposal: 90 s–2 min idle timeout; unimplemented); LiteLLM's `stream_timeout` is first-chunk-only; Claude Code itself has an SSE-stall issue (#54434) and a Python-SDK bug masking mid-stream errors behind status 200 [S59, P]. **The wrapper must own the no-event-for-N watchdog.** Threshold evidence: 90 s–2 min proposals for pure streaming; OpenHands' 2-minute inactivity kill produced false positives on long builds — tool execution needs its own liveness signals (PostToolUse/`session.status` events), not one global timer. Run-state discipline from the mature platforms: **"stalled" is never a stored state — always derived from liveness signals**; and mature taxonomies separate *task failed* / *infrastructure died* (Crashed/Terminated) / *deadline exceeded* — collapsing these is how failures go silent [S60, P].

**Spend anomaly.** The reference enforcement design is LiteLLM's: hard budgets (`max_budget` + `budget_duration`) rejected at request admission per key/user/team, plus *soft budgets* that alert at thresholds; Langfuse/Helicone are observe-and-alert only. War stories are real (TechCrunch: an engineer spending $40k in tokens in one month; Uber blowing its 2026 AI budget by April; ~18.6x per-developer token growth in nine months) — and one is fake: the viral "$47,000 in 11 days" story is an unverifiable SEO cluster marketing an MCP budget product; excluded. The most instructive incident: Gemini CLI #25671 — an infinite loop **burned through quota inside the engine that has loop detection**, riding an MCP-tool pattern the heuristics missed. Detection layers are not a substitute for ceilings [S61, S62, P/S].

### 2.6 Hard ceilings: enforcement points that actually bound damage

| Ceiling | Engine-native (belt) | Platform enforcement (load-bearing) | Latency / damage bound | If the enforcer dies |
|---|---|---|---|---|
| **Time** | none per run in either engine | **systemd transient unit per engine process (`systemd-run` + `RuntimeMaxSec=`)** — enforcement lives in PID 1 | exact; damage = the window | systemd effectively never dies; a wrapper timer dies with the wrapper → always pair both |
| **Turns/steps** | `claude -p --max-turns` — **live-verified enforced** (`terminal_reason:"max_turns"`), but *hidden from `--help`* at v2.1.211 (parses fine; documented in cli-reference; v2.1.205 fixed queued-message loss at the limit); opencode `steps` — graceful: injects "respond with text only, summarize work + remaining tasks"; gh-aw `max-turns` (default 500); LangGraph `recursion_limit` (25; note subagents don't inherit it) | platform counts turns from its own stream-event log; belt flags set on both lanes | one turn — but **a single turn's cost is unbounded**, so turn caps alone never bound spend | flag enforcement survives wrapper death (in-engine); platform count dies with platform |
| **Cost/consumption** | **only** Claude's `--max-budget-usd` — reactive, post-call, against the client-side estimate (same figure as `total_cost_usd`); live-tested this session: `error_max_budget_usd`, `terminal_reason:"budget_exhausted"`, **19x overshoot on a $0.001 cap** ($0.0194 spent; 8.4x on $0.01 in an independent April test); enforced under subscription auth too. opencode: **no cost cap** (FRs #4559 kill-switch, #11138 token budget open) | platform meters every call from stream usage events (D4/D5), aborts at the next boundary when a ceiling crosses | **irreducible granularity = one model call** in every observed design (LiteLLM admission included); on tiny budgets overshoot is proportionally huge | gateway-style admission fails **closed**; wrapper-side metering fails **open** → the time ceiling is the backstop |

Sources: [S63, S64, S10, S65, P — including this session's live probes]. The `terminal_reason` field in the `-p` JSON result is a machine-readable kill-reason signal worth parsing on every run end.

### 2.7 Clean cancellation and maintenance-mode draining

**Cancellation layers, outermost-last:**

1. **Message-boundary interrupt first** (settled P-T01-4, now with cross-engine confirmation): opencode had a whole abort-mid-tool corruption family — dangling `tool_use` without `tool_result` rendering "the whole session unusable" — **fixed April 2026** (#21489, #21326 closed-completed via PR "preserve raw running tool state"; verifier majority over one dissenting status read), with an adjacent instance still open (#27871). Claude's interrupt-mid-tool transcript corruption is report 01 canon. **The idiom stands: interrupt at boundaries; after any abort, run a session-health probe before reuse; fall back to fork-from-checkpoint on the corrupt-transcript error class** [S38, S66, P].
2. **Engine abort verbs**: opencode `POST /session/:id/abort` (cooperative — a force-kill API was requested because it "can fail" for stuck subagents; single-source); Agent SDK `interrupt()`/AbortController (the Bash tool receives the signal directly; drain the message stream after interrupting); Codex `turn/interrupt` (turn ends `status:"interrupted"` with usage; in-flight tool fate undocumented) [S9, S67, P].
3. **MCP cancellation is advisory**: `notifications/cancelled` — receivers "SHOULD stop… MAY ignore"; compliance gaps even in the official python-sdk. **New: the MCP 2026-07-28 release candidate promotes Tasks to an official extension — `tools/call` can return a durable task handle with `tasks/get`/`tasks/cancel`** (a non-advisory cancellation path, and a future parking primitive; final spec July 28, 2026) [S68, P].
4. **Process-tree kill without orphans**: spawn each engine process as its own process-group leader (`detached:true`/setsid — plain `child.kill()` does not reach grandchildren, Node #40438), then TERM → grace → KILL on the **group**. The Claude-side reality check: SIGTERM/SIGINT "orphans all Bash tool child processes (reparented to PID 1)" and SessionEnd hooks don't fire on signal death — closed as duplicate of a closed-not-planned issue, i.e. **unfixed with no open canonical**; a Bash-timeout SIGTERM once killed the whole engine via the shared process group (#45717, closed not-planned). Partial vendor movement: v2.1.132 graceful shutdown on external SIGINT; v2.1.160 background shells get SIGTERM-before-SIGKILL; v2.1.169 a `post-session` hook + configurable SIGTERM→SIGKILL window (default 5 s) [S69, P].
5. **The sandbox is the final cleanup boundary**: bubblewrap `--die-with-parent` (SIGKILL cascade when the parent dies) + `--unshare-pid` (namespace pid1 reaps everything) gives kill-all-on-exit *by construction* — one more reason the S5 ladder pays for itself; the orphan epidemic is real (a cleanup tool found "74 Chrome processes from agent browsers… 56 GB, 18 orphan node processes from dead Claude sessions" on one machine) [S70, P/S].
6. **Workspace effects on cancel**: snapshot-restore where snapshots exist (opencode per-step, Gemini `/restore`) vs leave-and-mark-dirty + startup GC (Vibe Kanban: orphaned-worktree GC on startup; its "ghost run" bug — DB row `running`, worktree gone — proves **DB-vs-filesystem reconciliation at startup is mandatory**). Two hard rules from the issue record: never auto-delete a workspace with uncommitted changes (a worktree auto-cleanup permanently destroyed work, #55724); treat `.git/index.lock` as transient and retry with backoff [S71, P].

**Maintenance mode = the two-signal drain canon**, uniform across Sidekiq (TSTP quiet → TERM with timeout → unfinished jobs **pushed back to the queue**), Temporal workers (STOPPING → DRAINING → DRAINED; running activities get a `WORKER_SHUTDOWN` cancellation after the grace period), and Kubernetes (preStop → SIGTERM → grace → SIGKILL). Agent-platform semantics to copy and to avoid: Trigger.dev pause = "runs keep queuing but stop running" (copy); **Inngest pause silently *drops* events received while paused — pause ≠ queue (avoid)**. Sinet's mapping: admission gate keeps enqueuing → in-flight runs drain to their next checkpoint boundary → past the grace window, boundary-interrupt + checkpoint + park (the Sidekiq push-back, in D7 terms) [S72, P].

### 2.8 The production failure-mode taxonomy (and the defensive idioms)

- **(a) SSE stalls/disconnects.** Streams die silently (§2.5); neither engine offers stream resumption (OpenAI background-mode cursors are the industry fix, single-vendor). **Defensive idiom: the harness's own event log is the resume surface; adapter-level idle watchdog per stream; reconnect + re-read, never re-request blindly** [S59, S73, P].
- **(b) Half-written state.** SQLite WAL/atomic-commit semantics are the reference (fully-visible-or-invisible after crash); atomic file writes = temp + fsync + rename; append-only event logs. Config footgun found in the wild: `cleanupPeriodDays: 0` silently disables *all* transcript persistence rather than disabling cleanup [S74, P].
- **(c) Double resume / duplicate runs.** Canon: a lock+lease alone cannot guarantee mutual exclusion (Kleppmann); the fix is a **fencing token** checked at the resource; Stripe idempotency keys (result replay, 24 h) for outward actions. It happens in real agent platforms: a self-hosted Trigger.dev restart storm created 3,800+ duplicate tasks; LangGraph same-thread concurrent invocation is unsupported-and-broken. **Idiom: single-writer lease per run + fencing token stamped into every checkpoint write + idempotency key `(run_id, step, action)` on every gate-released outward action** [S75, P].
- **(d) Crash between paid call and checkpoint write.** No platform documents exactly-once usage accounting (named-pattern absence verified). Composable answer, flagged as composed: at-least-once accounting + **reconcile-from-engine-transcript on restart, deduplicated by (session-id, message-id)** — both engines persist enough (JSONL / message store) to make the engine the accounting cross-check, which is also exactly harvest item N1's harvest step [S76, P + inference].
- **(e) Laptop suspend/wake — Sinet's signature hazard.** `CLOCK_MONOTONIC` pauses during suspend (the 2018 kernel change was *reverted* because resumed watchdog timers all fired); systemd timers can opt into suspend-aware clocks (`WakeSystem=`); `/usr/lib/systemd/system-sleep/` hooks fire around sleep. Consequences: monotonic deadlines silently stretch across sleep; TCP/SSE connections are dead on wake; **a slept worker is indistinguishable from a crashed one to any lease/heartbeat system — wake is a double-resume factory**. Idiom: a post-resume hook triggers the same reconcile pass as startup (re-verify leases before resuming anything) [S77, P].
- **(f) Zombie/orphan accumulation.** Claude Code purges session files >30 days by mtime, silently (lost-history complaints reached the press); Vibe Kanban ghost runs; the zclean orphan census. **GC must cover three layers — engine session files, harness DB rows, OS processes — reconciled against each other at startup and wake** [S78, P/S].

**Postmortem lessons that bind the design (all primary):** (1) Anthropic Sept-2025 — three overlapping infra bugs (context-window misrouting hit 16% of Sonnet-4 requests at the worst hour); "the evaluations we ran simply didn't capture the degradation users were reporting" → uptime checks don't catch quality faults; the harness needs its own quality signals. (2) Anthropic Apr-2026 (Claude Code itself) — the *harness* degraded the product with weights untouched: default reasoning effort silently lowered (Mar 4–Apr 7), a bug clearing thinking history **every turn** instead of once, a verbosity prompt costing ~3% on evals; "neither our internal usage nor evals initially reproduced the issues" → **for an adopt-don't-fork platform, engine upgrades are release events: pin exact versions, run before/after conformance + quality probes** (extends P-T01-2 / S2.8 with vendor-postmortem proof). (3) Manus — "KV-cache hit rate is the single most important metric for a production-stage AI agent" (~10x cached-vs-uncached cost); append-only deterministic context; keep errors in context → **the harness event log must be append-only, and resume/fork must not rewrite history** — cache economics and agent behavior both depend on it [S79, S80, S81, P].

## 3. Candidate approaches

**A. Sinet-owned control plane: SQLite(WAL) append-only run-event log + explicit run-lifecycle FSM + platform watchdogs, driving both engines through the D3 adapter.** The wrapper persists a record per paid call from stream events (checkpoint = event row + session cursor + artifact-snapshot ref), owns parks/gates/ceilings/watchdogs/reconciliation. Everything in §2 is achievable this way via documented seams; the split-store pattern (git for code, SQLite for workflow) is production-proven in exactly this wrapper class. Cost: Sinet builds the FSM, watchdogs, and reconcile pass itself (bounded, well-evidenced components). This is also the only shape that keeps the checkpoint store authoritative per P-T01-1.

**B. A durable-execution runtime as the harness spine (Temporal / Inngest / Restate / DBOS).** The *concept* is exactly D7 (paid call = journaled step; crash → replay skips completed steps; parks are free), and the checkpoint-at-paid-call granularity is native. But the fit fails on operating reality: Temporal's SQLite mode is dev-only (production posture wants Postgres + services — the heaviest option; plus a 51,200-event history cap forcing continue-as-new); Inngest's `step.ai.infer` offloads to their cloud and pause *drops* events; DBOS is the lightest (library, no server) but requires Postgres; Restate is a genuinely light single binary (RocksDB, ~2 GiB) but is still a second always-on stateful service. Deeper impedance: these runtimes journal *deterministic function steps*, while Sinet's "steps" are interactive subprocess/HTTP streams with human gates — the engine already holds the conversational state, so the runtime would journal references anyway (Temporal's own agent guidance: store history externally, keep "a reference and a cursor"). The runtime buys ~30% of the harness (checkpoint/replay/timers) at 100% of its ops cost, and none of the agent-specific 70% (freshness, loop detection, engine reconciliation, gates UX).

**C. LangGraph as the harness framework.** Mature interrupts/checkpointers and the Agent Inbox UX are real prior art — but it wants to *be* the loop (Sinet's loop lives inside adopted engines), and its production record on exactly Sinet's concerns argues against: node re-execution on resume, same-thread concurrency unsupported, checkpoint schema evolution silently breaking parked threads, unbounded checkpoint growth. Pattern donor, not dependency.

**D. Engine-native state + a thin status DB.** Rejected outright by the verified evidence: 30-day sweeps that delete *parked* defers, in-memory pending asks, CWD-keyed lookups, cache regressions, format-unstable transcripts. Engine state is a resume optimization and an accounting cross-check — never the record.

## 4. Recommendation for Sinet

**Build the harness as approach A — a Sinet-owned control plane over the two pinned engines — with the following specified mechanisms (each traceable to §2 evidence):**

1. **Run-lifecycle FSM (the spec's run state machine):** `queued → running → {waiting-input (parked-on-gate), parked-limit (3.2), draining} → completed | failed | crashed | timed-out | cancelled`, plus **`stalled` as a derived flag, never a stored state** (liveness-computed); *task failed* vs *infrastructure died* vs *deadline exceeded* kept distinct (§2.5). Every terminal transition emits an alertable event into the S2.7 watch and, where human-relevant, a decision card (4.6; escalation liveness per report 04).

2. **Checkpoint = one platform event row per paid model call** (D7 literally): parsed stream message + usage/cost fields (incl. `cache_read`/`cache_creation`) + session cursor (engine session id + message index) + artifact-snapshot reference. Artifact snapshots: opencode's native per-step snapshots on that lane; on the Claude lane a harness-owned snapshot commit per checkpoint (shadow-git idiom — Gemini's trio of *artifact state + dialogue state + pending action* is the reference shape for gate-time checkpoints; storage mechanics finalized in T07). Store: SQLite WAL, append-only, schema-versioned, platform-owned retention (§2.2, §2.8b). Raise `cleanupPeriodDays` well above the park horizon on the Claude lane *and* treat Sinet's store as authoritative (P-T01-1; the defer-evaporation trap).

3. **Gates and parking (4.2/4.3):** proposals are collected at PreToolUse-`defer` (Claude lane) and `permission.asked` → answer endpoint (opencode lane); **every ask is persisted as a durable platform record the moment it is observed** (opencode's are in-memory; Claude's die with retention). Park policy: hold-the-process only below a threshold (default proposal: 10 minutes — covers the notified-glance-decide loop of S3.7); beyond it, exit-park (`defer` → process exits; opencode → abort turn, session idles on disk) and resume on answer (`-p --resume` re-fires the hook with the answer in `updatedInput`; opencode re-prompt on the session id). Known limitation to engineer around: **defer works only on single-tool-call turns** — the G1 spike must measure how often parallel-tool-call turns force fallback (held process or abort+fork) before the gate coverage is trusted (open question 6).

4. **Freshness re-validation (novel — Sinet builds it):** fingerprint at park `{repo HEAD, source content hashes/ETags, spec+plan version, price-table version}`; re-validate when age > 24 h (spec default) OR fingerprint drift OR sibling-accept (S1.11); the pass is one cheap local/utility-model call over `git diff --stat` + changed sources + remaining plan steps → **continue / adjust-with-note / delta re-approval card** (report 03's delta shape). Prior art: GitHub's fingerprint-and-dismiss + Codex's resume-hook slot + AG-UI's `expiresAt`, composed (§2.4).

5. **Runaway detection, layered and containment-first (3.7/4.6):** (i) deterministic exact-match repetition counters in the adapter stream (tool-call hash, n≈3–5, aligned with doom_loop) made **output-aware** (identical call + different output ≠ loop) with waiting-state exemptions — the two documented FP causes; (ii) **no-progress-on-artifacts**: no checkpoint delta in N turns → flag (the field's requested-everywhere heuristic, free with mechanism 2); (iii) a local-model semantic cycle check as *advisory only* (the free tier per Operating reality; Gemini's FP record forbids auto-kill on LLM verdicts). Containment = pause-and-flag to the inbox, not silent kill; leave `doom_loop: ask` enabled on the opencode lane as a belt. Ceilings stay the backstop (the Gemini quota-burn-through-a-loop-detector incident).

6. **Ceilings (3.7), platform-enforced with engine belts:** wall-clock via a **systemd transient unit per engine process** (`RuntimeMaxSec` — PID-1 enforcement that survives harness death) plus platform timers armed on suspend-aware clocks; turns counted from the platform event log (belts: `--max-turns` — functional though hidden from help; `steps` on opencode); consumption/cost metered per call against the D5 price table with abort at the next message boundary (belt: `--max-budget-usd` on the Claude lane). Document the honest bound: **cost-ceiling granularity is one model call; overshoot ≈ the largest single call** (19x on a $0.001 cap live; 8.4x on $0.01). Ceiling hits produce decision cards, never silent death.

7. **Stall detection (4.6):** per-run liveness derived from stream-event recency with per-phase thresholds — streaming phase ~90 s–2 min idle watchdog **owned by the adapter** (no vendor SDK watches inter-chunk gaps); tool-execution phase keyed to tool lifecycle events (PostToolUse / `session.status`), since one global timer is the proven FP source; parked runs exempt. Consume `StopFailure` categories and `session.error` as first-class failure signals.

8. **Cancellation (4.5):** ladder = boundary interrupt → engine abort verb → process-group TERM → grace (≥5 s) → KILL, with each engine process spawned as its own process-group leader; **post-abort session-health probe** before any reuse, fork-from-checkpoint as the standard recovery (abort-corruption class: principal opencode bugs fixed 2026-04, adjacent instance open; Claude mid-tool corruption is canon); `asyncio.shield` (or equivalent) around checkpoint flushes; sandbox PID-namespace (`--die-with-parent`, `--unshare-pid`) as the final cleanup boundary — S5 pays for itself here; never auto-delete a workspace with uncommitted changes; retry `index.lock` errors with backoff.

9. **Startup/wake reconcile pass (3.8) — N1 generalized:** on every platform start *and* every resume-from-suspend (system-sleep hook), before resuming anything: re-verify run leases; sweep OS processes vs DB rows vs engine session files vs worktrees (four-layer GC); classify each orphaned run *active / finished / dead* (wait / harvest result / supersede); **reconcile usage records from engine transcripts at-least-once, deduped by (session-id, message-id)** — closing the paid-call-vs-checkpoint crash gap. A slept laptop is a crashed worker: wake is treated identically to restart.

10. **Concurrency safety:** single-writer lease per run with a **fencing token stamped into every checkpoint write**; idempotency key `(run_id, step, action)` on every gate-released outward action (Stripe canon); append-only event history (also the Manus cache-alignment rule — resume/fork must never rewrite history).

11. **Maintenance mode (4.5):** admission gate that **keeps queueing** (Trigger.dev semantics; explicitly not Inngest's event-dropping pause) → in-flight runs drain to their next checkpoint boundary → past the grace window, boundary-interrupt + checkpoint + park (Sidekiq's push-back, in D7 terms). Same FSM, no special cases.

12. **Engine-drift defense (P-T01-2 extended):** pinned versions; upgrades are release events with before/after conformance *and quality* probes (the Apr-2026 postmortem class is invisible to uptime checks); a standing **cache-fidelity alarm** — `cache_read` stuck flat across resume turns fires a warning (the #34629 class regressed twice).

**Why this and not B/C/D:** it is the only shape that satisfies D7 at paid-call granularity on both lanes without engine surgery, keeps the authoritative record out of engine stores that demonstrably expire/corrupt/regress, adds zero always-on services beyond the platform itself (one maintainer, one laptop), and turns the two documented novel gaps (freshness pass, no-progress heuristic) into small components on top of data the harness already collects.

**What would change the decision:**

- **MCP Tasks extension maturing** (final spec 2026-07-28: durable task handles, `tasks/get`/`tasks/cancel`): if both engines adopt it, parking/cancel could converge on protocol handles — track in S2.8, revisit at T07/G2.
- **ACP shipping checkpoint/fork verbs + stable per-turn usage** (report 01's watching brief): would shrink adapter glue, not change the harness layer.
- **Any vendor shipping plan-level freshness re-validation**: adopt theirs, keep the fingerprint trigger.
- **`defer` regressing or being removed** (it is one changelog entry old): fallback is held-process parking below threshold + abort-park (fork-from-checkpoint) above it — same FSM, worse economics; the G1 spike pre-tests this fallback.
- **Sinet adopting Postgres for other reasons (T07)**: re-evaluate DBOS as the checkpoint spine (its library-only model is otherwise the best durable-execution fit); Restate is the named fallback if the platform ever outgrows embedded storage.

## 5. What NOT to use and why

- **Temporal as the harness spine** — production posture (Postgres/Cassandra + services) is disproportionate for one laptop; SQLite mode is dev-only; event-history caps force continue-as-new; determinism constraints mismatch interactive subprocess streams. Its *patterns* (heartbeats, drain states, timers) are harvested throughout §2.
- **Inngest** — `step.ai.infer` offloads to their cloud; pause **drops** events (documented trap); wrong dependency shape for self-hosted-first.
- **DBOS now** — requires Postgres that Sinet doesn't otherwise run (revisit per T07); **Restate** — closest lightweight fit, but still a second always-on stateful service whose journal duplicates what the engines+event-log already hold; named fallback, not choice.
- **LangGraph as the harness** — wants to own the loop; node re-execution on resume, unsupported same-thread concurrency, checkpoint-schema fragility, unbounded checkpoint growth. Donor of the interrupt/inbox patterns only.
- **Held-process parking as the default** (Happy/Omnara shape) — hours-scale holds on a sleeping laptop guarantee orphaned parks; use only below the hold threshold.
- **Semantic/embedding loop detectors as blocking mechanisms** — shipped nowhere, no measured error rates (mid-2026): snake oil until proven. **LLM-verdict auto-kill** — the only production deployment still generates false positives at 0.9 confidence; advisory only.
- **Engine-native undo/snapshot as the authoritative rollback** — opencode's undo/redo family shipped data-loss and git-corruption bugs; Claude checkpoints ignore bash-driven changes. Use as convenience, verify against the platform's own snapshot refs.
- **Engine ceilings as the primary enforcement** — `--max-budget-usd` is reactive with proportionally huge overshoot on small caps; `steps` doesn't stop spend inside a turn; belts only.
- **MCP `notifications/cancelled` as a kill path** — advisory by spec, spotty compliance; kill at the process/sandbox layer.
- **External approval SaaS** (HumanLayer classic — deprecated by its own README, per report 04; gotoHuman-class) — Sinet's inbox is local infrastructure; patterns (expiry policies, webhook resume) already extracted.
- **Trusting engine transcript retention** — 30-day mtime-keyed silent purge, `-p` sessions unindexed (report 01), `cleanupPeriodDays: 0` disabling persistence outright.
- **PID-file/lock-only single-writer schemes** — leases without fencing tokens are the documented double-resume recipe on a machine that sleeps.
