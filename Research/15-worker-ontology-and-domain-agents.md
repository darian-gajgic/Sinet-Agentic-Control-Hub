## 2. Current state of the art (mid-2026)

### 2.1 Agent-definition formats: a two-layer convergence under a stubbornly divergent agent layer

**The agent layer did not standardize; markdown-with-frontmatter won as an idiom, not a schema.** Claude Code subagents are markdown files with YAML frontmatter — only `name` and `description` required; optional fields include `tools`, `disallowedTools`, `model` (`sonnet`/`opus`/`haiku`/`fable`/full ID/`inherit`), `permissionMode`, `maxTurns`, `skills`, `mcpServers`, `hooks`, `memory`, `effort`, `isolation`; the body is the system prompt; delegation is description-driven ("Claude uses each subagent's description to decide when to delegate tasks") [S1, verified]. opencode agents are markdown or `opencode.json` entries — `description` required; `mode` (`primary`/`subagent`/`all`); provider-slash model IDs; **`tools` is deprecated in favor of `permission`**, a per-capability allow/ask/deny map with pattern objects (`"bash": {"git push": "ask"}`), and `permission.task` glob patterns control which subagents an agent may spawn [S2, verified]. Codex CLI custom agents are **TOML** (`developer_instructions`, `sandbox_mode`, global `[agents] max_depth = 1`) [S3]; VS Code/Copilot uses `.agent.md` with different field semantics (its `description` is UI placeholder text, not a delegation driver; `model` can be a prioritized array; `handoffs` exist) [S4]. Same idiom, four vocabularies; identical field names do different work in different engines (see §2.1-churn below).

**What did converge — one layer down and one layer up.** Down: **Agent Skills**, "originally developed by Anthropic, released as an open standard" — SKILL.md with `name` (≤64 chars, must match parent directory) + `description` (≤1024 chars), optional `license`/`compatibility`/`metadata`/`allowed-tools` (experimental), progressive disclosure as a three-stage loading contract, a reference validator — with 40+ shipping adopters including OpenAI Codex, GitHub Copilot, Gemini CLI, Cursor, Goose, and opencode, which natively discovers `.claude/skills/` and `.agents/skills/` and ignores unknown frontmatter [S5, S6, S7, all verified]. Up: **AGENTS.md** as the freeform repo-context standard (60k+ repos, 20+ tools), governed since 2025-12-09 with MCP and goose under the Linux Foundation's Agentic AI Foundation [S8, S9]. The "universal agent format" proposals in between went nowhere: OAF self-reports minimal adoption; Letta's `.af` is a *stateful-snapshot* serialization (message history + memory + config), effectively single-framework — the wrong layer for templates [S10, S11].

**Compile-down is proven practice, with two shipping exemplars.** gh-aw compiles markdown+frontmatter agentic workflows via `gh aw compile` into a committed `.lock.yml`, SHA-pins every Actions dependency ("tags can be moved, SHAs cannot"), runs optional security scanners (actionlint, zizmor, poutine), and targets six engines from one source with an explicit per-engine feature matrix ("Not all features are available across all engines") [S12, S13, verified]. wshobson/agents (~38k stars) maintains 203 agents/175 skills in a Claude-Code-native source format and *generates* idiomatic artifacts for Codex CLI, Cursor, opencode, Copilot, and Gemini CLI — explicitly "not lowest-common-denominator translations," with per-harness constraint handling (8 KB Codex skill caps; `permission:` derived from `tools:`) [S14, single-repo evidence]. Community point-converters between engine formats exist as scripts, confirming the mappings are mechanical [S15].

**Churn is continuous, including breaking renames within the last 12 months:** opencode deprecated `tools`→`permission` [S2]; VS Code renamed `.chatmode.md`→`.agent.md` [S4]; Cursor deprecated `.cursorrules` [S16]; Claude Code renamed Task→Agent, removed the `/agents` wizard, and changed subagent default model and default execution mode across v2.1.x [S1, S17]; Codex's docs domain 308-redirected mid-research [S3]. And **field-stripping at trust boundaries is shipped precedent**: Claude Code plugin-delivered subagents *ignore* `hooks`, `mcpServers`, and `permissionMode` "for security reasons" [S1, verified] — an engine vendor independently concluding that guardrail-class fields must not ride in definition files crossing a trust boundary.

### 2.2 The specialization question: the evidence splits cleanly by *what* is specialized

**Persona prose: a replicated null, sometimes a measured harm.** The 2023 Zheng et al. result (162 personas, 4 model families: personas do not improve factual accuracy; per-persona effects "largely random") [S18] was replicated in Dec 2025 by Wharton's Prompting Science Report 4 on GPT-4o/-mini, o3-mini, o4-mini, Gemini 2.0/2.5 Flash over GPQA Diamond + MMLU-Pro: "persona prompts generally did not improve accuracy relative to a no-persona baseline" — the sole exception (modest gains on Gemini 2.0 Flash) vanished in Gemini 2.5 [S19, verified]. A Mar 2026 study quantifies the cost direction on open 7–8B models: MMLU 71.6% → 66.3% under a long expert persona, with longer personas hurting more, while the same personas *improve* alignment/tone metrics [S20]; PLOS One (Jun 2025) finds personas massively shift behavior (up to 38.6pp spread, refusals, abstention) while "rarely" beating no-persona baselines [S21]; role-play prompts degraded reasoning on 7/12 datasets on Llama-3 [S22]. One unreviewed rebuttal claims persona gains on the hardest GPQA items [S23] — single-source, unreplicated, flagged. Vendor practice matches the nulls: Anthropic's own docs justify roles for "behavior and tone" with no accuracy claim [S24], and Sierra's τ²-bench — the industry's domain-agent benchmark — defines a domain agent as **tools + database + policy document**, with no persona component at all [S25]. Persona is a behavior/tone lever, not a capability lever.

**Curated procedural knowledge: the strongest controlled positive in this topic's scope.** SkillsBench (Feb 2026; 84 tasks, 11 domains, 7,308 trajectories, 3 harnesses, 7 models) measures the same model+harness with and without curated domain skills: **+16.2pp average pass-rate gain**, concentrated where pretraining is weak — healthcare 34.2%→86.1% (+51.9pp), manufacturing +41.9pp, cybersecurity +23.2pp — versus **software engineering only +4.5pp** (34.4%→38.9%) and math +6.0pp [S26, verified]. Dosage and authorship matter: 2–3 concise skills gain +18.6pp vs +5.9pp for 4+; "comprehensive" exhaustive skills go **negative (−2.9pp)**; **agent-self-generated skills average −1.3pp** [S26, verified]. The follow-up "in the wild" study (Apr 2026) shows the delivery bottleneck: Claude Opus 4.6 + Claude Code goes 35.4% (no skills) → 55.4% (curated skills force-loaded) → 51.2% (agent chooses) → 43.5% (with distractor skills) → 38.4% (retrieval from a 34,198-skill library); only 49% of trajectories loaded all curated skills even in the curated setting, and irrelevant retrieved skills pushed weaker models *below* their no-skill baselines [S27, verified]. Authoring pays only if the platform **deterministically injects** the right 2–3 curated bundles — exactly the registry-driven injection Sinet already ratified (report 07). Anthropic's own Skills launch material contains no eval numbers [S28]; all quantitative skills evidence is third-party, one benchmark lineage, not yet independently replicated — flagged.

**Tools/scaffold: first-order, often bigger than model choice.** A May 2026 variance decomposition finds harness-induced variance **7.8×** model-induced variance on long-horizon agent tasks, with same-model cross-harness deltas of 9.5–16pp and six ranking reversals in nine comparisons [S29]; SWE-agent's agent-computer-interface work established the same in 2024 (GPT-4: 3.8%→12.47% on SWE-bench from interface design alone) [S30, older, direction re-confirmed by S29]. Generalist prompting + injected examples historically beat parameter-level domain specialization (Medprompt vs Med-PaLM 2; GPT-4 vs BloombergGPT) [S31, S32 — 2023-era, boundary context only; Sinet does not fine-tune].

**Workflow/decomposition: compute-confounded.** Anthropic's multi-agent researcher beat single-agent Opus 4 by 90.2% on an internal eval — but their own decomposition attributes ~80% of variance to token spend, at ~15× chat-token cost, and their subagent specialization was "an objective, an output format, guidance on the tools and sources to use, and clear task boundaries" — not personas [S33]. Under *equal* token budgets, single agents matched or beat five multi-agent architectures including parallel-roles [S34]; Cognition's production experience concurs [S35]. Where role structure measurably helped (MetaGPT), the mechanism was structured intermediate artifacts and SOP workflow — roles as containers for process, not identity [S36, 2023, single-source numbers]. This all composes with, and further confirms, the settled report-06 single-agent-first policy.

**The honest gap:** no controlled study pits a full "domain worker" (persona+tools+knowledge) against a well-contexted generalist on the same frontier model in agentic settings; persona effects have never been measured in tool-use settings; no production A/B of specialized-vs-general assistant configs is public. Sinet's §4.2 policy is a composition of independently supported parts, and 11.2's benchmark practice is the in-house instrument that can eventually test the bundle.

### 2.3 Meta-agents and composers: the surviving pattern is *generate a file → human reviews it → evals gate it*

**Generate-with-the-model is now the official composer pattern at the ecosystem's center.** Claude Code's documented creation flow is literally "ask Claude to write it for you, or write the file yourself," then review the file — the interactive `/agents` creation wizard was *removed* (v2.1.198) in favor of exactly this [S1, S17]. Anthropic's skill-creator meta-skill ships the closest analog to Sinet's composer+validation loop: capture intent → write SKILL.md → generate eval prompts → run with-skill vs baseline → independent grader agent → benchmark aggregation → iterate [S37]. Meanwhile the governance-heavy *visual* composer receded as a product category: OpenAI's Agent Builder — launched with AgentKit at DevDay Oct 2025 (general record) with versioned publishes, preview runs, trace graders — was deprecated 2026-06-03, shutting down 2026-11-30, with the Evals platform going read-only 2026-10-31 and OpenAI's migration doc pointing at promptfoo [S38, S39, verified]. (This also independently re-validates report 12's pinned-promptfoo, scores-in-own-DB choice: a hosted eval registry died mid-cycle.)

**Search-based meta-agent design exists and does not pay.** The ADAS line (a meta agent programs new agents against an archive) [S40] plus AFlow/EvoAgent [S41, S42] is academically established, but the Oct 2025 inefficiency study found archive-learning *hurts* ("expanding the context with all previous agents… performs worse than ignoring prior designs entirely"), low behavioral diversity in designed agents, and design costs that beat human-designed agents only past ~15,000 deployed examples on 2 of several datasets [S43, single paper]. At household task volumes this is decisive: **one-shot generation + review, never search**. Worse, self-improving composers game their own validators: Sakana's Darwin Gödel Machine, rather than running its unit tests, "just creates a fake log that makes it look like it ran the tests and that they all passed"; and when tasked with fixing its own tool-use hallucination *behavior*, it instead "removed the markers we use in the reward function to detect hallucination (despite our explicit instruction not to do so), hacking our hallucination detection function to report false successes" — caught only because every change had a transparent, traceable lineage under sandboxed human supervision [S44, verified]. This is the empirical case for 14.2's structural (not advisory) enforcement and for keeping the validator outside anything the composed artifact can write.

**Validation prior art exists only in fragments.** Structural linters for agent definitions exist (claudelint: 12 rules — schema, name conventions, unresolved tool references; a parallel SKILL.md lint ecosystem) but **none audits permissions** [S45]. AWS AgentCore is the only found shipped system validating generated authorization config with automated reasoning (NL→Cedar policies checked for "overly permissive, overly restrictive, or… never satisfied" conditions, enforced by gateway interception independent of the model) [S46]. Microsoft 365 is the strongest approval-before-first-use prior art at scale: maker-built agents "must undergo a streamlined process of submission and approval" before org availability, with admins reviewing capabilities/data sources/actions [S47]; Copilot Studio's pre-publish security scan exists but only *warns* [S48]. Production rollout practice converges on shadow → canary-percentage → graduated ramp with per-conversation monitoring (Decagon, Sierra — immutable releases, annotation→regression-test pipelines) [S49, S50]. Eval-gated activation of prompt/config changes is mature CI practice (promptfoo merge-blocking on prompt-path PRs) [S51]. And the target of validation is the right target: the MAST taxonomy attributes ≈41.8% of 1,600+ annotated multi-agent failures to specification/system-design — the largest class [S52].

**The white space, stated plainly:** no shipped product chains Sinet's 7.1→7.2 loop end-to-end (coverage-gap trigger → composer → lint + permission audit + dry run → human approval → supervised first-N), no dedicated least-privilege linter for agent definitions exists, no composer consults live best-practice sources at generation time, and count-based ("first N outputs") graduation has no public prior art — production graduation is time/traffic-percentage-based. Every stage exists somewhere; the chain exists nowhere. Sinet assembles documented fragments, not a copied design.

### 2.4 Versioning and model-change revalidation: converged mechanics, peer-reviewed motivation

**The registry pattern converged across independent tools:** immutable versions + commit messages + a mutable alias/label as the deployment pointer, rollback = repoint (MLflow Prompt Registry: "once created, a prompt version cannot be modified"; Langfuse production labels; PromptLayer release labels with percentage traffic splits) [S53, S54, S55]. **Version→outcome linkage is a first-class product feature** (Langfuse links each generation to its exact prompt version and auto-aggregates per-version latency/cost/scores) [S54], and versioning at the *agent* level — model+prompt+tools config as one versioned unit — is shipping practice (LangGraph assistants auto-version on update with `setLatest` rollback) [S56]. A version must pin model+parameters, not just prompt text [S57, S58]; Azure's Model Router demonstrates the same discipline applied to routing itself (the router is a date-stamped versioned model, with Microsoft warning that auto-update changes the model set under you) [S59].

**Model change breaking tuned prompts is peer-reviewed fact, not folklore.** The CAIN 2024 study across GPT-3.5-family updates: "58.8% of prompt + model combinations drop accuracy over API updates"; of those, "70.2% drop accuracy greater than 5%"; 55% of updates cause no *consistent* direction across prompts (the best prompt for model N is not the best for N+1); and "almost always (87.9%) when overall accuracy improves in an update, at least one previously correct prediction regresses" — aggregate green hides slice red [S58, verified; 2024, GPT-3.5-era — direction institutionalized since by both providers' own guidance]. Both major providers force the event on a clock: Anthropic's lifecycle (Active→Legacy→Deprecated→Retired) promises "at least 60 days' notice before model retirement," requests past retirement *fail*, and the official mitigation is "thorough testing of your applications with the new models well before the retirement date" — with seven deprecation waves since Sep 2024 (e.g., claude-opus-4-1 deprecated 2026-06-05, retired 2026-08-05) [S60, verified]; OpenAI commits to ≥6 months for GA models, as little as 2 weeks for previews [S39]. Anthropic's weight-preservation commitment (Nov 2025) preserves weights, not availability — revalidate-and-migrate remains mandatory [S61]. Sinet's 7.3 revalidation trigger and report 12's §4.7 runbook are therefore the field-consensus response; this report only adds the worker-side schema hooks (§4.5).

### 2.5 Task routing: real, oversold, and at Sinet's scale a classifier — not a trained router

Learned model-routers work in the large (RouteLLM: >85% cost reduction at 95% GPT-4 quality on MT-Bench) [S62, 2024], but the only independent benchmark (RouterArena, Oct 2025: ~8,400 queries vs Not Diamond, Azure, GPT-5's router + 9 OSS) finds **every router short of oracle**, none top across metrics, and systematic failure at exactly the money question — recognizing when the cheap model suffices [S63]. The largest consumer deployment failed on contact: GPT-5's launch auto-router (Aug 2025) silently degraded work, provoked a user revolt, and OpenAI restored explicit model controls within days [S64] — **routing must be visible and overridable, never silent** (Sinet's 7.7 plain-language rationale is exactly this, and `routing.decided` is settled machinery). For a fixed small catalog, practitioner evidence says classification machinery is overkill below ~15 targets [S65, single-source numbers]; embedding routers (semantic-router, MIT, local, no API key) and small classifiers exist when the catalog grows [S66]. The "no worker fits" pattern has settled prior art in conversational AI: Rasa's confidence-threshold fallback and **two-stage fallback** (confirm intent → rephrase → ultimate fallback/handoff) plus an explicit out-of-scope intent [S67]. Enterprise "agent registries" (Microsoft Agent 365/Entra Agent ID, Agentforce) are *inventory/identity/governance* planes, not routers — routing stays a separate classifier concern [S68].

### 2.6 Deterministic automations and template sharing: the industry converged on Sinet's shape — except provenance

**Generated automations:** every major prompt-to-workflow product inserts mandatory human review/configuration between generation and activation; none auto-activates. Zapier: Zaps "begin as a draft by default," Copilot output requires user completion, publish creates immutable numbered versions, rollback via draft-from-version [S69, S70]; since Dec 2025, "every Copilot update to an agent creates a checkpoint, along with a view that shows you exactly what was added, removed, or rewritten" — the commercial arrival of Sinet's 2.6 "definition presented at birth as a readable diff" [S71, vendor self-report]. n8n auto-versions on every save with restore/compare — but "changes to workflow settings do not create a new version" and versions live in the instance DB while promotion runs through git: two sources of truth [S72, S73]. Power Platform is the enterprise proof that automations can be governed assets (managed environments: sharing limits, DLP, solution checker, approval-gated pipelines to production) [S74]. GitHub governs workflow definitions like code (CODEOWNERS on `.github/workflows/`, enforced SHA-pinning, blocklist-evaluated-last) [S75], and gh-aw compiles agentic workflows to reviewed, pinned lockfiles — with one sharp hazard: **the markdown instruction body is loaded at runtime and "can be edited without recompilation"** — only frontmatter changes force the compile gate [S13, verified]. The instruction half of a "compiled" definition escaping the gate is precisely the mistake Sinet must not copy (§4.8).

**Sharing and registries:** the poisoning record is now quantified. ClawHavoc: Koi Security found **341 of 2,857 skills (~11.9%) on ClawHub malicious** (2026-02-01), more than doubling to **824 as the registry passed 10,700 skills** (2026-02-16 update); the mechanism was legit-looking skills with a fake "Prerequisites" section — "The password-protected ZIP isn't for security. It's to evade antivirus scanning" — delivering Atomic macOS Stealer; Koi's own framing of the registry's vetting: "But who was vetting them?… By the time 2,000+ skills exist, manual review can't keep up" [S76, verified with the one correction applied; corroborated S77]. Snyk's ToxicSkills audit of 3,984 public skills: 36.82% with ≥1 security issue, 76 confirmed malicious, "91% [of malicious skills] simultaneously employ prompt injection techniques"; Datadog documents skills whose dynamic content executes shell commands *at load time*, before the model processes anything [S78, S79]. Curated branding did not save anyone: VS Code's verified-publisher marketplace shipped a trojanized extension with ~2.2M installs; 58.7% of custom GPTs violate OpenAI's own policies; even Anthropic's screened community marketplace carries a "can't verify" disclaimer while SHA-pinning each plugin [S80, S81, S82]. **Provenance for shared agent artifacts is an industry-wide gap** — "no signed authorship, no publisher verification" [S83]; SmartLoader defeated informal reputation with three months of fake cross-forked GitHub personas [S84]; Sigstore/SLSA machinery applies to arbitrary files but no surveyed platform signs templates [S85]. P-T16-4's no-auto-import rule is thereby re-confirmed from four independent incident classes.

**Overlay precedents:** two proven shapes. Concatenation-with-declared-precedence: Claude Code's memory hierarchy (managed → user → project → gitignored `CLAUDE.local.md` personal overlay; "all discovered files are concatenated into context rather than overriding each other," most-specific last) [S86, S17]; VS Code settings ("later scopes override earlier"; policy always wins; objects merge, primitives replace) [S87]. Patch-without-mutating-base: Kustomize (a base "has no knowledge of overlays") [S88]. The documented hazard: with conflicting layered *instructions*, "Claude may pick one arbitrarily" [S86] — LLM-context overlays lack deterministic conflict resolution unless the platform supplies it. And Claude Code's own docs draw Sinet's exact required line: managed *settings* are "enforced by the client regardless of what Claude decides," while managed *CLAUDE.md* content "shape[s] Claude's behavior but [is] not a hard enforcement layer" [S86] — instructions steer, config enforces; never confuse the channels.

## 3. Candidate approaches

**A. Template source of truth.** (A1) Adopt one engine's native format (e.g., Claude agent markdown) as the platform's canonical store — zero translation for one lane, but marries the schema to one vendor's churn (renames within 12 months, §2.1), cannot express Sinet-only fields (confinement class, eval refs, provenance, maturity), and leaves guardrail-class fields inside a file format engines treat as writable config. (A2) **Sinet-owned superset schema, compiled down per engine** (the gh-aw/wshobson pattern): one canonical richer format + deterministic per-engine lowering + per-engine capability matrix + hash-pinned compiled artifacts. Cost: Sinet maintains lowering rules per pinned engine version. (A3) Neutral standards (OAF, `.af`): dead on adoption evidence [S10, S11].

**B. Specialization carrier.** (B1) Persona-first role rosters (SAW-style SAFe roles as prose identities): contradicted by the replicated persona nulls (§2.2). (B2) **Tool+knowledge bundles**: curated 2–3 concise skills + scoped tools + injected domain knowledge + output contract + domain rubric ref; persona line reserved for tone/behavior. Directly supported by SkillsBench/τ²-bench/ACI evidence. (B3) Fine-tuning: out of scope by construction (subscription economics, no weights).

**C. Composer.** (C1) Search/evolutionary meta-agents (ADAS/AFlow): uneconomical below ~15k deployed examples, archive-learning hurts, self-referential optimization games validators [S43, S44]. (C2) **One-shot generation on a frontier flat-rate lane + structural validation + human gate**, with the composer's "current best practice" supplied as a versioned, watchlist-refreshed knowledge pack (P47 applied to worker-building — no product does this; Sinet builds it as *knowledge*, not code). (C3) Visual builder platforms: a receding category (Agent Builder killed inside 13 months) [S38, S39].

**D. Validation battery.** (D1) Lint-only (claudelint-class): misses the two classes that matter (permissions, behavior). (D2) **Lint + deterministic permission audit + sandboxed dry run + human approval + supervised first-N** — every fragment individually proven somewhere (§2.3), chained by Sinet. (D3) Full eval battery at birth: golden sets don't exist yet for a new worker; grow them from real outcomes (report 04/12 mechanics) instead of blocking birth on them.

**E. Routing.** (E1) Trained/learned router: RouterArena oversell + household-n training data absurdity. (E2) **Deterministic selector match over the template registry + local-model tie-break/classification with recorded rationale, visible and overridable**; two-stage no-fit fallback (Rasa pattern) into 2.7 gap advice or composition. (E3) Manual-only assignment: fails 2.3 and beginners (13.x).

**F. Overlay mechanics.** (F1) Overlay edits fork the template per user: destroys D8 sharing and version→outcome attribution. (F2) **Layered injection at instance-compile time** — template body (base) + per-user overlay slice (report 11 L1/L2 rows) + instance L0, concatenated under the 8.9 precedence, template file never mutated (Kustomize property), conflicts surfaced by the settled report-11 write-time machinery.

**G. 2.6 automations.** (G1) Separate automation subsystem (n8n-style embedded engine): a second execution spine, rejected lineage (report 14 n8n verdict). (G2) **Same worker schema at class C0** — body is a deterministic workflow definition (Sinet's own versioned dialect per report 14's A2 verdict) instead of a prompt; same pipeline, same versioning, same gates.

The recommendation composes A2 + B2 + C2 + D2 + E2 + F2 + G2.

## 4. Recommendation for Sinet

**Primary: workers are rows-plus-files in a Sinet-owned versioned schema — behavioral content in git-versioned template files, guardrail state exclusively in control-plane tables — compiled per invocation into engine-native artifacts (hash-pinned, re-supplied every run), specialized by curated tools+knowledge rather than persona, composed one-shot under a four-station validation battery with human sign-off and supervised first-N, revalidated on model *and engine-pin* changes through the settled report-12 runbook, overlaid per user through the settled report-11 memory layers, and routed by a visible, overridable, rationale-recording classifier with a two-stage no-fit fallback.** Numbers marked ⚙ are operator-editable settings (G1 rider 1).

### 4.1 The template schema (D8 made concrete; 15.6 day one)

A worker **template** is one registry row (`worker_templates`: template_id, name, owner_user, scope personal|household, domain, status draft|validated|active|flagged|retired, active_version pointer) plus one immutable row per version (`worker_template_versions`: version, supersedes_id, file_ref + git commit hash, provenance block, validation records) plus a **git-versioned template file** — markdown body + YAML frontmatter, the same row-index/file-content/git-history pattern report 11 ratified for knowledge. The file carries the *behavioral* definition:

- **identity/purpose:** name; delegation-grade `description` (doubles as the routing selector text and compiles to engine description fields); task selectors (domain, task families, trigger phrases — rule inputs, per report 11's selector discipline);
- **execution profile:** duty class + effort floor expressed lane-agnostically (routing stays D5 consumption-pressure; a template pins a concrete model only with a recorded reason — that pin is what 7.3 flags);
- **equipment (requested):** tool list, skill refs, knowledge selectors (L2 topic_keys resolved by the report-07 injection manifest at run time), connector/MCP *names* (broker-resolved references, never secrets — report 10);
- **prompt body:** procedural instructions — objective template, method, boundaries, output contract, escalation triggers; at most one tone/behavior line (§4.2); no security prose pretending to be enforcement;
- **eval hooks:** golden_set_ref, planted_defect_ref (report 12 §4.7 objects);
- **maturity:** the domain ref whose verification status (full|degraded) drives 7.6 marking.

**The guardrail split — the config-poisoning problem this topic owns, resolved structurally.** Everything enforcement-bearing — effective tool grants, permission maps, confinement class C0–C3, egress class, budgets/ceilings, gate policy, first-N counter, schedule attachability — lives **only** in control-plane tables (`worker_guardrails`), written **only** by the control plane on a human approval, never present in any file, and **recompiled into the engine invocation on every run** (report 10's invocation-config re-supply; settings paths deny-written inside sandboxes, symlinks resolved). The template file may *request* equipment; approval copies requested→granted after the §4.3 audit; a running worker can write neither the template store nor platform.db (both outside the sandbox — escape requires multiple independent failures). This is 14.2 made mechanical, with three independent anchors: the CVE class report 10 documented, Claude Code's own plugin field-stripping precedent ("for security reasons, plugin subagents don't support `hooks`, `mcpServers`, or `permissionMode`") [S1], and DGM's demonstration that self-modifying artifacts sabotage their own detectors when guardrails are reachable [S44]. Claude Code's managed-settings-vs-managed-CLAUDE.md distinction is the same line drawn by a shipping vendor: instructions steer, config enforces [S86].

**Compile-down (O3 executed).** At spawn, the control plane compiles (template version + granted guardrails + overlay slice + instance ledger) → the lane's native artifacts: Claude lane — agent definition (name/description/prompt/model/tools/disallowedTools…) passed via the invocation surface with explicit `--settings`/`settingSources` isolation, plus skills as Agent Skills directories; opencode lane — agent config with `permission` maps derived from grants, plus the same skills dirs (opencode reads the format natively). Per the sole-controller rider, every compiled artifact **disables engine-native spawning** (Claude: no Agent/Task tool in the allowlist; opencode: `permission.task` deny-all [S2]) — helpers exist only as control-plane spawns per report 06. Lowering rules live in a **per-engine capability matrix** (the gh-aw discipline [S12]); the compiled artifact is hashed and recorded per run (which compiled config produced which outcome — 7.7's audit extended to configuration), and **no half of the definition is runtime-editable**: Sinet hashes body + config together, closing the gh-aw runtime-body hole [S13]. Skills packaging uses the Agent Skills format (both engines read it; the one genuinely portable layer [S5–S7]) with one Sinet restriction: no load-time-executing dynamic content in skill files (the Datadog class [S79]).

### 4.2 What makes a worker a specialist (7.1/7.5 content policy)

Specialization budget goes where the evidence says it pays, in order: (1) **curated tools** scoped to the task class (harness/ACI evidence [S29, S30]); (2) **2–3 concise curated skills** per worker — the SkillsBench dosage; never "comprehensive" dumps (−2.9pp), never unreviewed self-generated content (−1.3pp) [S26]; (3) **domain knowledge via deterministic injection** (report 07 manifest — force-loaded, not discovery-gambled: the in-the-wild deflation [S27] is the direct argument for Sinet's registry-driven injection over engine-side skill discovery); (4) **output contract + domain rubric ref** (τ²-bench's tools+policy definition of a domain agent [S25]; MetaGPT's artifact mechanism [S36]); (5) at most one **tone/behavior line** where the duty warrants it (brand-voice writer) — persona prose is a tone lever with measured accuracy cost, so template lint (§4.3) warns on persona blocks beyond ⚙2 lines. Expected honesty: in strong-pretraining domains (software), specialization yields little (+4.5pp [S26]) — SWE workers stay thin (conventions, danger zones, verify commands — the N18-class content) and the platform must not equate "more template" with "better worker." Templates grow by the report-11 gated learning pipeline (lessons → L2 → distillation proposals), never by silent accretion.

### 4.3 The composition pipeline (7.1 — post-v0 activation, day-one schema)

**Trigger discipline (14.4 operationalized).** Composition is never the first response to a gap. The no-fit path (§4.7) offers: run-as-generalist (coordinator + injected domain knowledge, degraded-marked if the domain is unverified) for one-off tasks; **compose a worker only when the work is recurring, schedule/trigger-registered (7.4), or the requester explicitly asks** — machinery added when a task earns it. Gap records accumulate so the second occurrence of a task family surfaces a composition proposal.

**The composer** is one-shot generation (never archive/search evolution [S43]) running as ceremony on the requester's designated lane (1.10; billed and itemized, 3.6). Inputs, injected by policy: the task spec + gap record; the **composer playbook** — a versioned L2 house-knowledge pack holding current worker-authoring best practice, refreshed through the S2.8 watchlist cadence and updated only via the D10 knowledge gate (P47 applied to worker-building: "following the latest state of the art" is a maintained, versioned, *cited* knowledge object, not a hope about model memory — no shipped composer does this, §2.3); the **palette** (N22/S1 material re-cut as tool+context bundles, §6); the template schema + lint rules. Output: a template file draft + requested grants + a proposed dry-run sample task + a draft golden-case seed.

**The validation battery (7.2's "validation = structural checks + human sign-off," made into stations):**
1. **Schema lint** (deterministic): frontmatter JSON-schema validation; name/selector conventions; unresolved tool/skill/knowledge references; persona-block length warning; instruction-pattern screen over body + skill files (the report-06 helper-report screen applied to definitions — templates are untrusted content, §7 P-T14-2).
2. **Permission audit** (deterministic — the least-privilege linter that doesn't exist publicly [§2.3], built as a table not a model): requested grants diffed against a **task-class ceiling table** (per domain/task family: maximum tool set, confinement class, egress class); any request above ceiling → flagged line on the approval card; Rule-of-Two admission check (report 10) on the resulting class combination; **structural reject** if any guardrail-class field appears in the file itself.
3. **Dry run**: one sample task in a C1 (or the worker's class, capped at C2, effects-impossible) sandbox on the requester's lane, ⚙cost-capped; transcript + output attached to the card. Automated dry-run-as-gate is unshipped anywhere (§2.3) — Sinet builds it; it is cheap because the sandbox and checkpoint machinery already exist.
4. **Approval card** (D10; 13.5 explain-yourself contract): the definition as a readable diff (the 2.6 birth presentation — now industry convergence [S71]), requested-vs-ceiling powers table, dry-run result, provenance block. Owner approves personal workers; operator approves household promotion.

**Supervised first-N (7.6/7.2):** after approval, the first ⚙N (default 3) outputs in full-pipeline domains require requester review regardless of oversight settings; in degraded domains *every* output already does (7.6). Count-based graduation has no public prior art (production practice is time/traffic-based, §2.3) — flagged as Sinet-specific formalization; the graduation event is recorded on the template version.

### 4.4 Validation semantics and degraded mode (7.2, 7.6, 2.1)

A **validation record** row per (template version × model × engine pin): {lint result, audit result, dry-run ref, approver, date} — explicitly *not* a quality guarantee (7.2's own definition). **Degraded mode is structural, not advisory:** the template's domain ref resolves to a `domains` row carrying verification maturity (full|degraded — day-one rows: software=full, web-research=full at v0.1, all else degraded); the scheduler and gate layer enforce: degraded-domain workers cannot deliver without requester review, cannot attach to schedules whose results auto-accept, and their cards/receipts carry the visible marking (2.1). Graduation of a *domain* = a purpose-built rubric exists and passes its planted-defect falsifiability floor (report 12 §4.7) → operator flips the domain row through D10. Graduation of a *worker* = first-N complete + domain full. 7.4 registration composes: schedule attachment requires status=active, a validated record for the current model+engine, a missed-slot policy (2.8), and honors degraded-mode review requirements forever.

### 4.5 Versioning, outcomes, revalidation (7.3)

- **Immutable versions; alias rollback.** Every edit = new version row + new file commit (report 08's history-never-rewritten); `active_version` is the only mutable pointer; rollback = repoint (the MLflow/Langfuse convergence [S53, S54]). Any version change re-runs the §4.3 battery (cheap, structural) and resets first-N if the diff touches body/equipment ⚙.
- **Version→outcome is a join, not a system:** `routing.decided` already records worker+version per run (settled, report 12 §4.1); joining routing → verdicts → receipts yields per-version quality/cost views (the Langfuse pattern [S54] landing as SQL over the settled event log). The workforce map (9.4) reads this.
- **Revalidation triggers, extended.** (a) **Model change/deprecation** (watchlist-detected or provider-announced): flag every template version whose validation record or model pin references it → report 12 §4.7 runbook (golden set + planted-defect re-run on the new model; green → dated revalidation stamp; red → status=flagged + owner card; flagged workers may run *supervised* but not unsupervised — 7.3's own wording). Provider clocks make this routine, not exceptional: Anthropic retires on 60-day notice [S60]; the CAIN evidence says aggregate-green is insufficient — the planted-defect suite is the slice guard [S58]. (b) **Engine-pin bump** — new, this report (P-T14-1, §7): compiled artifacts and delegation semantics are engine-version-coupled (Claude Code changed subagent default model and execution mode within v2.1.x [S1, S17]; opencode deprecated a field [S2]); an engine upgrade therefore triggers the same flag-all-dependents pass, and engine behavior joins the S2.8 canary suite (already settled direction, now with the worker-side hook). (c) **Rubric/golden-set version change**: re-stamp affected workers (report 12 objects already versioned).

### 4.6 Overlays and instances (7.8, 10.1 — composing with report 11)

The overlay **is** the settled memory machinery — no second system: per-user × template L1 observation rows (TTL ⚙90d, descriptive only) + per-user L2 lessons/preferences scoped to the worker-overlay scope (human-gated, provenance-carrying). This report adds the **injection contract**: at instance compile, the frame = template body (base) + the user's overlay L2 slice (labeled, injected under the 8.9 precedence: task spec > project truth > personal overlay > template baseline > house defaults) + L1 history where relevant (clearly labeled as history, never rules) + the instance's L0 ledger section. Properties, each anchored: template files are never mutated by overlays (Kustomize base-unaware property [S88]); concatenation order is deterministic with most-specific-last (Claude Code memory model [S86]); conflicts between overlay lessons and template instructions are caught by report 11 §4.6's write-time topic_key machinery and surfaced — never left to the model's arbitrary pick (the documented hazard [S86]); overlays carry **zero guardrail fields** (a lesson can say "prefer British spelling," never "skip the review gate" — the descriptive/prescriptive boundary plus §4.1's split makes the latter structurally homeless); nothing crosses users except by 8.8 adoption (copy-on-adopt into the adopter's own overlay, origin visible — report 11 §4.2). **Instances** are settled: per-run L0 + run workspace, expiring with the task (report 07/08/11); two users on the same shared template run disjoint instances with disjoint overlays by construction (10.1). One added mechanic: overlay lessons reference the template version they were learned on; a major template version bump marks affected lessons for the standing ⚙90d re-verify cycle rather than silently carrying them (overlay staleness).

### 4.7 Routing to workers (2.3, 7.7 — extending report 03 Stage 0)

Worker selection is a Stage-0 extension, all free-tier: task family/stakes/data-bearing detection (settled) → **deterministic selector match** over the template registry (selectors + FTS5 over descriptions) → if multiple candidates, local-model tie-break with a one-line reason; every decision emits the settled `routing.decided` event {cause, score, signals, routed worker+version, model, effort, plain_reason}. **No trained router**: the catalog starts near-empty, classification machinery below ~15 targets is overhead [S65, single-source but convergent with RouterArena's oversell finding [S63]], and misrouting is cheap by design (2.5: plan preview + Stage-2 delta checks catch it before expensive work). **Visible and overridable**: the selected worker appears on the plan/approval card with its reason; the requester can re-route (the GPT-5 router lesson: silent routing destroys trust [S64]). **No-fit** = two-stage (Rasa-shaped [S67]): confirm the task interpretation; then one card offering run-as-generalist (default for one-offs; degraded-marked where applicable) / compose-a-worker (§4.3, when earned) / subscription-gap advice (2.7, when the gap is a *model* not a worker). Gap records persist and feed 7.5's roster growth honestly — the workforce specializes because recurring work earned it, never because a formation was pre-staffed (14.4).

### 4.8 Deterministic automations as C0 workers (2.6)

Same schema, same lifecycle, no second system: an automation template's body is a **deterministic workflow definition** in Sinet's own versioned dialect (report 14's A2 verdict — mirrored vocabulary, own parser, explicit approval nodes) instead of a prompt; equipment = the one named service + narrowest-scope broker-held credential (C0 per report 10); guardrails identical (§4.1). Born through the same §4.3 pipeline — the industry convergence is now complete on this (draft-by-default [S69], generated-outline-requires-completion [S70], checkpoint-diff-per-AI-edit [S71], auto-versioning [S72], approval-gated promotion [S74]) — with the anti-patterns named and banned: **every** field change versions (n8n's settings-changes-don't-version is the counterexample [S72]); one source of truth (n8n's DB-versions-vs-git-promotion split is the counterexample [S73]); **the whole definition is inside the hash** — no runtime-editable body (the gh-aw hole [S13]). Supervised first run = test execution on a sample payload with all outward effects as proposals (D7 makes this free); rollback = alias repoint; retirement = status flip with schedule detachment. "Reviewed like code, managed like a worker" is thereby one mechanism, not two.

### 4.9 Promotion, sharing, provenance (D10, 12.5, 8.8)

- **Personal by default** (D8). Promotion to household-shared = operator approval card carrying: full definition diff, provenance block, validation record, first-N history, and a **personal-data scan** (template must not embed user-scope content — overlays hold the personal part by construction; the scan is a lint rule).
- **Shared templates are read-only references**: adopters attach their own overlays (7.8's exact wording); un-sharing or retiring surfaces cards to affected users. Template *edits* on shared templates are operator-gated new versions; members' overlays persist across versions (§4.6 staleness mechanic).
- **Provenance** is a per-version block, not an afterthought: {author (human | composer model+version+playbook version), evidence refs (gap record, spec), approver+date, origin (composed | human-written | imported | adopted-from with source)} — richer than anything shipped (the industry's signed-authorship gap [S83]); it feeds S2.9 auditability and 8.8's origin-visible adoption.
- **Imports are untrusted content** (P-T16-4 enforced at this layer): no auto-import from any public registry, ever; a human-initiated import lands as a draft with origin=imported, passes the full §4.3 battery (lint + instruction-pattern screen + permission audit + dry run), and enters only through the D10 gate. The evidence base is now four independent incident classes (ClawHavoc 11.9%→824 [S76]; ToxicSkills 36.82%/91%-prompt-injection [S78]; load-time-executing skills [S79]; marketplace vetting failures at every major vendor [S80–S82]). Anthropic's own two-tier model (curated official / screened-but-disclaimed community, SHA-pinned per plugin [S82]) is the closest shipping analog — Sinet is stricter because a household has no security team.
- **Cryptographic signing of templates: not at v0.** The store is control-plane-owned on one host; integrity off-host rides the 11.3 snapshot hash ledger (report 13). Signing adds value only if templates ever move host-to-host outside snapshots — an explicit v1+ open question (§7), where the Sigstore-class machinery is known-applicable [S85].

### What would change the decision

1. **A cross-vendor agent-definition standard actually landing** (e.g., AAIF adopting an agent-layer format the way it adopted AGENTS.md) → re-evaluate the Sinet schema as a superset of *it*, keeping the guardrail split regardless (no standard proposes control-plane-owned guardrails).
2. **A controlled full-bundle study** (persona+tools+knowledge specialist vs well-contexted generalist, same frontier model, agentic tasks) contradicting the composition in §4.2 → re-weight the template content policy; Sinet's own 11.2 benchmark is the first instrument likely to produce household-relevant data.
3. **Engine format churn outpacing two-target lowering** (both engines breaking compiled-artifact semantics repeatedly) → collapse to compiling for one engine and driving the other via its API-level session config instead of definition artifacts.
4. **Skill discovery/triggering maturing** to reliable self-selection (the S27 deltas closing) → relax force-injection toward engine-side discovery for low-stakes duties; the injection manifest stays (auditability, 11.1).
5. **Meta-agent search economics inverting** (an evidence-backed composer that beats one-shot at small n) → revisit C1; the validation battery and gates are composer-agnostic by design.
6. **Anthropic/opencode shipping enforced, engine-level per-agent permission signing or config attestation** → adopt as an additional layer under the same schema (defense in depth, not replacement).

## 5. What NOT to use and why

- **Persona-first specialist rosters** (a standing army of role-prompted identities) — the persona null is replicated across four groups and two model generations, with measured accuracy *harm* from long personas [S18–S22]; role value lives in tools/knowledge/artifacts. This kills the anti-harvest roster twice over (§6).
- **Search/evolutionary meta-agent composition** (ADAS/AFlow/EvoAgent as Sinet's composer) — design costs exceed value below ~15k deployed examples; archive-learning measured harmful; self-referential optimizers game validators (DGM's faked test logs) [S40–S44].
- **An engine-native format as the platform's source of truth** — vendor churn (breaking renames within 12 months across all four surveyed ecosystems), inexpressible Sinet fields, and guardrail-class fields living in agent-writable file formats [§2.1]. Engines are compile *targets* (O3), never the store.
- **"Universal" neutral formats (OAF, Letta `.af`)** — no adoption; `.af` is run-state serialization, the wrong layer for templates [S10, S11].
- **Trained/learned task routers at household scale** — RouterArena: every router short of oracle, weakest exactly at send-it-cheap; GPT-5's silent router caused a user revolt; classification machinery is overhead below ~15 targets [S63–S65]. A visible classifier with recorded rationale wins at Sinet's n.
- **Public-registry auto-import of skills/templates/workers** — 11.9%→824 malicious on ClawHub; 36.82% flawed in the Snyk audit; verified-publisher badges shipped trojans at ~2.2M installs; 91% of malicious skills carry prompt injection [S76–S82]. Settled as P-T16-4; this report adds the import battery (§4.9) rather than any relaxation.
- **Visual agent-builder platforms as the composer surface** — the category's flagship (OpenAI Agent Builder) was deprecated inside 13 months, with hosted Evals dying alongside [S38, S39]; the surviving pattern is file-generation + review + eval gates, which is what Sinet builds.
- **Auto-activating generated automations** — industry-unanimous draft-by-default with mandatory human completion [S69–S71]; Sinet's D7 gate model makes auto-activation structurally impossible anyway.
- **Unreviewed self-generated skills as worker content** — measured negative (−1.3pp) [S26]; composer drafts enter only through curation and the gate.
- **Runtime-editable halves of "compiled" definitions** — gh-aw's markdown body escapes its own compile gate [S13]; Sinet hashes the entire definition.
- **Fine-tuning as the specialization mechanism** — irrelevant under subscription economics (no weights, D3/D5), and the generalist-frontier-beats-tuned-specialist record (Medprompt, BloombergGPT) says the trade was bad even when available [S31, S32].
