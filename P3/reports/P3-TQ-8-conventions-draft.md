## 81. The judge reads the tree, not the report — the change is the artifact, the step report is labelled claims, and the bound falls at a file boundary (P3-TQ-8, 2026-09-22; S07.5, S07.11, S13.1, S13.2; §15, §22, §23, §59, §74, §77, §78)

- **The defect.** `verify/artifact` carried the executor's step report and `verify/diff` was empty, so axis 1's mandatory extractive quote was measured against the executor's prose about its own work — the judge could only re-read what was claimed. S07.5's slice is "the artifact + its diff against the previous revision [S13]"; §78 settled that a repo-backed revision IS its tree at the pin.
- **What the judge receives for a tree revision.** `verify/artifact`: the whole change inventory — kind, path, old path on a rename, sizes, +/− counts, binary flag — never shortened (S13.1); then, in plain words, how much is shown and which files were left out; then the full new-side content of the modified/renamed text files that fit. `verify/diff`: the shown per-file unified diffs in path order, concatenated without separators. An added file's diff IS its content and rides once; a deleted file is its `-` diff; a binary gets an inventory row only — its bytes never reach the judge (S13.2). `verify/executor-report`: the report behind an `executorClaims` label saying a claim is not the work; emitted ONLY when non-empty, after `verify/diff` and before `verify/rubric`, carried on `JudgeInput.Report`. `verify.RenderChangeSlice` renders it, pure; the manifest stays the §15 clean assembly of S07-owned items.
- **One seam, implemented by the adapter that owns the identity.** `verify.ChangeSource.RevisionChange(ctx, d, bodyBudget)` is the only way a tree reaches verify; `stage.reviewSink` implements it over `review.Store.Change/CompareFile/RevisionFile`, so verify still never imports review (§22/§23). `newVerifier` wires one adapter into both seams whenever the review store is composed. **Only the revision NUMBER comes from the deliverable**: pins are read from the review store's own revision rows, because the revise path copies a stale `SnapshotSHA` onto rework revisions. Revision 1 compares against the recorded pre-task base (S13.1). `RepoFacts` stays pins-only; the stripped `VerificationWorkspace` is never a diff source (S07.3 rule 1, §59). The drain asks once per judged round — after the mint, before the paid call.
- **The bound, and where its number comes from.** `verify.JudgeArtifactBytesCap = 192 << 10` bounds the BODIES (diffs plus contents together) — a structural constant with its reason, not a ⚙ (S18 ratifies no key; the §78 caps' precedent): judge-seat window 200k tokens × ⚙ `context.stage_fit_target` 0.50 = 100k for the whole prompt; 192 KiB of code-shaped text ≈ 65k tokens at a conservative ~3 bytes/token, leaving ≥ 35k for the ACs, rubric, V1 outcomes, prior findings and the answer (S05.3). **Settings-tab ledger:** `verify.JudgeArtifactBytesCap`; a seat-derived bound is the refinement path once a seat's window is visible to verify. The §78 caps (512 KiB / 256 KiB / 1 MiB) stay the WIRE caps. The cut lands on a FILE boundary twice: diffs in path order until one does not fit and everything after is omitted (a contiguous prefix, so "the first N of M" is literally true), then contents from the remainder under the same rule. A budget-skipped row (`BodySkipped`) counts as omitted. Never a mid-file cut; every omitted file is NAMED beside its inventory row. The S05.3 watcher stays the measured backstop.
- **A lost pin kills the round; an absence is an answer.** Any seam error — `review.ErrContentDrift` included — is wrapped and returned from the drain before any judge call: zero paid calls, no verdict row, never a fall-through to the report (§78 F1). An `AbsentReason` (no snapshot pinned; no base recorded; no tree source composed) is an ANSWER: the slice keeps the content shape and the reason is recorded.
- **`JudgeSaw` on the round record.** Set on EVERY judged round, tree and content lane alike: kind, pins, `Files`, `DiffsShown`/`DiffsOmitted`, `ContentShown`/`ContentOmitted`, byte counts, `Truncated`. `RoundRecord.JudgeSaw` → `roundPayload.judge_saw` in `RecordRound` → the keep-forever verdict row (S07.11). That row's registered name is `verify.EventRound` (`verdict.recorded`); `verify.round` is a legacy alias nothing writes — **read event rows by their registered constant, never by a literal.**
- **Axis 1 quotes the tree, never the claims.** `ValidateAxis1`'s body is unchanged; its artifact argument is `JudgeInput.Quotable()` — the artifact item plus `"\n" + diff` when there is one. A PASS quoting only the report is forced `unknown: non-extractive evidence`. `axis1Schema` states the rule by item id; `validateFindings` is untouched (§77).
- **What did NOT change.** Cost shape: one compliance and at most one sanity call per judged round; the seam's reads are host-side git ($0); a bigger prompt is allowance, never a new call (S07.11). No ⚙ key, no migration, no new dependency. Content-pinned lanes stay byte-identical on the wire — a bare `Verifier` (nil `Change`) and every `AbsentReason` answer: `Artifact == d.Content`, `Diff == d.Diff`, no report item. Untouched: `verify.ReviewSink`, `internal/review`, `internal/project`, the retry package (`BuildRetryPackage` still carries `Deliverable.Content` — rework input is S07.6's, not the judge's), `Deliverable.SHA256()` and `stop.observe`, both still over the report.
- **The rule for future packets.** For a repo-backed deliverable the judge's artifact is the tree at the pins; the step report is claims, only claims. Anything added to that wire enters as its own S07-owned Extra item through `BuildJudgeInput` and declares whether it is quotable: nothing joins `Quotable()` that the platform did not read from its own store. **Carried:** `stop.observe` still compares reports across rounds, where equal pins would be the honest measure; modified files ride twice by design and contents are the first thing the bound drops.
