# P3 build conventions

Derived from the frozen spec (S01, S16; build order S19.5) at packet P3-B0-1, 2026-07-19. Every packet session follows this file; on any conflict the spec wins and the conflict is reported to the coordinator. The file is append-mostly: later packets add the conventions their sections ground (each addition cites its spec section) and never silently rewrite earlier ones.

## 1. Repository layout (S01.5, S16.2, S19.5)

```
cmd/sinet/            the one release binary — mode dispatch only
internal/             all platform packages (module-private; nothing is importable from outside)
tools/                repo/CI tooling (e.g. tools/lockgate) — never part of the release artifact
.github/workflows/    CI (S01.11)
components.lock       adoption manifest (S16.2) — repo root
P3/                   build coordination (STATE.md is coordinator-owned; packets never edit it)
Spec/  Research/  Docs/   read-only for build sessions
```

- **One binary.** The release artifact is a single static Go binary, `sinet`; `sinet-control`, `sinet-broker`, and `sinet-portpool` are the same binary invoked in dedicated modes (S01.5 multi-call posture). Never add a second `cmd/` — a new daemon is a new mode plus a unit file, not a new artifact.
- Daemon modes live in the mode table in `internal/cli`; modes not yet built are reserved names that fail with "not implemented in this build" (exit 1) so invocation shape and future `ExecStart=` lines are stable from the first build.
- SPA assets embed into this same binary via `go:embed` at B6 (S01.5); nothing about that lands earlier.
- No `pkg/` directory: this module is never imported, so everything beyond `cmd/` and `tools/` is `internal/`.

## 2. Go conventions (S01.5)

- **Module path:** `github.com/dariannixda-eng/Sinet-Agentic-Control-Hub` (the real repo; private, never fetched by proxy — the uppercase path is accepted).
- **Toolchain pin:** the `go` directive in `go.mod` (`1.26.5`) is the single source of truth; the `Go toolchain` entry in `components.lock` mirrors it and `tools/lockgate` fails on any mismatch. Toolchain bumps are adoption-rail events (dated lock edit + go.mod change together).
- **stdlib-first.** Any third-party Go module is an S16 adoption: S16.4 checklist plus a `components.lock` entry (with the module path in the entry's `modules` list) land in the same commit as the first import. CI enforces this (§4).
- **Formatting/linting:** `gofmt`-clean and `go vet`-clean, both enforced in CI. No additional linters at B0 (a linter is a dependency; adopt it through the rail or not at all).
- **Package naming:** short, lowercase, no underscores. The S01.1 module seams map to fixed package names, created by their owning packets (B0-2+): `internal/storage`, `internal/scheduler`, `internal/gates`, `internal/ledger`, `internal/eventlog`, `internal/adapters`. Names are fixed here so packets converge; do not invent variants.
- **Doc comments:** standard Go style on exported identifiers; cite spec sections (e.g. "Spec S01.5") where they genuinely clarify a design constraint. No research narration, no changelog prose in code.
- **⚙ settings discipline (S01.10):** no ⚙ value is ever a hardcoded constant. Consumers read the settings registry (built in P3-B0-2) by dotted key. Until the registry exists, leave a named seam: `// TODO(settings): ⚙ <key> per <section>` — never an inline number.
- **Errors:** wrap with `%w`; introduce sentinel/typed errors only where a caller branches on them.
- Open (deferred to owning packets): logging/structured-log shape → B0-3 (journald posture, S01.11); SQLite driver + storage conventions → landed at B0-2, §6; systemd unit generation → B0-3 (generated, not installed — host changes wait for the B0 gate); frontend conventions → B6 (FC-v1).

## 3. Test conventions

- stdlib `testing` only — assertion/mocking libraries are dependencies and none are adopted.
- Tests are colocated `_test.go` files; table-driven where natural; test binaries and fixtures never write outside `t.TempDir()`.
- `go build ./...` and `go test ./...` green is a precondition for every commit — packets never commit red.
- The real `components.lock` and workflow files are validated inside the test suite (`internal/lockfile`) as well as by the standalone gate, so plain `go test ./...` trips on manifest breakage.
- Bring-up measurements (S19.6) are not Go tests: they are coordinator/operator-run probes recording to `P3/measurements/`.

## 4. Adoption rail mechanics (S16, S01.11)

- **Serialization (resolves S16.2 TBD-P3(lock file serialization), P3 choice dated 2026-07-19):** `components.lock` is strict, pretty-printed JSON — one field per line, so review diffs are clean (S16.2's only constraint), and the Go stdlib parses it, so the gate itself requires zero adoptions. Unknown fields are rejected (`internal/lockfile`); a format migration, if ever wanted, is an ordinary dated lock edit.
- **Fields:** the nine S16.2 normative fields, with `license` structured as `{spdx, scope, checked}` (path scope + check date, P-T16-2) and `role` as `{summary, section}`. Documented extension fields, additive only: `modules` (Go module paths an entry covers — the mechanical hook for the bundled-dependency rule) and `notes`. An npm-side equivalent of `modules` is defined at B6, not before.
- **Entry materialization:** the S16.3 table is the binding v0 commitment; a row's lock entry materializes when its component is first consumed (running unit, bundled dependency, toolchain, CI mechanism). TBD-P3 pins resolve per their row text (Go: "pin at scaffold" → resolved at P3-B0-1) or at the first quarterly pass (S16.7, S19.5). Anything outside S16.3 enters only through the S16.4 onboarding checklist; checklist #10 (operator approval) means packet sessions propose and phase gates approve.
- **CI actions are on the rail.** GitHub Actions workflow actions are constituents of the ratified S01.11 CI mechanism, recorded as `kind: toolchain` lock entries and pinned to full 40-hex commit SHAs (the human tag goes in `notes`), so "no new dependency without a lock entry" holds everywhere. Runner images are pinned to exact stable labels (`ubuntu-24.04`); `-latest` and preview labels are floating and never used.
- **Pin discipline:** exact versions only — never `latest`, `*`, or ranges (`^ ~ > < =` are rejected by validation). Where vendored content exists, the pin carries a content hash and upstream LICENSE/NOTICE files are kept in-tree (S16.2); nothing is vendored yet.
- **The gate:** `go run ./tools/lockgate` — locally before commit and as the CI `lock-gate` step. It validates the manifest fields (S16.2), asserts every `go.mod` require is covered by an entry's `modules`, asserts the `go` directive matches the Go-toolchain pin, and asserts every workflow `uses:` is SHA-pinned and entry-covered. The workflow scanner is a line-level tripwire for this repo's own files, not a general YAML parser — keep workflow `uses:` lines simple. The running-unit half of the S16.2 CI rule activates when unit generation lands (B0-3+).
- **Removal discipline:** an entry leaves the lock only by executing its funeral plan, as a dated lock edit with the reason — never silent deletion (S16.2).

## 5. Commit & process conventions (P3)

- **Subject:** `P3-<phase>-<n>: <summary> (<spec sections>)` — e.g. `P3-B0-1: repo scaffold + adoption rail + CONVENTIONS (S01, S16, S19.5)`. Body optional; trailer on every packet commit: `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.
- Stage files explicitly — never `git add -A`. Packet sessions never push (the coordinator pushes after validation), never force-push, never edit `Docs/`, `Spec/`, `Research/`, or `P3/STATE.md`, and never read or stage `*-api-key.txt`.
- **CI:** `.github/workflows/ci.yml` runs gofmt, vet, build, test, lock-gate on push to `main` and on PRs. The tag-triggered release pipeline (artifact + `SHA256SUMS` + signed tag, S01.11) is a later packet.

## 6. Storage, event-log & settings conventions (P3-B0-2; S02.1–S02.2, S01.10, S18)

- **Driver:** `modernc.org/sqlite` (pin + funeral plan in `components.lock`; S16.3 row resolved at B0-2). `internal/storage` is its only importer — the storage seam (S01.3). **Pin coupling:** `modernc.org/libc` stays exactly at the version in the driver's own `go.mod` (upstream issue #177); driver and libc bump together, never independently.
- **Connection discipline (S02.1):** WAL journal mode, ⚙ `state.synchronous`, ⚙ `state.busy_timeout`, and `foreign_keys=ON` ride the DSN (`_pragma=…`) so every pooled connection is identical; `_txlock=immediate` makes every `sql.Tx` a `BEGIN IMMEDIATE`. The pool is one connection (in-process serialization; the write rate needs no more). `PRAGMA integrity_check` runs at every open. Pragma ⚙ values are read from the settings registry at open with declared defaults; the shell calls `ReapplySettings` once overrides load (S01.6 step 1). Nothing file-copies the live DB; `-wal`/`-shm` sidecars are never deleted or renamed; WAL stays same-host (S02.1).
- **Migrations (S02.1):** numbered one-transaction SQL files `internal/storage/migrations/NNNN_name.sql`, contiguous from `0001`; each applies atomically with its `PRAGMA user_version` bump (`user_version` is the sole version authority). **A migration file, once committed, is immutable** — schema change = new numbered file, never an edit; history is never rewritten.
- **Append-only enforcement:** `run_events` and `settings_events` carry `BEFORE UPDATE`/`BEFORE DELETE` `RAISE(ABORT)` triggers; a future compaction (11.1) enters via its own migration, never ad-hoc writes.
- **Event conventions (S02.2, S02.5):** ordering only by `event_seq` — timestamps are recorded, never ordering (P-T07-4). Platform-scope events have `run_id NULL` (and no generation); run-scoped appends carry the run's generation and are fenced against `runs.generation` (stale AND ahead both rejected). Payloads are validated before persist (valid JSON, ⚙ `state.event_payload_cap`; refs-not-blobs, P-T07-5). Every row carries `user_id` (15.6). State transitions append via `AppendTx` inside the same `WriteTx` as their row update (S02.3).
- **Settings conventions (S01.10, S18):** all declarations live in `internal/settings/index.go` — declare-once; tests pin the index to the S18.5 tallies (118 keys, 33 domains, per-owner counts). Canonical units: unnamed durations → seconds, sizes → bytes; keys whose name embeds a unit (`_s`, `_days`, `_hours`, `_mb`, `_months`, `_usd`) stay integers/floats in that named unit (S18.4 R10: cosmetic under typed declarations). Map-valued families (`local.alias.<duty>`, `watchdog.silence_budget.<run_type>`) are one `TypeMap` key each, subkeys as map keys. Consumers read ⚙ values by dotted key through narrow per-package interfaces (`storage.Settings`, `eventlog.Settings`) satisfied by `*settings.Registry`; composition order: `settings.New()` → `storage.Open` (defaults) → `Migrate` → `eventlog.New` → `Registry.Attach` → `ReapplySettings`. Every write is one transaction: override row + `settings_events` audit row + `settings.changed` event (G3 Def.2); actors are `operator` or `automation` (automation: auto-flagged keys only, value moves only, within bounds — G1 rider 1); numeric bounds are operator-owned, seeded from the ratified clamps; reset-to-default deletes the row.

## 7. Shell, API & unit-generation conventions (P3-B0-3; S01, S15.2–S15.3, S02.1)

- **Composition root:** `internal/shell` realizes §6's order, then the S01.6 ladder: bootstrap config → registry attach + `ReapplySettings` → listener-binding lint (P-T13-2, fail-closed `shell.ErrNonLoopback`; **literal loopback IPs only — hostnames incl. `localhost` rejected**, re-asserted on the bound listener) → bind + serve (front chain tolerates not-ready) → recovery-ladder seam (`shell.RecoveryLadder`, stub until B0-4; the S01.7 wake path reuses the same level-triggered `Reconcile`) → `platform.started` → `sd_notify(READY)` + heartbeat → admission-seam resume. SIGTERM/SIGINT shutdown: STOPPING → stop admission → `platform.stopping` → SSE final drain → graceful HTTP stop → `wal_checkpoint(TRUNCATE)` → close (in-process budget 20 s; unit `TimeoutStopSec=90` exceeds it, S01.6). WAL-truncate scheduling is a shell goroutine on ⚙ `state.wal_truncate_interval` (live-apply, re-read per cycle). Maintenance mode is `shell.Maintenance` (`running/draining/maintenance`, ⚙ `shell.drain_grace`, park-at-expiry via the admission seam); no HTTP mutation surface until auth lands (B0-5).
- **Bootstrap config (S01.10):** `<config-dir>/bootstrap.conf`, strict `key = value` lines (`http_addr`, `db_path`; `#` comments; unknown keys fail closed); config dir = `--config-dir` → `$CONFIGURATION_DIRECTORY` → `/etc/sinet`. **Dev posture is the absence of systemd env** (`NOTIFY_SOCKET`, `STATE_DIRECTORY`, `CONFIGURATION_DIRECTORY`), never a build flag; dev flags `--state-dir`/`--http-addr` override per invocation. sd_notify is implemented in `internal/sdnotify` on the stdlib (unixgram write) — never adopt a library for it.
- **Logging (S01.11):** ops logs are stdlib `log/slog`, text handler, **stderr** (journald captures under systemd; stdout stays for tool output). The event log remains the only audit truth. No log-level ⚙ exists — none is ratified; don't invent one.
- **Five seams → packages (S01.3):** storage → `internal/storage` (B0-2); process → one unit per organ — generation in `internal/units`, mode table in `internal/cli`; API → `internal/api`; adapter → `internal/adapters`; adoption → `components.lock` + `internal/lockfile` + `tools/lockgate` (B0-1). The §2 module-seam packages `internal/{scheduler,gates,ledger,adapters}` exist from B0-3 as stubs citing their owning sections (S10/S02/S05/S03); owning packets replace stub internals, package names stay. The shell's lifecycle calls cross seams only through `shell.Admission`/`shell.RecoveryLadder`.
- **API & SSE (S15.2–S15.3, S02.1):** unversioned at v0 (no `/v1`). `/api/health` is the readiness surface: 200 once the S01.6 sequence completes, 503 while starting/stopping, JSON `{ready, mode, version, event_head}` (`event_head` = snapshot-then-tail cursor bootstrap). The one SSE endpoint `/events`: frames `id:` = `event_seq` (sole ordering authority), `event:` = stored type, `data:` = row JSON with payload embedded; resume via `Last-Event-ID`, then `?after_seq`; cursorless connect tails from head. Tailing is short-batch (256/read — not ⚙; S18 has no such key) on a 250 ms poll baseline plus in-process nudge; keepalive comment every ⚙ `obs.sse_keepalive`. Every route runs behind the identity-middleware seam (`api.Authenticator`); the dev implementation is a static `dev` identity, resolution-only, until B0-5. Platform lifecycle events `platform.started`/`platform.stopping` (platform-scope, `user_id` `platform`) are minted provisionally pending the S14 event contract (B5).
- **Unit generation (S01.2, S01.11):** `sinet units` renders the owned unit set + the journald cap drop-in (`journald-sinet.conf`, ⚙ `shell.journal_max_use`) to stdout or `--out DIR`, from **registry defaults** (override-aware regeneration arrives with the operator surfaces); ⚙ `shell.watchdog_sec` renders `WatchdogSec=`. Units with spec-stable invocations (control/broker/portpool: `ExecStart=<bin> <mode>`) are complete; `sinet-engine@`/`sinet-run@` emit as marked **DRAFT** skeletons carrying only spec-fixed directives (run@: `Type=exec` + `RemainAfterExit=yes` + `ExitType=cgroup` + `Restart=no`, S02.5) — their `ExecStart` belongs to S03/S11.8 at B1. Every unit: `User=sinet` (never `DynamicUser=`), the S01.2 hardening set, the A1 hostname constants (`units.Hostname`/`units.FQDN`). Adopted organs' units are never generated (process seam: replace unit + lock entry). **Generation never installs**; `dist/` (git-ignored) is the conventional local output dir; host installs are phase-gate operator decisions. Non-daemon subcommands (`units`, `version`) are tools, not modes: no unit file, never in the reserved-mode table.

## 8. Run FSM, effect journal & recovery conventions (P3-B0-4; S02.3–S02.7, S02.9, S16.5)

- **Package map:** the S02 machinery lands as `internal/run` (S02.3 FSM + S02.6 freshness comparison), `internal/gates` (S02.4 checkpoints + S02.7 effect journal — the S01.1 gates seam its B0-3 stub reserved), `internal/recovery` (S02.5 ladder, implements `shell.RecoveryLadder`). The shell owns *when* the ladder runs: startup step 3 plus a sweep goroutine on ⚙ `recovery.sweep_interval` (live-apply, mirrors the WAL loop).
- **Transition discipline (S02.3):** every `runs.state` change goes through `run.Store` in ONE WriteTx — CAS-guarded UPDATE + `eventlog.AppendTx` — and run creation appends its birth event in the same tx (the run's existence is in the D7 event record from its first instant). The resume edge parked→running bumps `generation` and appends at the new one; fork is the takeover bump: crash event at the old generation → old-row generation bump (the fence) → successor row + `run.forked` event at generation+1, all one tx. The ratified edge set lives in `run.transitions` with per-edge citations; `crashed` is terminal-but-supersedable (harvest/fork/tombstone/finalize), the other four terminals admit nothing.
- **Fork lineage (migration 0002; S02.5 step 3):** `runs.parent_run_id` (supersession link), `runs.dispatch_id` (durable one-dispatch-per-interruption id, `<parent>#g<newGen>`, partial-unique index = the double-start CAS), `runs.recovery_attempts` (lineage-cumulative, checked against ⚙ `recovery.max_attempts` before each fork). Successor run ids are `<parent>.g<newGen>`; successors enter `queued` (the work was already admitted; queue-row materialization is S10's, B1). Step 3's "with backoff" rides the pass cadence (⚙ `recovery.sweep_interval`) until the scheduler owns re-dispatch timing (B1) — no backoff ⚙ exists and none was invented.
- **Run event types** `run.created` / `run.state` / `run.forked` / `run.wedged` / `run.harvest` / `run.checkpoint` are provisional pending the S14 event contract (B5), extending §7's lifecycle-naming note. Run-scoped event rows are attributed to the run's **owner** (15.6); the acting principal (`platform` for ladder/shell acts, `run.ActorPlatform`) rides the payload.
- **Effect journal (S02.7, gh-aw safe-outputs shape S16.5 — effects gate ≠ quality gate):** payloads are stored canonicalized (UseNumber decode → sorted-key compact re-marshal; platform-internal consistency, not cross-system canonicality) and `payload_hash` = sha256 hex over that form. `executing` commits in its own tx BEFORE the provider call; `idempotency_key` = the effect UUID, set at first BeginExecute, never changed. Approval expiry (⚙ `effects.approval_expiry`) or payload drift at execution **commits** the row back to `proposed` (Terraform saved-plan semantics — the reset must outlive the failed call) and reports `ErrApprovalExpired`/`ErrPayloadDrift`. Reconcile of in-doubt rows: A/B/C → `approved` with key + attempts intact (replay dedups at the provider; class C searches first when attempts > 0), D → `unknown` + decision card (P-T07-3). Journal transitions are effects-row updates, not `run_events` appends; composition with FSM transitions uses the `…Tx` variants.
- **Ladder discipline (S02.5):** level-triggered, passes serialized; suspend-aware grace (⚙ `recovery.wake_grace`) applies on a process's first pass and on a wall-clock jump > 2× ⚙ `recovery.sweep_interval` between passes (the S01.7 clock-jump wake detection; logind D-Bus wiring is a later packet — needs an adoption decision, no stdlib D-Bus). DEAD needs proof (corpse-failed) or a dead/absent lease — a live lease is always honored, and WEDGED is pause-and-flag (once per stall episode), never auto-kill (D1.3). Crash + bound decision (fork / tombstone / finalize) commit in one tx so no crashed run is ever left without its decision; ⚙ `recovery.stale_finalize` applies to crash-interruptions only — parked-on-gate runs are "blocked, not failed" and route through the S02.6 freshness pass instead. Checkpoints are writable only in `running`/`draining`. B0 observation seams `recovery.UnitLiveness`/`recovery.HarvestSource` default to observing nothing; real systemd + engine-store probes arrive with run units and adapters (B1).
- **Kill-9 harness (S02.9):** a standing conformance entry in `internal/recovery` — the test binary re-execs itself (`SINET_CRASH_SCENARIO`) as a child that drives real machinery to a nasty window and dies by self-SIGKILL; the parent asserts `integrity_check` ok, committed state intact, the interrupted tx invisible, one pass classifying every non-terminal run, fencing inert, per-class effect resolution, gap-free `event_seq`, and ask-row survival. The suspend-cycle companion injects clock deltas through the ladder's `Now` seam.

## 9. Auth conventions (P3-B0-5; S01.9, S01.4, S15.2)

- **Package split:** `internal/auth` is the S01.9 data layer (sessions, argon2id PINs, device grants — AuthZ enforced here, per S01.9 "enforced in the control plane's data layer": accessors take the acting user and check the one role bit against the users row); `internal/api` keeps the seam (`api.Authenticator`, production impl `SessionAuthenticator`) plus the login/session endpoints under `/api/auth/*` (S15.2: those endpoints are S01.9's; exact paths are P3's within that bound). Migration `0003` adds the PIN columns, `sessions`, `device_grants`.
- **Route classes:** the pre-session surface is exactly `/api/health`, `GET /api/auth/session`, `GET /api/auth/users`, `POST /api/auth/login`, and `POST /api/auth/users` (bootstrap window only) — reaching it already proves tailnet membership (S01.9 layer 1). Everything else, `/events` included, requires an authenticated identity, fail-closed 401; an internal resolution failure is 500, never an anonymous downgrade.
- **Sessions (layer 3):** server-side rows; the cookie (`sinet_session`, HttpOnly, SameSite=Lax for S15.11 deep links, Secure outside dev posture) carries a 256-bit bearer token stored only as its SHA-256. Expiry is absolute wall-clock (a suspend never extends a login); expired rows delete on sight plus a login-time sweep. **No auth ⚙ keys exist in S18** — session TTL 30 d, 5-attempt ceiling, 15-min lockout, PIN length 4–128, and the RFC 9106 argon2id parameters are code constants (the `sseBatchSize` precedent, §7), flagged to the B0 gate; dialing any of them is an S00.9 amendment + S18 sweep. Credentials are PHC strings, so parameters ride the stored hash and can move without invalidating PINs.
- **Device hint (layer 2):** only `Tailscale-User-Login` is parsed (the one injected header S01.9 assigns meaning); it prefills (`/api/auth/session` hint block) and completes login solely through an operator grant row (`device_grants`, one per device account — the header IS the whole device signal). Grant-login never touches the PIN failure counter; the counter is shared between login and step-up (same secret, same guessing surface). No-grant default = shared device, PIN always required (G3 Def.1).
- **Step-up (High-tier re-prompt):** no stored elevation state — S01.9's "never inherited from an idle session" is implemented as verify-at-act: credential/grant/user-admin verbs re-prompt the actor's own PIN in the same request (`VerifyPIN`, purpose-tagged `auth.reprompt` events), and the B2+ approvals family routes High-tier answers through the same call.
- **Audit:** every auth act appends in the same tx as its row change — provisional types `auth.{login,login_failed,logout,pin_set,grant,grant_revoked,reprompt,reprompt_failed,user_created}` (pending S14, extending §7's naming note), owner-attributed per 15.6; acts without an owning row (unknown-user attempts) attribute to `platform` with the attempted id in the payload. Failure responses stay collapsed (401) — the event log carries the precise reason.
- **Bootstrap & reserved ids:** while `users` is empty, one anonymous create is allowed and MUST be an operator (D10 needs a holder from the first user); `platform` and `dev` are reserved ids no person row may take. The dev fallback identity (dev posture only, absent systemd env, §7 — detection now `shell.devPosture()`) is resolution-only: it reads, but every admin verb refuses it.
- **Rail:** `golang.org/x/crypto` v0.54.0 adopted at B0-5 (S01.9 names argon2id; stdlib has none) — lock entry with S16.4 walk, golden-vector conformance test in `internal/auth`, companion `golang.org/x/sys` bump v0.46→v0.47 (coverage stays with the driver entry); operator ratification (#10) queued for the B0 gate.

## 10. Adapter & engine conventions (P3-B1-1; S03, S02.4, S16.3)

- **Package map:** `internal/adapters` owns the D3 contract (S03.1 verbs: start/stream/checkpoint/pause/resume/cancel/report_usage) **and** the platform-side `Driver` that persists what the contract yields (run_events, S02.4 checkpoint rows, `engine_sessions` + transcript copy-aside, ask rows). One package per substrate beneath it: `internal/adapters/claudecli` (Anthropic lane); the opencode adapter lands with its consuming packet under `internal/adapters/` too. Substrate names on `runs.substrate` are the package constants (`claude-cli`, `opencode`); lane names `anthropic`/`zai`/`local` (S03.2).
- **Engine events in run_events:** adapter-observed events append as `engine.<kind>` over the closed S03.1 kind set (message/usage/rate_limit/gate_ask/tool_result/done) — names provisional pending the S14 event contract (B5), extending §7/§8's note. Unknown ENGINE frame types are logged and skipped, never fatal and never minted as new platform kinds (S03.1 MUST). Payload excerpts bound at `adapters.ExcerptCap` (4 KiB, plain constant — the §7 `sseBatchSize` precedent); full content lives in the engine transcript + copy-aside (P-T07-5).
- **Paid-call bookkeeping:** each per-call usage event commits `engine.usage` + the S02.4 checkpoint row + its `run.checkpoint` event in ONE WriteTx; run-total usage rows (terminal envelope) ride `engine.done` + the Outcome, never a checkpoint (D7 is per paid call). Ledger-revision block stays an empty seam until S05 (B2); artifact-snapshot block fills via `Driver.Snapshot` when workspace machinery lands.
- **Conformance tiers (S03.3) & THE sanctioned skip class:** every engine adapter ships a conformance suite in three marked tiers — **F** replay fixtures (always run; CI has no engine), **R** real-engine zero-cost (auto-runs when the engine binary is installed), **L** real-engine paid (only under `SINET_LIVE_SMOKE=1`, one minimal call). Tier R/L absence-skips print `SANCTIONED SKIP (CONVENTIONS §10)` — this is the one skip class allowed in a green battery. Suites assert behavior, never docs/help text (S03.3 rule 4; live-proven: 2.1.215 dropped `--max-turns` from `--help` while still parse-accepting it).
- **Pin discipline:** each adapter exports its `Pin`, test-coupled to the `components.lock` engine entry; a pin↔installed delta is reported LOUDLY (test notice + lock-entry note + packet report) and never silently retargeted — reconciling is the operator's S03.3 deliberate-bump procedure. Fixtures record engine behavior with provenance (spike record or live re-record, dated).
- **Credential hygiene (D2):** owner credential refs are PATHS handed through env (`CLAUDE_CONFIG_DIR` = the per-user config root on the Claude lane), never read, logged, or embedded; lowering scrubs `ANTHROPIC_*`, `CLAUDECODE`, `CLAUDE_CODE_*`, `AI_AGENT`, `CLAUDE_EFFORT`, `CLAUDE_PID`, and ambient `CLAUDE_CONFIG_DIR` from the child env (S03.5 env channel + subscription-auth protection). Broker-mediated injection replaces the dev-mode ref at B1-3 (S11).
- **Gate hook:** `sinet engine-hook --ctl <dir>` is a tool subcommand (§7 sense) compiled into lowered settings for gated tools (S03.4); it exchanges state through the ctl dir only (config.json / fires.log / answers/).
