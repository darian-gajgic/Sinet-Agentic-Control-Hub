**Recommended split — the B5-3/B5-6 A/B precedent, cut on the section boundary (S14.9 | S14.10):**

**R1 [A] — `run.summary_written` producer, at run end, never later.** [S14.9 ¶1; S14.2 "Run summary" row] A summary is written at the run's terminal transition, in the same WriteTx discipline the §6/§8 state+event convention imposes. Contract-minimum payload per S14.2: **summary artifact ref + generation inputs digest**. `run.summary_written` flips declare→minted per §29 (see R16).

**R2 [A] — the summary is deterministic aggregation FIRST.** [S14.9 ¶1] The structured story — objective, stages, tool-call counts, verdicts, decisions, receipts, final state — is computed by SQL/Go aggregation over `run_events` + `checkpoints` + `receipts`. Every field in that list is derivable from tables that exist. This aggregate **is the record**.

**R3 [A] — the local tier ENRICHES, never gates.** [S14.9 ¶1; S12.4 `distill-summarize` row] The narrative pass rides alias **`distill-summarize`** (S12.4: "L1 distiller; **run summary at run end** [G2 Def.11]"), workhorse seat, with "grounding instructions, extract-then-abstract, **event-id citation-forcing**, length caps, section schema"; low-confidence handling is "sampled outputs screened by `entailment` … persistent failure escalates the model choice, **never the run**". `*local.Duty` is nil-safe (`ErrStackAbsent`) — an absent stack yields a summary carrying the deterministic aggregate alone, honestly flagged. **A run must never fail to end because the local tier is down.**

**R4 [A] — incremental-per-run only.** [S14.9 ¶1] No batch/backfill summarizer over historical traces. "Bulk summarization over months of trace is the documented failure shape."

**R5 [A] — the compaction pass strips bulky event payloads and transcript copy-asides at ⚙ `retention.compaction_horizon`.** [S14.9 ¶2] The key is **`PerUser: true`** → read via `IntFor(key, userID)`, per-owner, never `Int(key)` (§14). **R6 [A] — the keep-forever set is enumerated over the S14.2 families, not guessed.** [S14.9 ¶2] The spec names seven classes; mapped onto the registry in `internal/eventlog/contract.go` (15 families, 94 types) they are:

### C — Layer 2 open SQL, the S12.3 guardrail stack (may be its own packet)

**R29 [C-opt] — read-only connection (`query_only`) on a SEPARATE handle.** [S14.10 ¶3; S12.3 restated] Verified obstacle: `internal/storage/storage.go` opens **one** `*sql.DB` with `SetMaxOpenConns(1)`; a per-connection `PRAGMA query_only` would disable the control plane's own writes. Layer 2 therefore needs a **second, separately-opened handle** — read-only by DSN and by `query_only` — for which **no seam exists today**. Consistent with S02.1's stated posture: "the `sinet-control` process MUST be the sole writer; dashboards, the CLI, and read-model followers open read-only connections" and storage.go's own doc, *"everything else opens read-only (enforced by posture, not by this package)"* — this packet makes it enforced by mechanism for the query surface.

**R30 [C-opt] — allowlisted views ONLY.** [S14.10 ¶3; S12.3] Arctic generates against the named view set (R19/R23), never base tables. The allowlist is data; a query naming anything outside it is refused before execution. This is also what makes R9's "structurally unreachable" property compose: raw trace payloads are not in the allowlist.

**R31 [C-opt] — single-statement parse rejecting DDL/DML — and it must EXTRACT, not merely reject.** [S14.10 ¶3; and the adverse measurement] **This is the load-bearing finding of `P3/measurements/2026-07-22-sql-open-arctic.md`.** Measured on the deployed seat: **Arctic-Text2SQL-R1-7B Q5_K_M scored 0/30 (0.0%)**, Wilson [0.00, 0.11], **worse than the general-purpose proxies** (9B 16/30, Gemma 17/30, 4B 9/30). Diagnosis, verbatim: *"Arctic-Text2SQL-**R1** is a REASONING (R1-style) model: it emits a long chain-of-thought before the SQL, which exceeds the suite's 600-char output-contract cap (and/or buries the `SELECT` past the checked window) … This is exactly why S12.3 flags the SQL layer lower-confidence and why its real consumer is the S12.3 guardrail stack (S14/B5): read-only connection, allowlisted views, **SINGLE-STATEMENT PARSE (which extracts the `SELECT` from the reasoning output)**, LIMIT+timeout, audit-logged."* Therefore the parser **must** locate and extract the SQL from surrounding reasoning text, then assert: exactly one statement, `SELECT` only, no DDL/DML/PRAGMA/ATTACH, no multi-statement separator smuggling, no comment-hidden second statement. **`NoThink` is not the answer here** — Arctic's reasoning IS its method; suppressing it degrades the model. Extraction is the design.

**R32 [C-opt] — LIMIT + timeout injection.** [S14.10 ¶3] A LIMIT is injected (or tightened) on every generated query; a wall-clock timeout bounds execution. Neither number is a declared ⚙ key — see **OQ6**.

**R33 [C-opt] — every generated query is audit-logged.** [S14.10 ¶3] The NL question, the extracted SQL, the injected LIMIT/timeout, the refusal reason if refused, and the outcome. This is the audit record of an escalation surface; it lands in `run_events` like everything else (S14.1: the record always lives in Sinet's DB).

**R34 [C-opt] — every answer is flagged lower-confidence.** [S14.10 ¶3; S12.3; S12.4 "every answer flagged lower-confidence **by construction**"; S15: "whose answers MUST visibly carry their lower-confidence flag"] By construction means the shape carries the flag — there is no unflagged Layer-2 answer type. The §35 "no bare-rate accessor" pattern is the precedent: make the unflagged form inexpressible.

**R35 [C-opt] — canned queries remain the floor; Layer 2 is escalation, never default.** [S14.10 ¶3; R12 §4.8] Ordering is structural: Layer 0 → Layer 1 → Layer 2. Layer 2 is reached only when Layer 1 intent classification fails to resolve — and per R25 the Layer-1 failure mode is *a disambiguation card*, so the escalation path must be explicit, not a silent fallthrough.

## 11. OPEN QUESTIONS — coordinator disposition required

Each carries a recommended disposition with its spec evidence. **None may be resolved silently by the executor.**

**OQ0 — the split (see §0).** Recommend **A/B on the S14.9|S14.10 seam**, with the B/C seam pre-cut if tighter packets are wanted. *Evidence:* nine subsystems, five with zero in-tree precedent; the B5-3/B5-6 A/B precedent; the all-opus routing already isolating the injection surface.

**OQ1 — compaction vs the append-only trigger. (The single biggest structural constraint.)** `run_events` carries `run_events_no_update` and `run_events_no_delete`, both `RAISE(ABORT)` (`0001_core_schema.sql:79-89`). **An in-place payload strip cannot execute against the current schema.** S02.1 says *"History is NEVER rewritten — append-only"*; S14.9 says the pass *"strips bulky event payloads"*. **Recommend (a): `0015` replaces `run_events_no_update` with a narrowed trigger that permits exactly one transition — `payload` → the compacted marker, on rows at/below the horizon — and still aborts every other column change and all deletes.** *Evidence:* S02.1's append-only is about history not being re-authored, re-ordered or deleted, and S02.1 itself defers to the retention period; S14.1 scopes reconstructability to *"the whole retention period (S14.9)"*; S14.9 explicitly mandates the strip; and `contract.go:15-19` already anticipates compacted rows as a designed-for state. The narrowed trigger keeps the invariant **checkable** (identity columns immutable, payload one-way, never to arbitrary content) rather than deleting it. *Alternative considered:* model compaction as a side table — rejected: it leaves the bulk in place, so it does not discharge the obligation at all.

**OQ2 — the exporter boundary: a genuine three-text tension.** Three sections describe the same boundary differently:
- **S02.9:** *"raw `run_events` payload bodies **past the 11.1 compaction horizon** excluded (traces stay local)."* → a **horizon** boundary.
- **S13.10:** *"text-first `.dump` (**raw trace payload bodies excluded**; full traces stay local under 11.1 retention)."* → **all** raw trace bodies.
- **S14.9:** *"the snapshot exporter reads an **allowlisted view containing only the keep-forever set**; raw trace payloads are **structurally unreachable** from it."* → a **type** boundary, all ages.

The current code implements neither cleanly: `dumpTableData` blanks **every** payload at/below a scalar `stripPayloadBeforeSeq`, **including keep-forever ones**, and `internal/backup/backup.go:108-110` holds it at `0` (so today nothing is stripped at all). Note also that `retention.compaction_horizon` is **per-user**, so a single global seq cannot express the horizon boundary anyway. **Recommend: follow S14.9 + S13.10 — the exporter's `run_events` source becomes the keep-forever allowlist view; raw trace payloads never leave the host at any age.** *Evidence:* S14.9 owns the boundary (its own heading is "11.3 boundary by construction") and is the most mechanically specific; S13.10 agrees; S02.9's horizon phrasing is satisfied a fortiori (excluding all raw trace bodies necessarily excludes those past the horizon); and a type boundary is the only one a per-user horizon can express. **Consequence to approve: this edits landed B4-3 code** in `internal/storage/backup.go` + `internal/backup/backup.go`, and `StripPayloadBeforeSeq` likely retires in favour of the view.
