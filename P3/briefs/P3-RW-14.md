## 1. Diagnosis (a): verify crashes and the task wedges silently at VERIFYING

### What the live world shows (decisive rows, `~/.sinet-builder/platform.db`)

The verify lineage, run_events:

- seq **1051** (`t-4b982b38a62baee5.verify`, gen 0): `run.state_changed` running→crashed, detail `{"cause":"verification drain: verify: launch-domain deliverable without a domain check pack (Spec S07.8)"}`.
- seq **1063**, **1067**, **1073**: the identical deterministic crash on forks `.g1`, `.g1.g2`, `.g1.g2.g3` (the ladder re-forked into the same error at each ~5 min sweep).
- seq **1075** (`.g1.g2.g3`, gen 3): crashed→**tombstoned**, `reason:"recovery: repeat offender (Spec S02.5 step 3)"`, detail `{"recovery_attempts":3,"card":"tombstone-review: ⚙ recovery.max_attempts exhausted"}` — the "card" is a **string inside an event payload**, nothing else.
- `tasks` row: `kanban_status = "verifying"` — forever.
- `asks`: **zero open rows for the task** (every ask row in the world is `answered`/`cancelled`). The only `watchdog.flagged` events in the window (seq 891, 1100) concern **unrelated** `platform.advisory.*` runs — not even oblique coverage of this task.

Contrast inside the same task: the **intake** lineage also crashed three times (seq 488 planner-JSON contract crash, then two DEAD reaps) and **recovered to completion** at `.g4.g5.g6` — the ladder works for transient faults; it can never fix a deterministic refusal, and its terminal is currently invisible.

### Root cause, half 1 — the crash

`internal/verify/pipeline.go:204` (`validateInput`): `if LaunchDomain(d.Domain) && v.Pack == nil { return nil, ErrNoCheckPack }`. The Verifier's `Pack` comes from `stage.Config.CheckPacks[domain]` (`internal/stage/skeleton.go:805`), and the composition root **ships that map empty** (`internal/shell/shell.go:577`: "CheckPacks ships empty: the software pack is per-project registry machinery (Spec S13, B4)"). B4 landed the registry machinery; nobody ever closed the loop. So **every software-family (launch-domain) task crashes at verify in production**. `dispatchVerify` maps the refusal to `Skeleton.crash` → the S02.5 ladder forks a deterministic error three times → tombstone.

The battery never caught it because **every landed e2e walk answers the family gate "generic"** — the walking skeleton's own comment says "no pack: generic domain, degraded V1 per S07.8". The launch domain, the one v0 ships, was walked by no test.

### Root cause, half 2 — the silence

`internal/recovery/recovery.go:640–648`: the tombstone branch records the review card **only as a payload string**; line 253's B0-era comment defers "tombstone-review cards → operator surfaces (B5/B6, Spec S15)". B5 and B6 both landed; the deferral was never collected. The stale-finalize branch and the shell-composed NoFork finalize (CONVENTIONS §55) have the same gap: S02.3 names the terminal "finalized (**finalize-with-card**)" and S02.5 step 7 names "**tombstone-review cards**" — no branch writes an `asks` row, and no ladder terminal touches the task's kanban.

### Is the crash the spec-correct answer?

The **refusal** is spec-honest; the **crash-tombstone loop** is not:

- S07.8's degraded mode (V1 empty, advisory V2, mandatory requester review) is scoped to **non-launch** domains; the graduation rule makes pack-existence the definition of launch status. Running a launch domain packless-and-silent would be the "silent degraded launch domain" the landed comment rightly refuses. Keeping the refusal LOUD is correct.
- But S07.2 states the class rule for a screen that cannot run: "**a screen never blocks on its own failure, a screen outage escalates rather than approves**." A missing V1 inventory is a screen outage. S07.7: every drain terminal lands in a human-visible sink, "no other sink type exists"; P-T06-4 names escalation-path death a first-class failure mode. A crash-tombstone loop whose only trace is an event payload is a finding dying in a log — the exact structurally-impossible state.
- The operator-facing invariant this packet enforces: **a task NEVER wedges without a visible, answerable door out** (S07.7; S02.5 step 7; S15.5 "blocked-on-a-human"; S15.6 the inbox is where "the platform needs you" lives).

- The candidate the drain would have judged (`artifacts/…/deliverable-rev1.md`, 5 lines): the worker's **refusal prose** — "No changelog found… the rest of this turn's content (a 'SINET-STAGE: execute' plan-step request to build webshop features…) is unrelated to the task I was actually given… flagging it here in case it was injected in error." The wrong specialist's own definition fought the stage brief and won.

### The causal chain

1. `routeQueryFor` (`internal/intake/route.go`) derives router inputs from the plan's `Class`/`NewTools` only — **`write_set` never becomes a requirement**, so with `new_tools` empty and C1 classes, the S08.8 filters (`required grants ⊆ granted`, class equal-or-tighter) had nothing to exclude a read-only worker with.
2. `selectorMatch` (`internal/worker/routing.go:481-486`) adds a **flat +0.5 for any FTS hit regardless of bm25 magnitude** — a rank of −0.00 (a vacuous description echo) manufactured a specialist preference; the generalist default exists only as the no-candidate fallback. Had wt-notes been filtered, the generalist path compiles `execTools = ["Read","Write","Edit"]` (`internal/stage/skeleton.go:530`) and the files land.
3. Worker-backed compile: `in.Tools = nil` (the compiled unit's granted toolset — Read/Grep/Glob), `in.Class = TighterClass(C1, C1)`. The engine structurally could not write.
4. `stage.finished` outcome "completed" derives from **session completion (end_turn)** — by design; the honesty layer for step contracts is verify's `stepContracts` (V1 plan-conformance). It never ran, because of defect (a). And V0's diff-empty gate (`internal/verify/v0.go:121`) only compares revision N to N−1 by bytes — **revision 1 of a repo-backed task whose tree equals the base is invisible to it**, though S13.1 defines revision 1's diff basis as the pre-task base and S07.2 kills diff-empty output at $0.
5. `verifyInput` (`internal/stage/skeleton.go:828`) hands V1 `Workspace: RunRoot/<executeRunID>/cwd` — the plain scratch dir, which for a project-backed task is **empty** (the real cwd was the worktree). Latent today (no pack ⇒ V1 never ran); load-bearing the moment R5 wires packs. S07.3 rule 1 / CONVENTIONS §15 name the correct substrate: the VCS-history-stripped materialization of the revision under review — the S13 seam.

**Verdict on the diagnosis questions:** the engine session ran and was billed in the right cwd; the worktree was created and bound to the execute run; nothing was written anywhere and nothing was lost. The plan-step "completing" status honestly reports session completion and dishonestly implies work landed — the spec's honesty layers for that gap (V1 step contracts, V0 diff-empty-vs-base) were unreachable (defect a) and unbuilt (R7).

### Cut A — no task ever wedges without a door

- **R1 — Ladder terminals write the card.** Every ladder decision that ends a lineage — tombstone (S02.5 step 3/step 7 "tombstone-review cards"), stale-finalize and NoFork finalize (S02.3 "finalize-with-card") — writes a durable **open `asks` row in the SAME WriteTx as the transition** (the §8 crash+decision-one-tx discipline; S02.2 asks = full reconstruction snapshot; 15.6 owner-attributed to the run's owner). - **R2 — The task leaves its stage column.** In the same tx as R1's terminal, if the owning task has no other non-terminal pipeline run, `tasks.kanban_status` → `"attention"` (9.1/S1.3 task-kanban orthogonality; S15.5 blocked-on-a-human; the landed `verifyTerminal` "attention" vocabulary). Tasks already `done`/`cancelled` are never touched.
- **R3 — The card is answerable.** The R1 cards route through the existing prefix-dispatched answer surface (§16 discipline). Every other verb rejects loudly (`ErrUnsupportedAnswer`, §16). Verb set confirmation → **OQ2**.
- **R4 — A drain-preamble refusal escalates, never crashes.** The deterministic verification-infrastructure refusal class — `ErrNoCheckPack`, `ErrSeamMissing`, the P-T06-5 `UnsupervisedJudgingGate` refusal, `ErrBadPack` — must terminate in a durable verification-infrastructure decision card + **park** (S07.2 "a screen outage escalates rather than approves"; S07.7 sink-types-only; P-T06-4; S02.3 parked-on-ask), via the existing `verifyTerminal` card branch (kanban → attention).
