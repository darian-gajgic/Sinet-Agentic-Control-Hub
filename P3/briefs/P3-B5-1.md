### C — S14.2 contract rules 1–3 (the three disciplines, each with a concrete test)

- **R5.** **Rule 1 — Completeness, enforced by a test** [S14.2 rule 1]. "An S2 capability that cannot be answered from these families is a contract defect — fix the contract, never bolt on a side store." **Concrete test:** enumerate the S2.1–S2.11 capabilities (equivalently the **S14 Coverage table**, S14 §Coverage, which maps each feature-list item → subsection/type) and assert **each maps to ≥1 registered family/type**. A capability with no family is a failing test, not a runtime error. This is also the **anti-side-store** assertion: no capability is answered from a table outside `run_events` (the ledger `ledger_update`/checkpoint rows are `run_events`/`checkpoints`, in-substrate — S02.2).
- **R6.** **Rule 2 — Evolution by amendment + `schema_version` upcast-on-read** [S14.2 rule 2; S02.1]. New types/fields enter only by dated S00.9 amendment (this packet is the ONE v0-formalization moment — see OQ1). Provide an **upcast-on-read hook**: a per-type registry of upcast functions applied when an event is decoded for a consumer, chaining `vN→vN+1`. At v0 every function is identity (all types are v1). **Concrete test:** a v1 payload round-trips unchanged; a **fixture type with a registered v1→v2 upcast** decodes a stored-v1 row into the v2 shape (proving the hook fires) — never a real type's payload (no real upcast exists yet).
- **R7.** **Rule 3 — Forward-tolerant parsing, enforced by a test** [S14.2 rule 3; S03.1]. "Consumers parse forward-tolerantly — unknown types are logged and skipped, never fatal" (the same discipline S03.1 imposes on engine streams; CONVENTIONS §10 already applies it to unknown ENGINE frames). Provide a **`Classify(type) → (family, known bool)`** helper: a registered type returns its family; an **unregistered type returns `known=false`** so a consumer logs-and-skips — **never an error, never a panic, never fatal**. **Concrete test:** `Classify("totally.unknown")` returns `known=false` with no error; a reader over a `run_events` set containing an unknown-type row yields it without failing (mirror `eventlog.After`'s existing behavior — it already returns unknown rows; the helper adds the skip-classification a consumer needs).

### D — the registry design (declare-once; the settings-index precedent)

- **R8.** **One declare-once registry file in `internal/eventlog`** (recommended `internal/eventlog/contract.go`; executor may name it) holding: the 15 families; every registered v0 type → its family + required-field descriptor + `schema_version` + upcast chain; the `Classify` helper (R7). **The registry declares the canonical type strings as DATA** (its own consts/table) — it does **NOT import the producer packages** (they import `eventlog`; an import back would cycle). Mirrors the ratified `internal/settings/index.go` "declare-once; tests pin the tallies" pattern (CONVENTIONS §6).
- **R9.** **A declare-once contract test** (external test package, e.g. `package eventlog_test`, which MAY import every producer) asserts: **every producer `Event*` constant is registered under a family** (a newly-minted type absent from the registry FAILS — this is the mechanism that finally *enforces* the "provisional pending S14" discipline, replacing the 20+ scattered comment notes), and **every registered type belongs to exactly one family**. External test packages import freely (no cycle); this is where the producer↔canonical cross-check lives.
- **R10.** **Required-field conformance is asserted at test time, not enforced at runtime append** [S02.1 "validate-before-persist" is satisfied by the existing envelope gate; S14.2 required fields are the *contract minimum*, formalized here]. A contract test asserts each registered type's **representative payload** (reuse existing per-package test fixtures / a small golden payload per type) contains its family's required-field keys. **Do NOT add per-family runtime field-validation to `eventlog.Append`** — that is heavier than the task, risks breaking every producer, and violates "validate only at boundaries / do the simplest thing that works" (CONVENTIONS §6, §28-style scope guardrail). If the coordinator wants runtime enforcement, that is OQ2.
