## 1. Root cause — diagnosed first-hand, adapter exonerated

The ship-gating crash `planner session: stage: session output is not the contracted JSON object:
unexpected end of JSON input` is **not** an adapter read/assembly defect. The engine side itself
never produced the missing bytes:

- **Lineage** (runs table): `t-611e038e722d95ed.intake` → `.g2` → `.g2.g3` → `.g2.g3.g5`
  (crashed/crashed/crashed/finalized). Crash details in `run_events` seq 678 and 724
  (`run.state_changed` → crashed, cause = the contracted-JSON error).
- **The crashed sessions engine-completed cleanly.** `engine.done` seq 668/676 (g2) and 714/722
  (g3 revise): `subtype:"success", stop_reason:"end_turn", terminal_reason:"completed"`, output
  tokens 4185/3562/2824/2488. Not a token cap, not an error envelope.
- **The decisive evidence — the engine's own transcripts.** Both the per-checkpoint copy-asides
  (`~/.sinet-drain-r1/copy-aside/<run>/cp-*.jsonl`) and the ORIGINAL live transcripts
  (`~/.claude/projects/-home-sinep--sinet-drain-r1-runs-…/<session>.jsonl`) record, for every
  failing session, a final assistant text that is a syntactically valid JSON prefix ending
  `…"}}` — **exactly one closing brace short** (appending a single `}` makes each one valid
  JSON); every session that parsed ends `…"}}}` balanced. Byte-identical between copy-aside and
  original (no copy race). Sessions: cp-666 (6848 chars), cp-674 (7003), cp-687 (6780), cp-712
  (6780), cp-720 (6742), cp-772 (9799) all one brace short; cp-695, cp-733, cp-747, cp-757,
  cp-780 valid. **6 of 11 claudecli plan/critique sessions in the walk (~55%), all on
  `claude-opus-4-8` at engine pin `claudecli.Pin` 2.1.218, all `stop_reason:"end_turn"`.**
- **Negative findings that close the adapter theories.** The control log shows NO
  `claudecli: … EMPTY result field` warning (so the envelope's `result` field was non-empty and
  the RW-9 fallback never ran), NO `stdout read` scanner error, NO malformed/unknown-line skips
  around the crashes. The `engine.message` excerpt (seq 664 etc.) shows the streamed text opening
  as clean contracted JSON (`{"spec":{"restatement":…`). The scanner-ceiling hypothesis is dead:
  the whole result is ~7 KB against a 10 MiB cap, and the envelope line demonstrably parsed.
- **Mechanism, stated honestly:** the final closing brace never appears in any engine-side record
  — the model (or the pinned CLI's own stream assembly; indistinguishable from outside, and both
  upstream of us) emits the deeply-nested single-object pair JSON one closing delimiter short and
  stops with `end_turn`. The adapter handed on VERBATIM what the engine said (RW-9: result field
  wins, never repaired) — correct behavior, unchanged by this packet.
- **Crash arithmetic.** Per advance the stage runs `jsonWithRetry` (1 bounded re-ask): two bad
  rolls at p≈0.55 → crash ≈30%/advance, healed only by the ~5-min S02.5 ladder fork. Matches the
  walk: g2 draft+retry both short → crash; g3 draft short, retry parsed; g3 revise+retry both
  short → crash; g5 revise short, retry parsed. NOTE: the framing's "3 of 5 attempts" includes
  one `context canceled` crash (04:56:59, seq 656) — a different class, out of RW-16 scope.

Deterministic reproduction: **yes, committed red** — `TestRW16ParseJSONOutputRecoversDelimiterOnlyTruncation`
feeds `parseJSONOutput` the evidence signature and fails with the exact production error string.
The investigation also surfaced (and reproduced red) two latent same-signature defects on the
read/parse path: the fence-in-string mangle (R4) and the oversized-line wedge (R5).

## 2. Requirements

- **R1 — adapter retention rules untouched (S03.1; RW-9 R1–R3; `adapters.Outcome.ResultText`
  contract).** No repair moves into the adapter: the envelope `result` field wins, the streamed
  final text substitutes only when that field is empty, text is handed on verbatim, and the
  adapter never fabricates or completes. `resulttext_test.go` and the conformance suites must
  stay green unmodified.
- **R2 — bounded structural completion at the stage's JSON-contract choke point (S06.6 "trust
  stays in the platform validation, never in the seam"; S06.10; S03.1 forward tolerance is the
  posture precedent).** `parseJSONOutput` (internal/stage/engines.go) recovers exactly the
  proven truncation class: eligible iff, after the existing fence/prose trim, the text is a
  syntactically valid JSON prefix whose end lies OUTSIDE any string at a value-complete position,
  and the only missing bytes are the closing delimiters (`}`/`]`) computable from the open-bracket
  stack — append exactly those, bounded by a small plain constant (≤8 closers; CONVENTIONS §7
  constant, NOT a ⚙), re-unmarshal. Never closes a quote, never appends after a dangling `,` or
  `:`, never touches empty/prose input, never fabricates values. All downstream semantic
  validation (`pair.Validate`, verdict-kind switch, judge schema rules) runs unchanged — a
  completion that produces a semantically gutted object still dies there, loudly. Ineligible
  inputs keep today's error verbatim.
- **R3 — completions are loud (S01.11 posture; S06.6 "never silently absorbed").** Every fired
  completion logs Warn through the Skeleton logger with run id, stage, session kind, and
  missing-closer count (the `jsonSession` layer has all of these in hand; thread what R2 needs).
  No new run_events type — the S14.2 event contract (§29) is untouched.
- **R4 — a fence inside a JSON string value is content (S06.6).** Fence-stripping in
  `parseJSONOutput` applies only when the first triple-backtick fence precedes the first `{` of
  the trimmed text; today a fence inside a string value cuts the document apart (reproduced red —
  same crash signature through a different door). The four working forms (bare / fenced /
  prose-then-fenced / prose-then-bare) are pinned green and must stay.
- **R5 — oversized stream line = skip, log, continue; never a wedge (S03.1 forward-tolerance
  MUST: "unknown/malformed lines logged and skipped, never fatal").** In the claudecli pump,
  replace the `bufio.Scanner` with a reader that, on a line exceeding `scanBufCap`, discards
  through its newline, logs the skip loudly (line length included), and CONTINUES parsing to EOF.
  Today `bufio.ErrTooLong` silently stops the read loop: the tail (including the terminal
  envelope) is lost and the child wedges on its blocked stdout write, so `cmd.Wait` never returns
  (reproduced red: 10 s deadline hang). `scanBufCap` stays a plain constant — S03 declares no
  result-size bound, so no new ⚙ (OQ-a). If the discarded line was the envelope itself, the
  session honestly ends on the existing "exited without a result envelope" crashed path.
- **R6 — retry and recovery posture stand (S02.5; compose.go's bounce rule).**
  `jsonRetryLimit` stays 1 (the bounce recovers a malformed envelope only — never a refine
  loop), and the S02.5 ladder remains the sole owner of crashed-advance recovery: no
  adapter-level or scheduler-level auto-retry is added. With R2 the observed failure class heals
  in-session at $0, so the ladder path becomes the rare fallback it was designed to be.

  result vs 10 MiB cap; envelope parsed). Recommendation: keep `scanBufCap` as the plain-constant
  backstop, adopt R5's skip-and-continue honesty; a bigger ceiling is a band-aid and an unbounded
  length-safe reader trades a wedge for unbounded memory. S03 states no result-size bound, so no
  spec amendment needed. DECIDE: accept R5's shape (recommended) or park the pump change and take
  only R2–R4 (the crash class heals either way; the wedge then stays latent — not recommended).
- **OQ-b (2026-08-12 "empty JSON result" — same mechanism?).** Not the same branch, on current
  evidence. Empty ResultText arises only from the RW-9 empty-envelope class (adapter already
  warns loudly and substitutes streamed text when it exists); the brace-short class ALWAYS yields
  non-empty invalid text, and R2 deliberately does nothing for empty input. The 08-12 world is
  gone, so this stays unproven — do NOT force one fix. Recommendation: no action; the RW-9 warn
  line plus R3's completion warn now separate the two classes unambiguously if either recurs.
- **OQ-c (retry semantics).** Recommendation: R6 — ladder posture stands (S02.5 owns recovery),
  `jsonRetryLimit` stays 1. R2 removes the reason to touch either.
- **OQ-d (other duties on the read path).** Answered in §5. Recommendation: no action for
