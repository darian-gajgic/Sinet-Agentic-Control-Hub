# P3-GF15 — the broker-down accept refuses in the requester's words

**SMALL four-stage backend packet**, cut from the exit cold walk's E7/F3 finding
(`P3/design/exitwalk-findings-2026-08-31.md`; STATE 2026-08-31 triage: "§38
class, the GF11 git-error precedent"). Scope is the refusal honesty and nothing
beyond it — no features, no refactors, simplest thing that works.

## §1 The defect, first-hand

With the world's broker daemon not running, a legitimate, open, PIN'd accept on
a local-only project answered:

> `500 {"error":"internal","detail":"accept: resolve signing posture: broker:
> dial unix /home/sinep/.sinet-exitwalk/broker/sinep.sock: connect: no such
> file or directory"}`

Loud and fail-closed — the correct posture — but a Unix socket path is not an
operator sentence. The walker's asked-for answer: *"a helper the platform needs
for signing is not running on this machine"* + where to look. Grounding also
reproduced a second, quieter half of the same defect: the failed accept leaves
its class-A effect row in `executing` (in-doubt), which the boot reconcile
(`ReconcileInDoubt` → `ReDriveApproved`) would ghost-re-drive behind the back
of a requester who was told nothing happened.

**The chain (all read at grounding):** `POST /api/deliverables/{d}/accept` →
`Accepter.Accept` → `executeAccept` (accept.go:494 `signerFor`, AFTER
`BeginExecute`, with NO `failEffect` on its error limb) →
`a.cfg.SigningPosture` (shell closure, `accept_seams.go:78-87`) →
`broker.Dial` (client.go:27-33, raw `fmt.Errorf`) → wrapped
`accept: resolve signing posture: %w` (accept.go:640) → `api.acceptErr`
(accept.go:654) has no arm for it → `reviewErr` default (deliverables.go:820)
→ 500 `internal` with `err.Error()` as the wire detail
(intake_handlers.go:102).

## §3 Requirements

**R1 — the transport marker (internal/broker/client.go).** New exported
sentinel (name suggestion: `broker.ErrUnavailable`), attached where the CLIENT
can tell a transport failure from a broker refusal — that distinction is
already client.go's own (`send` vs `roundTrip`, client.go:49-51):
- `Dial`'s failure (client.go:30) — the walk's case;
- `send`'s wire write/read failures (client.go:55-61) — a broker dying
  mid-conversation is the same fact.
A broker REFUSAL (`!resp.OK`, "broker: %s") is NOT marked — the guardrail held,
different class. The full ops detail (socket path, errno) STAYS in the error
string (it goes to logs, never the wire); use `%w`-chains so both the sentinel
and the inner error survive `errors.Is`/`errors.As`. No existing caller's
behavior changes — all of them propagate. (CONVENTIONS §2: sentinels only where
a caller branches — this packet adds the caller.)

**R2 — the re-export (internal/accept).** `accept.ErrBrokerUnavailable`
aliased to the broker sentinel (`var ErrBrokerUnavailable = broker.ErrUnavailable`,
beside `ErrPushFailed`, accept.go:65-75), so `internal/api` classifies with
`errors.Is` without importing `internal/broker` — the §24 wall stands, and the
landed import-scan test must keep passing untouched.

**R3 — the journal's truth (internal/accept/accept.go:494-497).** The
`signerFor` error limb in `executeAccept` fails the effect before returning
(`failEffect(ctx, s.effectID, ...)` — the collision/squash/push siblings'
exact precedent at :491/:503/:532). Reason string: short machine words like
its siblings (e.g. `"signing posture unresolved"`). This is what makes the
served "nothing happened" TRUE: no `executing` in-doubt residue, no `approved`
residue, nothing for the boot reconcile to ghost-re-drive. Fail on ANY
signerFor error, not just broker-unreachable — sibling parity, and every error
on that limb aborts the act. Nothing else in the accept flow moves; the pinned
arm (never touches the broker) and the card GET (never dials, and says so) are
untouched.

**R4 — the API arm (internal/api/accept.go, `acceptErr`).** A
broker-unreachable arm CHECKED FIRST — before `ErrPushFailed`, because a
dial-failed push wraps both (`%w: %w`, accept.go:533) and must land in THIS
class, not the remote's:

```go
if errors.Is(err, accept.ErrBrokerUnavailable) {
    s.logger.Error("accept: the credential broker is unreachable", "err", err)
    return &SurfaceError{Status: http.StatusServiceUnavailable,
        Code: "broker_unreachable", Msg: acceptBrokerDownMsg}
}
```

Status **503**: a named platform component is not running — not 500
(`internal` claims the platform broke unexpectedly; it did not — §56's lie
class), not 502 (the broker is the platform's own helper on this machine, not
the upstream remote; 502 `push_failed` remains the REACHABLE-broker
remote-failure answer, byte-untouched). Code `broker_unreachable` is its own
vocabulary word, distinct from `not_wired` ("not composed in this process" is
a different fact from "composed but the daemon is down") and from
`push_failed`.

**R5 — the served constant.** One constant (suggestion:
`acceptBrokerDownMsg`, the `acceptPushFailedMsg` sibling), true at all three
sites (posture, sign, push), in requester words:
- names the helper by what it does for the person — the platform's own
  credential helper, the part that signs commits and pushes in their name —
  and says it is **not running** on this machine;
- says NOTHING happened: the work is **not accepted**, still in review, no
  commit was made, no branch moved, and the accept's effect is recorded as
  failed;
- says what to do: the accept can be made again once the helper is running
  (starting it is the operator's/machine-owner's act, not the requester's);
  the underlying cause is in the platform's ops log.

Required tokens (pinned by the committed tests, case-insensitive): `sign`,
`not running`, `not accepted`. Banned anywhere on the wire: `unix`, `.sock`,
`dial`, `no such file`, `resolve signing posture`, `broker:` (the raw-chain
colon form; the word "broker" without the colon is established requester
vocabulary — the card's own signing statement uses "credential broker"). No
spec citations, no paths, no `%v`/`err.Error()` composition — the Msg is the
constant, whole.

**R6 — scope guard.** No new ⚙ key (`internal/settings/index.go`
byte-unchanged, 118/33), no new dependency (`components.lock` unchanged), no
migration, no change to adopted code, nothing under `web/` or any operator
path, `Spec/`/`Docs/`/`Research/`/`P3/STATE.md` untouched. The GF13 §A conduit
(the general `err.Error()` fallback) stays deferred; only this class closes.
