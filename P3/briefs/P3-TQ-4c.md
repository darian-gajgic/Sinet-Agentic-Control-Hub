# P3-TQ-4c — detected rungs in a graduated mixed pack: attribution never crosses origins, and a failed detected rung is a visible note, never silence

**Grounded 2026-09-18.** Single-use brief for the executor and the evaluator. Truth is the spec (`Spec/drafts/S07-verification-quality.md` S07.1/S07.3/S07.5/S07.6/S07.7/S07.8/S07.11; `Spec/drafts/S13-deliverables-review-git-backup.md` S13.4) plus the code on `main` at `b0a45b4` (every `file:line` below is that commit, read in this grounding). No prior brief was read as truth; CONVENTIONS §79 (P3-TQ-4a) and §80 (P3-TQ-7) were read as the landed rulings they are.

**The finding this packet closes** (P3-TQ-7's evaluation, observation N1; `P3/STATE.md` queue row P3-TQ-4c). After §79's per-slot composition a GRADUATED pack can mix owner checks with `detected:` evidence rungs (`Check.Origin == "detected"`). Two consequences, both reproduced RED by this grounding's tests on `main`:

- (a) a graduated pack whose ONLY failure is a detected rung SHIPs clean with items verified and ZERO findings — `RunV1`'s `CheckFailed` arm mints nothing for a detected rung (C4), `ComputeVerdict` sees nothing (C8), `VerifyLedgerItems` runs (C10). The failure lives on the `verify.v1` row and in the judge's evidence slice and nowhere a person looks. S07.7: "every verification finding terminates in a human-visible sink … 'a finding that died in a log' is structurally impossible". At bootstrap the posture disclosure and mandatory V3 exist; in a graduated pack nothing does.
- (b) S07.3's first-upstream-failure attribution CROSSES origins: `RunV1` keeps ONE `failedStage`/`firstFailure` pair for both origins (C2, C3), so a failed `detected:build` records the owner's downstream `test` rung UNVERIFIABLE-HERE attributed to `detected:build`, and `stepContracts`' fallback (C5) names the detected rung on the owner's step. A platform guess silences an owner rung — the exact inversion of §79's "no consumer may treat a detected rung as an owner check".

**The reading (binding for this packet; a reading of ratified text, not an amendment).** Per §79/§80 a detected rung is EVIDENCE: it must never KILL (S07.8 [A16] "detected commands do not graduate the project"; §80 "detected rungs stay evidence — by per-CHECK origin"). Per S07.7 it must be VISIBLE. S07.5 gives the shape: "a finding that cites none [no frozen criterion or rubric item] can only be a note". S07.6/S13.4: "notes ride along to the requester as review comments and never spin loops … polish travels as notes". So a failed detected rung mints a NOTE (severity note, cites nothing, anchored at the check) that travels to the review surface; the round is `SHIP-with-notes`, never clean `SHIP`, never `REVISE`; items are verified on a graduated round (the owner's own bar passed and that verdict is authoritative). And attribution is computed per origin lane: an owner rung is blocked only by an earlier OWNER failure; a detected rung is blocked by the earliest failure of ANY origin (S07.3's ladder is one ladder — a detected test on a tree the owner's own build refused is undecidable, and it is evidence anyway).

## 2. Requirements

**R1 — Attribution is computed per origin lane (S07.3 first-upstream-failure; S07.8 [A16]; §79/§80).** `RunV1` keeps TWO lanes. The OWNER lane (`ownerFailedStage`/`ownerFirstFailure`) is set only when an owner rung (`c.Origin != ProvenanceDetected`) records FAIL. The ANY lane is today's `failedStage`/`firstFailure`, set on a FAIL of either origin (C3). Then: an OWNER rung at rank r is UNVERIFIABLE-HERE iff `ownerFailedStage >= 0 && r > ownerFailedStage`, attributed to `ownerFirstFailure`; a DETECTED rung at rank r is UNVERIFIABLE-HERE iff `failedStage >= 0 && r > failedStage`, attributed to `firstFailure` (the earliest failure of any origin). Consequences: a detected failure never blocks an owner rung — the owner's rungs run and decide on their own exit status (and an owner rung that then FAILS mints its §80 kill exactly as today); an owner failure blocks every later rung of either origin, each attributed to the owner's first failure (the spec-honest answer: a detected test on a tree the owner's own build refused is undecidable; it stays evidence and mints nothing when blocked). Same-stage rungs still all run (`rank > failedStage` stays strict). Replace the first switch arm (C2) with the per-origin predicate; keep the quarantine/runner-failure arms and their ordering byte-unchanged.

**R2 — `stepContracts` receives the OWNER lane's first failure (S07.3; §74/§77).** Pass `ownerFirstFailure` at C5 (`v1.go:558`). The fallback at `v1.go:606` then never names a detected id. Nothing else in `stepContracts` changes; detected outcomes never enter `byStep` (they carry no `StepID`, C5), so the ladder's N-A rule is untouched (TQ-3 OQ-1 stands).

**R3 — A FAILED detected rung mints exactly one NOTE, at the `CheckFailed` decision (S07.7; S07.5; S07.3 declared categories).** In the `CheckFailed` arm (C3) the origin guard gains an `else`: `res.Findings = append(res.Findings, detectedNote(c, out))`. `detectedNote(c Check, out CheckResult) Finding` in `v1.go` beside `checkFinding` returns `Finding{Severity: SeverityNote, Category: c.FindingCategory, Criterion: "", Anchor: checkCriterionPrefix + c.ID, Text: <R4>, fromCheck: true}`. Category = the check's DECLARED category (production: AC-BLOCKER from C14; a pack declaring SANITY-BLOCKER notes under SANITY-BLOCKER), never a literal. Criterion is EMPTY: the note cites no frozen criterion and no rubric item, which by S07.5 is exactly what makes it a note; it does NOT cite `check:<id>` — the check citation is the owner kill's admission (C7) and a detected rung is not the project's bar. `Demoted` stays false (it was born a note). Anchor in production is `check:detected:<slot>` (C14). Only the FAIL state mints: a detected rung that is UNVERIFIABLE-HERE (blocked, or `DetectedUnrunnable`), QUARANTINED or RUNNER-FAILURE mints nothing new (C4 unchanged; `tq4drain_test.go` stays green).

**R4 — The note's text (S07.11 "recorded with reasons"; CONVENTIONS §38 plain words).** One sentence group in the requester's register that says: what the platform noticed — the quoted id (`%q` of `c.ID`), the rung in `stageWords[c.Stage]`, and "exit status N"; that this is NOT a check the project captured and so decides nothing on its own; and that capturing the command under the project's commands makes it an authoritative check (the door: the S13.7 Commands editor). Then the bounded tail exactly as `checkFinding` does it — `boundedTail([]byte(out.OutputTail))` after "This is the end of what it printed:\n\n", or " It printed nothing." — re-bounded in `RunV1`, never trusted from the runner. Never a platform path (`EvidenceRef` stays on the outcome row) and none of the internal tokens `assertPlainWords` forbids (`check:`, `step:`, `AC-BLOCKER`, `CHECK-INTEGRITY`, `check-pack:`, `tree:`, `S07`, `Spec`, `§`). Suggested wording (the executor may improve it; the tests assert substrings, not the sentence): "The platform noticed a command in the project's files and ran it as evidence: %q, covering %s, ended with exit status %d. It is not a check the project captured, so it decides nothing on its own. Capturing it under the project's commands makes it an authoritative check."

**R5 — The key is round-stable and can never collide with the owner kill's (S07.6 finding key).** Key = `"|check:" + c.ID + "|" + category` — no exit status, no output — so a detected rung that keeps failing is the SAME note each round (prior key → never suppressed) and one that passes on the reworked revision stops being raised. It differs from the owner kill's `check:<id>|check:<id>|<cat>` in the criterion by construction, and in the anchor by the composition: `packChecksFor` (C14) emits ONE rung per slot, id `<slot>` or `detected:<slot>`, never both — pinned by `TestTQ4cASlotIsTheOwnersOrDetectedNeverBoth` over all 8×8 owner×detected slot combinations. No dedupe code is needed; the proof is the composition.

**R6 — The note survives the round>1 new-note suppression, by the unforgeable mark (S07.6; the §70 reasoning).** `validateFindings`' suppression (C8, `v2.go:429`) exists to stop the JUDGE's goalposts drifting round by round. A detected rung that first fails at round 2 (the rework broke the detected build) is a platform fact about THIS round's verification, not a new goalpost; suppressing it to a count would re-create N1 one round later (SHIP-with-notes through `suppressed > 0`, C9, with the reason invisible on the review surface).
