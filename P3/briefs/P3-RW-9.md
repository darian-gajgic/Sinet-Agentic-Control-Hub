## 3. Requirements (numbered, each with its S-ref)

- **R1 — the fallback: retain the stream's final assistant text; use it when the result field is empty on a clean completion.** The parser keeps the LAST flushed assistant message's full text (a retained field set at `flush()`; today discarded parse.go:253). The transcript/copy-aside are NOT read back for this (S03.1 table: the JSONL transcript is "a resume optimization only"; the stream is the adapter's own witnessed truth — §11 OQ1).
- **R2 — genuinely-empty stays honest.** A clean completion with an empty result field AND no assistant text at all keeps `ResultText: ""` + the loud log — the adapter never fabricates text and never mints a crash for an outcome the engine reported as success (D3 honesty; S03.1). Loud failure for unusable text is the CONSUMER path's duty (R4) — and it already errors today; what's missing is the corpse.
- **R3 — bounded persisted payloads unchanged.** The retained text rides ONLY the in-process `Outcome.ResultText`; event payloads and `Outcome.Result` stay bounded exactly as now (P-T07-5 refs-not-blobs; CONVENTIONS §10 ExcerptCap).
- **R4 — the strand path: an intake advance that dies mid-drive leaves a classifiable corpse.** After the run has been taken to (or confirmed) running, an `Answer`/`Advance` error that is not a gate-park and not a terminal phase transitions the run CRASHED with its cause — the `Skeleton.crash` shape (skeleton.go:384–402: cancel-suppression consulted, corpse for the ladder), applied at the stage surface around `pipe.Answer` (surface.go:169) and `pipe.Advance` (surface.go:237), matching the landed dispatch-leg (:429–433) and verify-answer (answer.go:184/:193) postures (S02.3 crashed edge; S02.5 step 3 fork-from-checkpoint; CONVENTIONS §16 doctrine, extended to intake).
- **R5 — pre-resume failures stay corpse-free.** Errors BEFORE `closeAndResume` commits (unknown ask, not-requester, bad answer, decode failures) leave the run parked on its open ask and map to their existing 4xx — no crash, no state change (S06.1 gates wait). The cut line is the resume commit / the `ErrNotRunning` guard: only a run left `running` with no driver gets the corpse.
- **R6 — the door keeps answering honestly.** The 500 remains (the request truly failed); the response may carry a distinct code (§11 OQ3), but no swallowing in either direction: the error is returned AND the run is classifiable. The healed path needs no door change — the ladder forks and the fork re-drives (recovery.go:212; pipeline.go:347–360).
- **R7 — self-heal is bounded and human-free for this defect class.** With R4, the parse-error shape never enters the watchdog-silence window at all: crash at the moment of failure → ladder fork within ≤ ⚙ `recovery.sweep_interval` → fork's dispatch rebinds and re-runs the plan leg (or re-parks on a legitimate gate). No change to resume.go, the watchdog, or the ladder (S14.4 NO-AUTO-KILL untouched; parked stays unscanned by design).
- **R8 — uniform at the seam, stated for the future lane.** The fallback lives in the substrate adapter behind the unchanged `adapters.Outcome` contract; consumers change ZERO lines. If the contract comment is tightened, it is wording only (no signature change) — the conformance fixtures become the reference behavior any future adapter (opencode) must match (S03.2, S03.6).
