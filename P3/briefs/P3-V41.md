## 5. Mechanism of the version bump, settled (question (1) of the packet)

1. **In code:** `Version` string + weight literal + provenance consts in `softwareSeed()` (R1–R4). No registry, no migration, no file on disk ships with the binary.
2. **In the record (S09.8 supersession from first boot):** a MINTED Ensure (R5) that, once an operator account exists (D10; `ErrNoOperator` otherwise, retried each boot), finds the active `intake/taxonomy/software` house object, reads the content hash the row was COMMITTED with (`knowledge.write` event, never the file), and if that hash equals GF7's frozen v4 content and no version on the topic already carries the v4.1 originRef, writes a new version (`origin: imported`, `originRef: v41OriginRef()`, `supersedes: cur.ID`) — the old version retired in the same tx, the governed file `knowledge/house/intake-taxonomy-software.json` rewritten to the v4.1 strict JSON that `intake.LoadTaxonomy` parses (the operator-editable override input, §17), and the `knowledge.write` event carrying the new hash.
3. **An EXISTING world governing v4 (the operator's live worlds) receives v4.1 at its next boot** by exactly that path: GF7's Ensure sees its own content committed → repair-only/no-op; V41's Ensure sees committed == frozen v4 → supersedes. Result `Superseded: 1`, logged at Info. The RUNTIME interview changes with the binary regardless (in-code seed); the record catches up at boot.
4. **If the operator has edited the object THROUGH the gate** (`NewVersion`, a row with a foreign originRef): committed ≠ frozen v4 → V41's Ensure `continue`s — a later decision stands, never reverted (§9 T-M5a). **If the operator edited the FILE by hand** (no row): the row still attests v4 → the supersession to v4.1 proceeds and the hand-edited bytes are replaced (counted in `Repaired` when the on-disk hash differs, logged in the neutral "crash-torn write or out-of-band edit; repaired from the row" words); after v4.1 is active, a hand edit is repaired back to the row's v4.1 content at the next boot, minting no version (§9 T-M5b). The record's stance, in one line: a file is not a decision; the gate is.
5. **A fresh world** writes the chain v1 → v2 → v3 → v4 (PENDING record, retired) → v4.1 (RATIFIED record) in one boot; the v4 row keeps its honest PENDING text as history (§9 T-M2).
