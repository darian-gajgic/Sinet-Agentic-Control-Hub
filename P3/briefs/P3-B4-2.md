### D — Git topology (S13.5; S02.10; S02.4d; S13.1)

- **R14.** **Branch-per-pipeline** (S13.5): each pipeline gets ONE long-lived run branch in its workspace; the workspace is a **git worktree of the registered project store** checked out on that branch (S02.10 "a clone/worktree of the registered project store"; S13.5 "substrate: worktree + overlayfs per S02.10" — the overlay half is the sandbox's, see §2 seam 5). The branch accumulates commits across stages and review rounds; during a review round-trip: same branch, new commits. Branch base = project HEAD (default branch) at creation, recorded durably (it is revision 1's old side, S13.1). `runs.workspace_ref` (0001) records the workspace.
- **R15.** **Never amend / never force-push under review** (S13.5): the machinery has NO amend path and never moves a run-branch ref non-fast-forward while any deliverable of that pipeline is in-review; conformance-tested (attempted-violation style, §22 precedent). Nothing in this packet pushes anywhere (pushes are S13.6/B4-3's; dev-mode has no remotes).
- **R16.** **Snapshot commits** (S13.5): platform-owned, **tree-level** — they capture bash side effects: modified AND untracked files, not just tool edits — **junk-excluded via platform ignore rules** (platform-managed exclude mechanism; rules are STRUCTURAL code data, no ⚙ exists), authored as the platform with **per-invocation identity** (env/`-c`; no global/host git config mutation — the S13.6 step 2 rule generalized). Taking a snapshot must leave the worktree's own git state coherent for the engine's continued use (the engine may itself run git there; S13.5 "same branch, new commits" means snapshot commits and engine commits interleave on the run branch).
- **R17.** **Checkpoint boundary = the S02.4(d) artifact ref**: `adapters.Driver.Snapshot` (the CONVENTIONS §10 seam, `internal/adapters/driver.go:46`, nil today) goes LIVE: runID → workspace (via `runs.workspace_ref`/registry) → snapshot commit → sha returned; the checkpoint row's `artifact_snapshot_ref` carries it (`internal/gates/checkpoints.go`). Runs without a project workspace leave the block empty (the honest nil-path, unchanged).
- **R18.** **No-change checkpoint → no empty commit**: when the tree is unchanged since the last snapshot, return the existing snapshot sha as the ref (still-valid D7 material); never `--allow-empty` spam.
- **R19.** **Stage/round boundaries = revision raw material** (S13.5; S13.1): execute-leg stage close takes a snapshot commit; at the verification-handoff mint (round boundary), the round's snapshot sha is recorded on the minted revision — filling `deliverable_revisions.snapshot_sha` (the 0007 fill-once seam: NULL→sha exactly once; also settable at insert) via an optional `MintInput` member and/or a fill verb on `review.Store`. Pipelines without a workspace (pure content-pin lanes, e.g. composer definition deliverables) stay exactly as B4-1 shipped them — `snapshot_sha` NULL is a valid honest state.
- **R20.** **Platform ref creation** (S13.1; 0007 comment "the ref itself is created in the project store at B4-2"): at snapshot-sha fill time, `refs/sinet/deliverable/<id>/rev-<n>` (the exact string `review.RevisionRef` already produces) is created in the **project store** pointing at that snapshot commit. Minted-revision commits are thereby git-reachable independent of branches: **workspace GC MUST NOT delete the only copy of a minted revision's objects** (S13.1) — branch/worktree deletion is admissible only for commits protected by platform refs. Ref creation is driven from OUTSIDE `internal/review` (its storage+eventlog-only import posture holds, §22); the composition wires the git side and the review-side fill together.
- **R21.** **Fresh branch per attempt** (S13.5): when the base moved or an attempt is abandoned, a NEW branch (the attempt model) — never rewriting the old one; the old attempt's branch **stays** until revision-retention GC clears it (and per R20 only when its minted commits are ref-protected).
- **R22.** **Utility checkouts** (S13.5): plain worktrees for platform use (accept staging B4-3, preview-at-rev B4-4): created `git worktree lock`-ed while in use, swept with `git worktree prune`, **never auto-delete dirty**. The verbs + lifecycle rules land here; the consumers arrive in B4-3/B4-4. Prune runs opportunistically on the package's own create/teardown paths (no new timer, no ⚙ exists for one).
- **R23.** **GC rules** (S02.10 "workspace GC is a platform duty"; S02.5 step 7): the package provides flag/sweep verbs honoring: orphan worktrees are FLAGGED, never auto-deleted while they hold uncommitted work; dirty utility checkouts never auto-deleted; minted-revision protection per R20. The recovery ladder's step-7 posture (observation-only, `internal/recovery/recovery.go:233`) is unchanged — wiring timed sweeps into the ladder is NOT this packet's (no ⚙ cadence exists; the ladder text already names workspace GC as the machinery's future consumer).
- **R24.** **The net is the commits — never** (S13.5): nothing in this packet uses engine checkpoints, `git stash`, or jj as a safety/capture mechanism.
- **R25.** **Compare old side 0 materialized** (S13.1 "revision 1 is presented against the pre-task state (project HEAD at branch base)"; `review/compare.go:65` + `anchor.go:54` deferrals): branch-base content becomes resolvable for repo-backed deliverables via a seam FIELD on `review.Store` (the `PixelDiff` precedent — review's import set stays storage+eventlog only), wired by the composition root to the topology package. `Compare(id, 0, 1)` then diffs base→rev1; revision-1 old-side anchors get a non-nil source and can map (ladder step 1) instead of degrading from step 3. Non-repo deliverables keep the empty-base behavior.
