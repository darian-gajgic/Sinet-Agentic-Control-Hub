## The C2 §7-C2 BINDING conditions (extracted verbatim-in-substance from `Research/18` §3-C2 + §7-C2 — all bind, the way the seven §7-C1 conditions bound B3-4)

The 2026-07-20 standing directive (`P3/STATE.md`) ratified C2 for the B5/B6 cuts: *"serve-side redaction of observability projections + redact-before-match search; constant-on, never applied to deliverable content."* The authoritative conditions:

- **§7-C2·1 — SCOPE = observability projections ONLY:** run-event payloads on SSE/REST, the S14 query layers, and any search (with redact-before-match). B5-2 owns the **SSE half** (the live projection + tail frames); the query/search layers are B5-8.
- **§7-C2·2 — EXEMPT: never deliverable file content (S13's product) or broker internals.** Redaction is scoped to the observability serving edge, never a blanket response middleware.
- **§7-C2·3 — CONSTANT-ON, NO ⚙.** Revisitable as ONE clamped S18 row *only* under the standing settings-tab amendment if the operator ever wants a toggle — **not raised by this packet**.
- **§7-C2·4 — FRAMING: defense-in-depth for incidentally-captured secrets in tool output** (an agent `cat`s a key file; a provider echoes a header). Code + docs must **never argue it as a substitute for the D2 prevention story** (broker isolation, scrubbed env, key-hygiene greps). Two lines of defense, not a replacement for the first.
- **§3-C2 MECHANISM — one projection function that deep-walks values** and redacts pattern classes (bearer tokens, `sk-…`/`gh?_` keys, AWS key ids, PEM blocks, `SOME_KEY=<value>` pairs, own pairing codes); **search redacts BEFORE matching** (the search endpoint cannot be an oracle for redacted text); run-evidence search returns bounded excerpts (240-char) with hard result caps; **raw payloads stay journal-only** and are stripped from live frames unconditionally.

## 3. Per-topic snapshot-projection shape (R5, R8) — the DB projection each topic emits on connect

Each is a read-only SELECT set, owner-scoped (OQ1), redacted at the serving edge (R16). Shapes are the DATA contract; field encodings are the executor's within these minima.

- **`inbox`** → `{asks:[{ask_id, run_id, kind, observed_ts}...open only], approvals:[{effect_id, run_id, class, state:proposed}...], watchdog_flags:[...], drift_cards:[...]}` — from `asks` (`answered_ts IS NULL`) + `effects` (`state='proposed'`) + (B5-3/B5-6 rows when they exist). Open items only.

**Cursor:** each snapshot frame carries `cursor = event_head at projection time`; the tail resumes from that cursor (R7). Snapshot reads are short (no long-lived read tx — S02.1 read hygiene, the `After` precedent).

## OPEN QUESTIONS (genuine dispositions — the coordinator settles BEFORE the executor launches; the B4-6/B4-7/B5-1 precedent)

- **OQ1 — Owner-scoping of the live stream (THE load-bearing disposition).** The B0-3 `/events` relays **ALL** rows unscoped (`After` returns every row); S01.9 AuthZ mandates **owner-scoped accessors** (a member sees only their own runs; the operator sees all via the one role bit). B5-2 is the first real multi-owner surface. **Grounding recommends:** owner-scope the **snapshot projections** (the SELECTs carry an owner predicate — natural and cheap) and the **`run`-detail subscription** (a member may subscribe only to their own `run_id`); for the **delta tail**, filter `After` results by owner unless the caller is the operator (the correct S01.9 posture). This **changes the existing endpoint's behavior** (today's unscoped relay), so it needs coordinator sign-off. **Alternative:** defer comprehensive tail owner-scoping (operator-only v0 household is bootstrapped operator-first) and scope only the projections now — flag for B6/query-layer. Grounding leans **scope now** (S01.9 is explicit; the household has ≥1 member seat) but does not decide. *This is the one place with a real behavioral/security consequence.*
- **OQ2 — Redaction primitive home.** `internal/redact` (a stdlib-only **leaf package**, `redact(string)`/`redactJSON(payload)`) that `internal/api` imports now and B5-8/B6 import later — **recommended** (clean reuse, no cycle, the "one projection function" C2 mandates) — vs inline in `internal/api` with an exported func (lower footprint, but B5-8 then imports `api`). Grounding recommends the leaf package; coordinator confirms.
- **OQ3 — Projection home.** `internal/api` (a new file, e.g. `projection.go` + `topics.go`, per the task's "extend `internal/api`") reading through narrow seams wired at the shell — **recommended** — vs a new `internal/obs` package shared with B5-8. B5-1 explicitly declined `internal/obs` (OQ3 there); B5-8's query layers can own their own home. Grounding recommends `internal/api` for B5-2's live projection + the shared `internal/redact` leaf; coordinator confirms.
- **OQ4 — Reconnect-with-cursor: re-snapshot or pure-tail?** S14.3 says "reconnect = snapshot-then-tail" and the convergence note says "re-snapshot on gap — never patch blind." **Grounding reading:** a **topic-subscribed** SSE (re)connect ALWAYS emits snapshot-then-tail (re-snapshot is cheap + correct); the **raw `?after_seq` poll** path is delta-only (the poller owns its state). **No S00.9 amendment is flagged** — S14.3 fully specifies the surface and Research/18 §7-C2 confirms C2 is additive/spec-silent/no-⚙. The OQs are design/scope readings, not spec gaps.
