# P3-RW-13 — Stage-0 triage restructure: classification moves onto the RUNNING intake run

**EXPIRED 2026-08-16 — single-use artifact; the packet landed (`5936828`+`c4244a8`). Later grounding must never read this as truth.**

**Grounding brief** (2026-08-16). Code + spec verified first-hand this session; the design basis below is binding (characterized by a fresh evaluator, ratified by the coordinator, STATE log 2026-08-12). Where this brief and the code/spec disagree, code + spec win.

## 0. The defect, verified live in the code

`Pipeline.Start` (internal/intake/pipeline.go:201–240) calls `Classifier.Classify` BEFORE the task/run/first-state-event transaction (line 266). The classifier adapter (internal/stage/local.go:106–137) composes `req.TaskID + RunSuffixIntake` and hands it to `Duty.Call`, whose D7 metering (internal/local/duty.go:230–239) requires the run row to exist AND be `running`/`draining` (gates/checkpoints.go:150, `ErrNotCheckpointable`). At Start the run neither exists nor runs — so with the local tier wired, **every** Start-time classify burns the GPU call, fails its mandatory $0 D7 row, surfaces `local.unmetered_defect`, returns an error, and the pipeline fails closed to high with the family unresolved. The zero-touch path is structurally unreachable. livetriage_test.go:237–297 documents and asserts exactly this gap ("an S06.2 restructure this packet did not take on its own authority") — RW-13 is that restructure.

## 1. Requirements

- **R1 — Start keeps its deterministic legs unchanged.** Request validation, task/run/first-state-event birth transaction, the registry match with the P3-RW-1 pin posture (pinned failure fails Start; unpinned degrades), the deterministic P47 rule layer (`st.addHits(p.triggers().Detect(...))`), and the fail-closed baseline (`TierHigh`, `FamilyGeneric`, `FamilySourceDefault`, `Guess{Known:false}`, no band) stay exactly as they are. Start performs **no classifier call**. [S06.2 ¶"Deterministic floors"/"Classifier failure fails closed"; S06.3; binding design basis]
- **R2 — The classify step runs once, at the top of the first advance, on the RUNNING run.** In `advanceLoaded`, after the terminal-phase and open-gate early returns, after the `StateRunning` check and the lease hold, before the phase loop: run the classifier leg. The consuming run is `st.RunID` (after an `AdvanceDispatched` rebind that is the fork — the rebind precedes `advanceLoaded` by construction). This is the one place the §26 R18 row has a checkpointable consuming run. [S02.3 stored states; CONVENTIONS §14 "stage work requires running"; §26 R18; S02.5 step 2]
- **R3 — Guarded by a durable classify marker on `State`.** RECOMMENDED POLARITY: a `TriagePending bool` (JSON `triage_pending,omitempty`) set **true** by Start and cleared by the classify step — NOT a default-false `Classified` flag. A pre-RW-13 state event unmarshals the zero value and is therefore never re-classified (the familyGate/R10 precedent, pipeline.go:797–806); a default-false `Classified` would re-run classification over every in-flight old task and could rewrite a settled family/tier mid-interview, violating S06.4 monotonicity and the RW-11 provenance. **Recorded tension with the characterization's literal words ("guarded by a classified marker") — same mechanism, inverted polarity, for in-flight safety.** No migration: the marker is an event-payload field (§14: "NO intake table, no migration"). [S06.4; P3-RW-11 R10 precedent]
- **R4 — The classify step applies Start's current logic verbatim, with one strengthened guard.** On success: family adopted **only when `st.FamilySource == FamilySourceDefault`** (strengthens today's `!= FamilySourceRegistry` — at first-advance time a requester-answered family is now possible on re-entrant states and must never be overridden; precedence registry > classifier > ask > default stays intact); `ValidTier` gate on the tier; `st.Guess = prop.Est`; add-only `DataHits`; `validFloors` add-only via `addFloors`; band evaluation with all four S06.4 conditions and per-user ⚙ `intake.zero_interaction_cost_usd` via `FloatFor`; trivial-failing-band lands at `maxTier(TierLow, st.FloorTier)`. On nil-Classifier / error / abstain / invalid label: `st.Tier = TierHigh` fail-closed, family stays unresolved. The marker clears in **every** branch — a failed classify is a completed triage attempt, not a retry loop. [S06.2 rules 1/3/4; S06.4; P3-RW-11 R5/OQ3, drain D3]
- **R5 — `applyFamilyTaxonomy` re-runs after classification**, and its non-empty fallback disclosure line is recorded via `recordTaxonomyFallback` (the family may move generic→software, and registry-pre-answered slots of the new set must be re-applied; clearance recomputes). [S06.5; P3-RW-11 R6; binding design basis]
- **R6 — The intake-record artifact is versioned.** `recordPath` gains a version (v1 keeps distinct identity from v2 — new immutable file, never overwrite; the S06.6 immutability discipline applies). Start writes record **v1** with the honest baseline; the classify step writes record **v2** with the classified values, updates `st.RecordRef`, and emits the ledger `SessionVerbs(runID, "triage", gen).Artifact` entry for v2 plus the platform triage decision line (today's wording: `triage: family=… (%s) tier=… band=… data-bearing=… clearance=…`) — real values recorded where they become real. [S06.1 Stage-0 row "intake record → artifacts + decisions"; §14 artifact immutability]
- **R7 — One `intake.state` event carries the classification.** The classify step commits exactly one full-state append (`appendState`/`appendStateTx`) after applying R4/R5 — the state payload carries tier/band/floors/guess plus the cleared marker. No new event type; the §14 full-state-payload pattern is the mechanism the characterization's "emit a state event carrying tier/band/floors/guess" resolves to. [CONVENTIONS §14; S02.2 ledger_update precedent]
- **R8 — The Classifier seam carries the consuming run explicitly.** RECOMMENDED SHAPE: restructure to `Classify(ctx context.Context, in TriageInput) (TriageProposal, error)` with `TriageInput{RunID string; Request Request; Registry *RegistrySlice}` — the DraftInput/PhraseInput precedent (intake.go:265–287, 383–398): the pipeline knows which run it is driving, and after a recovery-fork rebind that is the fork. The stage adapter uses `in.RunID` and **deletes** the `req.TaskID + RunSuffixIntake` composition and its now-false "Start-only duty … can never see a fork" comment (stage/local.go:109–112). [§26 consuming-run rule; P3-RW-6 R7; CONVENTIONS §16 run-id rule]
- **R9 — S06.2's ordering guarantee is preserved by code order.** Classification precedes Stage-1 planning: the classify step runs before the phase loop, so no `Planner.Draft`, `Phraser`, or any paid seam can fire before it in the same drive; `familyGate` (which the classify step precedes) fires only when classification left `FamilySource == FamilySourceDefault` — i.e. on classifier absence/abstain/invalid-label. The fail-closed ask stays the fallback, never the common path. [S06.2 "before any paid model runs"; S06.5; P3-RW-11 R4]
- **R10 — Band entry moves to first-advance with no extra click.** A band-qualifying task is not banded at Start; the first advance classifies, enters the band, skips the family gate and interview (band never asks — pipeline.go:807–812), drafts, and auto-approves ungated in the same drive. Zero ask rows over the run's whole life. [S06.4; G1 P11]
- **R11 — The two REJECTED shapes must not appear.** (a) No self-admitted run inside Start: Start never transitions the run toward `running` (admission is the scheduler's — `ErrNotRunning` doctrine, §14; the Submit path enqueues and the claim loop dispatches, stage/surface.go:190–199 + skeleton.go:426–439). (b) No platform-scope metering for the classify call: never the `advisoryMeter` short-lived-platform-run pattern (shell/local_seams.go:246–265 exists for RUN-LESS advisory calls; the intake classify call HAS a consuming run), never an eventlog append in lieu of the D7 row. [S02.3; §26 R18; STATE 2026-08-12 ratification]
- **R12 — Degradation semantics unchanged, relocated.** nil Classifier, seam error, abstain (adapter → error), invalid label (adapter → `""` family, conservative high tier — parseTriage stays as-is): identical fail-closed outcomes, now at first-advance. `decision.family` (`CardFamily`) still fires from `familyGate` on exactly `FamilySource == default` ∧ not band. [S06.2; S12.4 row; §14 degradation rule]
- **R13 — The observable outcome when the local tier is wired.** The common path classifies zero-touch (requester never sees the family question); the `local.unmetered_defect` intake-triage class disappears because the consuming run now exists and runs; the $0 D7 row lands on the intake run with the `local` marker. livetriage_test.go's gap leg (lines ~237–297) flips per its own embedded instruction: the `defects == 0` fatal inverts, and the two fail-closed assertions re-point at `family=software` / `FamilySourceClassifier`. [§26 R18/R19; S12.1]
- **R14 — In-flight and surface compatibility.** Pre-RW-13 state events are never re-classified (R3). `Submit`'s synchronous task view now reports the baseline (high/generic) until the dispatch classifies moments later — honest, spec-clean; note it in the commit message for the operator. The follow-up Start path (shell/accept_seams.go:113–116) calls `Pipeline.Start` without enqueueing — pre-existing posture, untouched here (OQ6). Crash between classify and the R7 state append leaves the marker pending → one repeated $0 call on redispatch; deterministic guards make the re-application idempotent — accepted, documented in code. [S02.5; D7]

## 7. Open questions

- **OQ1 — marker polarity.** Characterization says "classified marker"; a default-false `Classified` re-classifies in-flight pre-RW-13 tasks. **Recommend `TriagePending` set by Start** (R3) — same guard, safe zero value, the R10 precedent. If the coordinator wants the literal polarity, it needs a second "old-world" sentinel; strictly worse.
- **OQ2 — seam shape.** `TriageInput` struct vs. added positional param vs. composition-bound resolver (`currentRunFor`). **Recommend the struct** — the DraftInput/PhraseInput precedent; explicit beats a resolver because the pipeline knows the run it is driving (the Phraser comment states this rule verbatim, stage/local.go:265–268).
- **OQ3 — Start's triage decision line.** Today Start records `triage: family=… tier=…` with classified values. **Recommend: Start keeps the record-v1 Artifact entry but the decision line moves to the classify step** — the decision should state facts where they become facts; a Start-time decision would honestly say "high/generic/default", which is noise. Evaluator checks item 8 either way.
- **OQ4 — record v2 content.** **Recommend adding `family_source`** (and keeping the existing keys) to record v2 — additive provenance the RW-11 decision line already discloses; the S06.1 record shape names the minimum, not a ceiling.
- **OQ5 — crash window between classify and state append.** **Recommend accept-and-document** (one repeated $0 call on redispatch, deterministic re-application): the alternative — clearing the marker before the call — loses a crashed classification forever with no retry. No spec text forces either; R14 records the choice.
- **OQ6 — follow-up Start path never enqueues** (shell/accept_seams.go:113–116): a successor intake run is born `new` and, in that wiring, nothing admits it — so post-RW-13 it also never classifies (today it classifies at Start but equally never interviews). Pre-existing admission posture, out of RW-13 scope; **recommend flagging to the coordinator for the S13.9 wiring's own packet.**
