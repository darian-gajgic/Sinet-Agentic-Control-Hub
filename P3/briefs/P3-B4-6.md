### B — VRAM ledger & admission math (S12.7)

- **R8.** **VRAM ledger = per-machine MEASUREMENTS, never documented constants** (S12.7). Build the R09-OQ8 protocol machinery (7 steps, S12.7): (1) **pool enumeration by UUID** (reuse `local.GPUUUIDs`, `config.go` — one nvidia-smi read); (2) **sleep-gate EVERY read** — check `power/runtime_status` FIRST; a **suspended GPU is recorded "asleep, 0 client bytes" and NEVER polled** (polling wakes it — R15); (3) **device truth from device-level `memory.free`, never per-process sums**; (4) **per-process attribution including graphics clients** (compute-only queries miss every graphics process); (5) per-(model, quant, context, slots, engine build) **footprint measured through a warm-up generation + guard band ⚙** (the measurement PROTOCOL — the concrete VALUES are R10/OQ1); (6) compositor headroom logged per display mode (hybrid + MUX separately — hybrid is the recommended VRAM-maximizing mode); (7) live-admission verification. Re-run triggers (driver upgrade / engine bump / model-quant change / display-mode change) are recorded as a documented invalidation rule (not a periodic job — R15).
- **R9.** **Admission math** (S12.7): a load is admitted **iff LIVE `memory.free` ≥ ledger(model) + ⚙ `local.vram.guard_band_mb`** — **always the live reading, never the ledger's belief**; **after any forced kill, `memory.free` recovery MUST be verified before the next admission** (zombie VRAM exists — R11). The guard band is read by dotted key `local.vram.guard_band_mb` (declared, `internal/settings/index.go:642`), never a constant.
- **R10.** **The calibration-values split (machinery here, VALUES B4-7).** The concrete per-model footprints, both compositor-headroom figures, and unload/kill→free latencies are **`TBD-BRINGUP(VRAM-ledger calibration)`** (S12.7; the S12.9 bring-up battery measurement #2), which the queue cut assigns to **B4-7**. B4-6 builds the PROTOCOL + admission math + kill path (R8/R9/R11); the ledger ships with an **honest uncalibrated posture** (an unmeasured seat has no footprint belief and the admission check says so — the live `memory.free` reading is always authoritative regardless, R9). **OQ1 (below)** records whether a single live footprint measurement is also wanted here. This is the direct parallel of B4-5's machinery-here / calibration-B4-7 structure.

### C — Preemption: kill-not-freeze (S12.7)

- **R11.** **Preemption is KILL-NOT-FREEZE** (S12.7). Freezing is categorically wrong for VRAM (a stopped process keeps its CUDA context + allocations; the driver frees memory only at teardown). Freeze/thaw is the CPU/RAM tool (S10); **unload/kill is the GPU tool**. Backend stop discipline: **SIGTERM → ⚙ `local.unload.term_grace_s` → SIGKILL** — the kill path is **MANDATORY, not a fallback** (`llama-server` can wedge and ignore SIGTERM) — then **verify recovery per R9's admission rule** before the next admission. `local.unload.term_grace_s` is declared (`index.go:649`); B4-5 already consumes it as llama-swap's `unloadTimeout` in config-gen — B4-6 additionally consumes it as the Sinet-side forced-kill grace.
- **R12.** **Granularity, stated** (S12.7): generation cancels between decode steps (~ms); a running prefill batch cannot be interrupted — worst-case *voluntary* preemption ≈ one prefill batch. When the operator needs VRAM now, the process is **KILLED** (the eager-unload verb, S12.2 — already built at B4-5: `eagerunload.go` stops admissions + calls `POST /api/models/unload`). B4-6 supplies the **forced-kill discipline BEHIND** eager-unload for the case where llama-swap's own unload wedges: the Sinet-side SIGTERM→grace→SIGKILL of the backend (R11), then recovery verification. One backend process per loaded model keeps CUDA-context overhead (~300–800 MB class) inside the measured footprint.
